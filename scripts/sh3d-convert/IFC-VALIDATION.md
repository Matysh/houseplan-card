# IFC implementation validation (#1458)

Snapshot: 17 November 2026. This is evidence for the external converter, not a stable-release test receipt or certification of current Archicad/Revit/KOMPAS versions.

The public IFC inputs, immutable source links, export instructions and compatibility boundaries are in [IFC.md](IFC.md). [The measured inventory](evidence/ifc-public-profile.json) records each source GUID/STEP id, outcome, reason, per-storey result and omitted non-wall/unfilled void. Counts refer to source objects; splitting a wall into graph edges does not inflate them. The full raw report is generated locally by `check-ifc-public.mjs` as documented there.

The synthetic input is [ifc-synthetic.ifc](fixtures/ifc-synthetic.ifc), generated by `test/helpers/ifc-fixture.mjs`. Its independent controls are two rooms 4 × 4 m on physical axes (3.8 × 3.8 m inside), 20 cm walls, a 90 cm door, a 120 cm window, T/X junctions and an isolated editable wall. Two storeys share one building frame. Golden JSON documents were produced by the actual CLI, with epoch metadata. They are also compared with actual offline-browser downloads.

Addressed verification:

- `node scripts/sh3d-convert/build-ifc-vendor.mjs --check`: clean C++/WASM rebuild in the pinned emsdk container, including regenerated JS glue; engine SHA256 `9991fc410b075a57c10135d6e8996f298c60064fb7f90fd59c672b6539502d75`, 5,946,148 bytes. Ordinary page builds only verify the committed artifact/index and do not run this heavy command.
- `node --test test/ifc-convert.test.mjs test/converter-site.test.mjs process-next/test/converters.test.mjs`: 26 passed. Includes physical units, rotated/mapped placements, reference offset, selected-floor identity, low/spanning walls, polyline hosts, duplicates, explicit geometry refusals and decoded Worker/vendor transport scans. Converter checks remain separately classified diagnostics.
- `python -m pytest tests_backend/test_ifc_converter.py tests_backend/test_ha_easy_floorplan_convert.py -k ifc -q`: 5 passed through actual validators/preview and authenticated HA apply/export/reimport. The wider addressed SH3D/Easy/picture backend set also passed (44 cases).
- `node demo/smoke_ifc_converter.mjs`: actual file:// HTML, real Blob Worker and embedded WASM in pinned Chromium 151.0.7922.34. All external network attempts blocked/tracked; none occurred. Node/document parity, storey selection, loss-only result, RU/EN and 390 px width, stale closures/messages, cancel, Worker/WASM refusal and recovery passed. No main-thread task over 50 ms during this small synthetic conversion; measured cancel 36 ms. These are one environment/fixture observations, not universal performance budgets.
- `node demo/smoke_plan_converter.mjs`: existing SH3D/Easy/picture offline journeys passed. Relevant compiled consumer/entry checks passed after preparing `test-build` (9 cases).
- `HP_NODE_ORDER_BACKUP=scripts/sh3d-convert/golden/ifc-synthetic.space-1.json HP_NODE_ORDER_FIXTURE_LABEL=ifc-synthetic HP_NODE_ORDER_REPORT=artifacts/ifc-converter/node-roundtrip.json PYTHON=... node demo/smoke_wall_node_python_roundtrip.mjs`: native pointer node moves, unchanged opposite endpoint/edge identity, actual Python save replies, cursor/context menu after save, Undo/Redo and recreated card passed. Optional capture directory records before/after screenshots with the whole plan fitted.
- `npm run build`: product TypeScript/Rollup passed. No engine or parser was added to the HA runtime; the card change only adds the canonical format label.

Public model times/RSS and artifact raw/gzip bytes are in the inventory. WASM linear allocation (139,788,288 bytes here) and process peak RSS are distinct observations; neither is a browser-wide memory measurement or a guarantee for all files below the 64 MiB input cap. Current user exports and a prepared KOMPAS example were not supplied. Door operation defaults and unsupported geometry/carriers remain visible losses before download.

Publication and the four published-format → disposable HA journeys are a subsequent acceptance step, recorded in #1458 with the exact accepted source/module hash. No owner HA, stand configuration, Caddy configuration or Houseplan version release is part of this implementation.
