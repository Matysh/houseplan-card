# Опубликованные конвертеры → настоящий HA

Набор #1179 запускается один раз в stable-профиле с готовыми байтами кандидата.
В обычных задачах, бете и hotfix его нет. Это диагностический результат:
отказ или невыполненное окружение видны, но не блокируют Houseplan.

Три сценария используют небольшие существующие синтетические fixtures:

- Sweet Home 3D: две комнаты, общая стена, дверь и окно.
- Easy Floorplan: комната, проём, три устройства, мебель и параметры света.
- picture-elements: 1600×1000, одиннадцать значков, два текста, действие script.

Каждый открывает именно `https://houseplan.tech/convert/` в отдельном пустом
контексте, выбирает файл и скачивает результат. В авторизованном HA-контексте
тот же скачанный файл поступает через обычный chooser в preview/apply. Проверки
читают принятые данные, затем перезагружают страницу и проверяют их сохранность
и отображение. Backend API не заменяет UI-переходы. Локальный HTML/CLI-конвертер
не подставляется вместо опубликованного сайта.

Сценарии хранятся здесь и копируются в новый private workspace подготовленного
`houseplan-e2e` вместе с тремя fixture-файлами. Companion не редактируется.
Используется существующий `runE2E`: отдельный seed/UUID-контейнер, фиксированная
loopback-публикация и удаление только контейнера с подтверждённой меткой владельца.
Для converters нужен только auth setup, без plan-model и других E2E journeys.

Для адресной проверки подготовить обычные зависимости companion/Chromium/Docker
по DEVELOPMENT/TESTING и JSON с точными входами, например:

```json
{
  "event": "converters",
  "e2eRoot": "/prepared/houseplan-e2e",
  "workRoot": "/private/converter-labs",
  "haVersion": "2026.10.4",
  "targetRef": "v1.83.1",
  "expectedVersion": "1.83.1"
}
```

`node process-next/cli.mjs run --request converters.json` выполняет только этот
диагностический набор. Для резерва `process-next-fallback.yml` указываются SHA
кандидата с обвязкой, `event: converters`, `haVersion` и полный `e2eCommit`
companion. Резерв устанавливает точный source candidate; stable использует
свою уже подготовленную release-package, не свежий dev и не повторную сборку.
Это не команда выпустить версию.

`artifacts/process-next/converters/report.json` и `report.md` различают три
формата, этап отказа и `passed / failed / unavailable`. Сохраняются SHA256 HTML
и ресурсов опубликованной страницы, ETag, версия/хеш скачанного JSON, точный
Houseplan ref/версия, HA version и identity исходников companion. Полные
Playwright-отчёты, скачанные файлы и кадры — в `artifacts` соответствующей
private lab; авторизация и HA config не входят в итоговый публичный отчёт.

Ошибки преобразования и импорта публикуются как баг в **houseplan-card**.
Stable включает публикацию автоматически. Адресный запуск сначала сохраняет
диагностику без создания багов: исполнитель разбирает её и публикует установленный
дефект. Прямой CLI адаптера допускает явный `--publish-failures` для того же отчёта.
Повтор того же формата/HTML-артефакта обновляет открытый баг. Отказ на стадии
импорта не объявляется доказанной поломкой конвертера: исходная причина требует
разбора. Недоступное окружение не создаёт баг конвертера. Если GitHub-запись
недоступна, остаётся явный `issues: pending`; исполнитель выпуска публикует
диагностику вручную, сохраняя результат, без повторения продуктовых тестов.

Тесты `process-next/test/converters.test.mjs`, `e2e.test.mjs`, `catalog.test.mjs`
и `fallback.test.mjs` адресно проверяют маршрутизацию и отчёты. Их зелёный
результат сам по себе не доказывает прохождение настоящих трёх HA-сценариев.

Первый настоящий прогон 02.11.2026: [41456147729](https://github.com/Matysh/houseplan-card/actions/runs/41456147729),
HA 2026.10.4, Houseplan 1.84.0-beta.2, converter plan-convert 0.2. SH3D прошёл
полный путь. Easy сохранил данные, но проём не отрисовался после reload (#1211);
опубликованный сайт не предлагает picture-elements (#1210). Это установленные
диагностические отказы, не принятые исключения и не разрешение подменить сайт
локальным артефактом. Следующие результаты определяются новым отчётом.
