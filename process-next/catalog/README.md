# Инвентарь миграции #1105

Правила — в [корневом PROCESS.md](../../PROCESS.md), исполняемые профили — в ../lib/catalog.mjs; снимок решений — в ../decisions/1105.json. Здесь нет второго процесса или обязательного запуска аудита. Состояние подключения — в [отчёте переключения](../evidence/cutover-status.md); старые механизмы и их тесты находятся в `legacy/process-v1/`.

Список исполняемых Node/backend/browser файлов теперь обнаруживается в текущем дереве. Инвентарь задаёт явные исключения и группы известных файлов, а не закрытый список разрешённых тестов: новый файл не пропадает из набора из-за старого снимка. Известные `addressed`/`retire` и `automaticReleaseRun:false` в общий продуктовый набор не входят.

inventory.json перечисляет 591 Node-файл, 108 backend-файлов, 492 browser-файла и 326 golden-сцен коммита 96a97b8. Это исходный снимок аудита; его golden `beta`/`baselinePresent` описывают прежнюю выборку. Актуальное размещение и состав визуальных сцен определяют selections.mjs и golden-selection.mjs. Решения: retire — исключён из исполнения и перенесён в архив; addressed — только при изменении механизма; keep — оставлен в соответствующей продуктовой выборке.

Числа деклараций — статический AST Node / определения Python, не исполненные кейсы. Параметризация, циклы, вложенные тесты и пропуски меняют результат. 92 адресных файла не означают обязательные 721 проверки: механизмы разнесены по упаковке, harness, визуальным инструментам, измерениям, ревью и fixtures; смешанные части требуют отдельного решения при переносе.

Оставшиеся 490 browser-файлов — консервативный инвентарь stable, **не утверждение о выполненной содержательной ревизии каждого кейса**. Бета использует ровно 13 файлов. У Node 10 групп и import/data closure; динамические читатели исходного дерева консервативны. Browser запускает всю карточку и имеет широкие зависимости: узкое повторение одного browser-кейса по любому src-изменению не заявлено.

Golden runner адаптирован из старого с сохранением semantic/pixel assertions. При активации две копии нужно объединить. Владелец 01.11 расширил бету с 25 до **75 сцен**. Прежние 25 сохранены, добавлены 50 существующих сценариев без перебора всех тем и размеров. Точные группы/ID — `GOLDEN_ADDITIONS`; это сцены, не число внутренних screenshot/assertions.

В исходном прогоне подготовки не было эталонов для 54 новых панельных ID, одной выбранной Static-сцены и ещё трёх Static-сцен в остатке. Это исторический снимок: актуальное наличие PNG и сравнение определяются текущим деревом и отчётом. Старые PNG карточки не подставляются вместо панельных; включение новой обвязки само по себе ничего не принимает. Stable использует те же 75 плюс 251 оставшуюся сцену: новые варианты заменяют исходные, всего 326 без двойной матрицы.

После включения изменений выпущенной `v1.84.0-beta.1` прочитано наличие эталонов:
отсутствуют только 54 новых панельных PNG; все Static и остальные 251 сцена
имеют эталоны. Это проверка наличия, не новый визуальный прогон и не принятие PNG.

Семантическая подготовка/repaint получают исходный scene ID, чтобы сохранить проверки, привязанные к точному имени; отчёт и PNG используют новый ID. После подготовки проверяется фактический host кадра, включая пересоздание карточки. Static получает отдельную страницу: изменение его контейнера не влияет на следующую интерактивную сцену. Исходный разбор #1181 относился к прежнему harness; продуктовые исправления сохраняются в общем harness, а не копируются в процесс.

Исторический прогон прежних 25: 25,0 с, 2 passed / 6 different / 17 missing-baseline, без ошибок подготовки; `../evidence/golden-panel-beta-wsl.json`. Он не доказывает готовность расширенной выборки. Унификация самой шапки — отдельная продуктовая #1184.

Расширенные 75 выполнены в WSL за **109,9 с**: 5 passed / 15 different / 55 missing-baseline, **0 ошибок подготовки/смысловых проверок**, все 75 actual PNG созданы, фактические host совпали с заявленными. Отчёт `../evidence/golden-beta-75-wsl.json`. Pixel compare выполнен для 20 сцен с существующими эталонами; время сравнения всех 75 после принятия PNG ещё не измерено. Это **не зелёный визуальный набор**, эталоны не приняты. Адресные 8 тестов каталога — PASS (Windows, 10,95 с); полный beta-профиль не запускался.

Шесть Python converter-контрактов используют реальные schema/import/preview продукта с внешними golden fixtures; обычная защита импорта/повреждённых документов сохранена. Coverage знаменатель не сужен; влияние исключения этих файлов на порог 87.2% здесь не измерялось. Полный converter E2E #1179 подключён отдельным диагностическим stable-шагом: опубликованный сайт → скачанный JSON → UI импорта изолированного HA. Окружение без необходимых входов остаётся unavailable. Команды и результаты описаны в [converters/README](../converters/README.md).
