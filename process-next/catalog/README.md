## Действующий каталог

`node process-next/cli.mjs catalog` печатает читаемый список, `--json` — записи с type/layer/domains/scenario/importance/lifecycle и видимыми пробелами. Это команда просмотра, не новый обязательный gate/job. `inventory.json` ниже — исторические решения keep/addressed/retire; реальные файлы берутся из текущего дерева. Правила и связи компонентов находятся в `../lib/task-selection.mjs`, общий import/data reader — `../lib/source-dependencies.mjs`. Старый процесс не сканируется и не восстанавливается.

На 2026-11-06 после добавления тестов этой задачи: 1213 активных Node/backend/native файлов, 326 визуальных сцен, 93 бизнес-сценария HA плюс 3 setup, 3 диагностических конвертера и 2 фоновые группы — 1640 записей разных типов, **не 1640 тест-кейсов**. Это снимок структуры; новый файл меняет числа без ручной правки allowlist. Проверка текущего дерева с закреплённым companion не обнаружила неразмеченных записей. Области шире четырёх примеров: геометрия/проёмы, хранение/полномочия/история, редакторы/декор, устройства/климат, View/UI, навигация/киоск, свет, сводка/погода, пылесосы, Zigbee, радары, лестницы, 2.5D, PDF, локализация, runtime/security, общие функции, производительность и инструменты/процесс.

### Глубина и причины

Общее продуктовое ядро и стартовый View сохраняются. Ship берёт импортирующие/читающие тесты и критичные/пограничные файлы поведения, Show — компонент и непосредственные контрактные связи, Ask — быстрые наборы затронутых/связанных подсистем плюс native сквозные witnesses. Критичные геометрия, хранение и история широкие при любом треке. Все категории/приоритеты наследуются от файла; кейсы внутри файла не отфильтровываются по названию. `areaTests` добавляет найденные риски, не сужает обязательный набор.

Неразмеченный исходник: обратные import/data связи плюс консервативный быстрый набор (полный Node, а для backend также полный backend), с явным предупреждением. Dynamic readers `src/**` получают смысловую область, а не выбираются при каждом изменении из-за wildcard. Rename/delete поступают обеими сторонами через diff `--no-renames`; существование исполняемого теста, в отличие от удалённого исходника, обязательно.

### Единицы, границы и окружение

Дедупликация идёт по файлу/стабильному шагу; ID выводится из пути, не из меток и состава соседних файлов. Дополнения не меняют команду уже выбранного файла. Синтаксис проверяет изменённые инструменты как данные, поведенческий шаг хеширует свои реальные import/data зависимости. Нет повторного запуска ради переноса WSL→GitHub. Подготовка задачи в fallback получает browser/backend/Python из actual plan; docs возвращаются ещё до обнаружения исполнителей. Смешанный diff включает продукт и инфраструктуру.

Для `test/coverage-diagnostic.test.mjs` явно описана область собственных generated fixtures: создаваемый им dist лежит в mkdtemp, не в checkout продукта. Это узкое исключение, а не разрешение всем infrastructure тестам читать dist. Отдельный регрессионный случай требует отказа для настоящего artifact consumer без подготовки. Строка, конструирующая fixture-код или объявляющая будущую команду worker, не считается импортом этого кода; реальные imports/URL/data readers продолжают отслеживаться.

### Внешние наборы

Golden использует ту же актуальную matrix/замену панельных вариантов, что release. `companion-inventory.json` — безопасный project/file/title roster из реальных HA отчётов stable 1.84.0, источник и pinned SHA указаны внутри. Авторизация, state HA и результаты с приватными значениями в снимок не входят. Для текущего внешнего дерева: `catalog --e2e-root /absolute/companion`. Проверяются source/config/fixture fingerprints; новый/изменённый ввод показывает явный пробел до штатного Playwright discovery, архив tests/legacy не возвращается. Без root это честно snapshot, не утверждение о текущем внешнем HEAD.

Эти проверки видны в каталоге, но не запускаются автоматически на S6 задачи. Реальные HA E2E/golden остаются перед бетой/stable, мутации/JS coverage фоновыми, конвертеры диагностическими. Точный набор параметризованных cases узнаётся из реального runner/pytest/Playwright отчёта. Сцены и файлы считаются отдельно; неизвестное остаётся null. Структурная классификация не является доказательством полноты пользовательского поведения каждого теста.

### Стоимость

`costs.json` хранит фактические сохранённые WSL наблюдения: source run/SHA, Node/платформа и concurrency. У native шагов есть wall time; агрегат Node-группы не делится на выдуманные стоимости отдельных файлов. Известная часть включает подготовку/сборку, неизвестные единицы и неизвестное время целого видны отдельно. Старый измеренный минимум всего S6 — 45.8 с, сборка 42.2 с (`product-minimum-wsl.json`); это историческая база, не измерение нового профиля и не прогноз для GitHub. Гипотезы 1–2 / 5–7 / до 10–15 минут не становятся сроком, квотой или нижней границей. Только необязательные связанные дополнения используют остаток известного бюджета по приоритету; обязательная ширина не режется.
