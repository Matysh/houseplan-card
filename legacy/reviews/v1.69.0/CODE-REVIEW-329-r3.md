# CODE-REVIEW-329-r3

Этап: code · заход r3 · блокирующих циклов израсходовано 2 из 4

## Скоуп раунда

Предыдущий вердикт (code r2, `226`-й комментарий issue) — красный,
единственная находка **r2-H1**: мутант `junction-limit-backend-raw-baseline`
в `scripts/mutation-gate.mjs` был добавлен с `guard: 'python3 -m pytest
tests_backend/test_junction_limits.py -q'`, в обход конвенции ВСЕХ прочих
бэкенд-мутантов реестра (`node scripts/backend-test-guard.mjs <pattern>
<file>`), из-за чего `test/mutation-gate.test.mjs` красился на CI.

Вердикт r2 получен на SHA `26c6e870` (Matysh: «Актуальный HEAD ветки для
ревью — `26c6e870`», непосредственно перед вердиктом). Автор закрыл
находку коммитом `273b0d5e`, текущий HEAD.

Дельта этого раунда:

```
git diff 26c6e870..HEAD --stat  (без docs/reviews/*)
 scripts/mutation-gate.mjs   | 4 ++--
 test/mutation-gate.test.mjs | 6 +-----
 2 files changed, 3 insertions(+), 7 deletions(-)
```

Дельта не затрагивает `src/**`, бэкенд-продакшен-код, геометрию, документацию
пользователя — только реестр мутантов и его контрактный тест. Это ровно то,
что запрошено находкой r2-H1, без побочных правок. Разбор по дельте признан
достаточным: изменение локально, не является ребейзом, не меняет контракт
поведения продукта и по объёму несопоставимо мало относительно исходной
задачи (две строки правки guard + возврат теста к исходному виду).

## Что проверено (дельта)

1. **Форма guard соответствует конвенции.** Новый guard —
   `node scripts/backend-test-guard.mjs
   test_legacy_baseline_is_judged_after_the_same_migration
   tests_backend/test_junction_limits.py` — совпадает по форме со всеми
   остальными записями реестра, использующими бэкенд-хелпер (проверено
   `grep -n "backend-test-guard" scripts/mutation-gate.mjs` — 16 вхождений,
   новое неотличимо от прочих).
2. **Контракт теста возвращён к исходному виду.**
   `test/mutation-gate.test.mjs` снова требует, чтобы guard называл `.mjs`
   (убрана временная ветка `.py`, убран комментарий-объяснение, который её
   оправдывал). `grep` подтвердил: других мутантов, называющих `.py`
   напрямую (в обход хелпера), в реестре нет — правка не откроет дыру для
   будущих аналогичных случаев.
3. **Мутант по-прежнему ловит регрессию.** Прогнан НЕ ТОЛЬКО `--check`
   (проверяет только уникальность якоря патча), а полный цикл конкретного
   мутанта:
   `node scripts/mutation-gate.mjs --id=junction-limit-backend-raw-baseline`
   →
   ```
   ok   чистый прогон: node scripts/backend-test-guard.mjs test_legacy_baseline_is_judged_after_the_same_migration tests_backend/test_junction_limits.py
   ok   junction-limit-backend-raw-baseline: тест покраснел, как обязан
   поймано 1 из 1
   ```
   То есть подтверждено обеими половинами: код без мутации проходит целевой
   тест, а с применённым патчем (`migrated = config` вместо прогона через
   `commit_wall_segment_model`) целевой тест красится. Это и есть доказательство
   «тест умеет падать» для данной находки.
4. **pytest напрямую.** `python3 -m pytest tests_backend/test_junction_limits.py -q`
   → `8 passed`. (pytest в песочнице ревью отсутствовал изначально, установлен

## Чего не проверял в этом раунде и почему

- **`npm run golden:verify`** — не прогонял. Дельта не трогает рендер,
  геометрию, стили, слои; полная матрица (~80 сцен) уже прогнана и зелёная
  в r2 на коде, который в r3 не менялся.
- **`npm run invariants`** — не прогонял. Дельта не трогает рёбра комнат,
  записи толщины, `layout`, `marker.space`, `open_spans` — инварианты модели
  здесь неприменимы.
- **Браузерные смоки** — не прогонял ни одного. `smoke-select.mjs` для
  диапазона `26c6e870..HEAD` прямо сообщает «выбирать нечего»: единственные
  изменённые файлы — `scripts/mutation-gate.mjs` и `test/mutation-gate.test.mjs`,
  оба вне `src/**`, ни один смок такой диапазон не оценивает даже как слабую
  связь.
- **`python -m pytest tests_backend -q` (полный набор)** — прогнал только
  файл `test_junction_limits.py`, целевой для находки; полный бэкенд-набор
  не запускал, так как дельта не трогает бэкенд-продакшен-код (только тест
  и реестр мутантов на фронтенде/CI), а `test_junction_limits.py` — тот файл,
  контракт которого проверяет закрытие r2-H1.
- **Performance-профили** — не прогонял, в AC не названы и дельта их не
  задевает.
- **Полный `.github/workflows/mutation-gate.yml` (пересборка бандла на
  каждого мутанта)** — не прогонял; это предрелизный гейт (PROCESS.md §8),
  несоразмерен точечной правке одной записи реестра. Точечный прогон именно
  этого мутанта сделан отдельно (см. выше) и достаточен как доказательство.
