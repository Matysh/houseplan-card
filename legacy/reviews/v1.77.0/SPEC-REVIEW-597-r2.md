## Как проверялось (дельта)

1. Сверил текущий текст AC2/К3/AC3 с цитатами старого текста в документе r1 —
   изменения ограничены ровно этими тремя местами плюс преамбулой «Редакция r2»,
   ничего другого в разделах «Аналитика», «Скоуп/не-скоуп», «Риски», «Откат»,
   «Release-артефакты», «Принято предположительно» не тронуто.
2. Прочитал `test/form-kit.test.mjs:25-58` в текущем дереве: словарь `PANEL_FRAGMENTS`
   существует, содержит ровно пять точных текстов (карточка-группа, обводка фокуса,
   выключенное состояние, ряд-переключатель, подпись ряда), и подтвердил находку r1
   независимо — строка `min-height: 54px` (form-kit.test.mjs:47) действительно лежит
   только внутри фрагмента «ряд-переключатель». Значит план M1-фикса («цикл по всем
   пяти текстам из этого же словаря») технически реализуем сегодняшними средствами
   файла — ровно то, что заявляет исправленный AC2.
3. Прочитал `test/styles-split.test.mjs:13-79`: подтвердил характеристику r1 — проверка
   для `CARD_DIALOG_FORM_KIT` строит `Set` селекторов и считает `@media`/`@supports` по
   заголовкам блоков, полного текстового сравнения действительно нет. Значит пробел,
   который называла M2, реален, и предложенное автором добавление байт-в-байт фикстуры
   его закрывает по существу, а не по формулировке.
4. Собрал тестовый бандл (`tsc -p tsconfig.test.json` + `fix-test-build.mjs`) и
   независимо вычислил `formKitCss(CARD_DIALOG_FORM_KIT, …)`:
   ```
   без переключателя: 1885
   с переключателем:  2399
   ```
   Числа совпали с теми, что автор привёл в комментарии-ответе («1885 | 2399», «оба
   совпали побайтово») — заявление проверено вычислением, а не принято на слово.
5. `ls test/fixtures/` — ни одной из трёх фикстур (`summary-panel-editor.css`,
   `form-kit-card-dialog.css`, `form-kit-card-dialog-with-switch.css`) в дереве ещё нет,
   что соответствует стадии «спецификация»: реализация не начата, гейты кода к этому
   раунду неприменимы.
