## Как проверялось

Материал ревью — ровно `62d86e0f`; `git checkout`/`fetch` на другой коммит не
делал.

Дешёвые гейты на этом SHA уже подтверждены Validate (упомянуто в задании
ревью: прогон `35151230014`, `success`) — это тот же код, что и на `9bf41ec3`
(дельта раунда не трогает исходники), поэтому `npx tsc --noEmit`, `npm test`,
`npm run build`+сверка бандлов, `check-docs.mjs`, browser-смоки,
`golden:verify`, мутанты — повторно не гонял. Причина не «доверие», а
«нулевая дельта кода»: r1 эти гейты уже проверил на идентичном дереве
(`9bf41ec3`), а r2 к дереву ничего не добавил кроме доксового файла, который
эти гейты не касается.

Единственное, что требовало самостоятельной проверки в этом раунде —
достоверность чисел из закрывающего комментария M1. Числа не входят ни в один
автоматический гейт как утверждение соответствия ТЗ (сам факт наличия числа в
отчёте гейтом не проверяется), поэтому свериться нужно было вручную:

```
python3 -c "
import json
d = json.load(open('custom_components/houseplan/frontend/houseplan-assets.json'))
for k in ['initialViewGzipBytes','lazyGzipBytes','lazyFurnitureArtGzipBytes']:
    print(k, d.get(k))
"
# HEAD (62d86e0f): initialViewGzipBytes 291158, lazyGzipBytes 433657, lazyFurnitureArtGzipBytes 23338

git show origin/dev:custom_components/houseplan/frontend/houseplan-assets.json > /tmp/dev-manifest.json
python3 -c "... тот же код на /tmp/dev-manifest.json ..."
# dev (e0b16c76, тот же код мебели что и 7c5fd32a): initialViewGzipBytes 291111, lazyGzipBytes 420521, lazyFurnitureArtGzipBytes 10254
```

Результат совпадает с комментарием **побитно**:

| поле | `dev` (было) | `HEAD` (стало) | дельта в комментарии | дельта, посчитанная мной |
|---|---|---|---|---|
| `lazyFurnitureArtGzipBytes` | 10 254 | 23 338 | +13 084 Б, +128 % | +13 084 Б, +127,6 % → округление до +128 % корректно |
| `lazyGzipBytes` | 420 521 | 433 657 | +13 136 Б, +3,1 % | +13 136 Б, +3,124 % → округление корректно |
| `initialViewGzipBytes` | 291 111 | 291 158 | +47 Б, +0,016 % | +47 Б, +0,0161 % → округление корректно |

Источник чисел — реальный закоммиченный файл манифеста
(`custom_components/houseplan/frontend/houseplan-assets.json`, поле пишет
`scripts/bundle-manifest.mjs`, тот же источник, которым руководствуется
`scripts/bundle-budget.mjs` при проверке бюджета `INITIAL_VIEW_GZIP_BUDGET =
301 066`), а не отдельный ручной подсчёт по blob'ам, как было у меня в r1.
Значит число теперь официальное и воспроизводимое любым будущим ревьюером той
же командой, а не разовый расчёт ревьюера.

Дополнительно проверено: `291 158 < 301 066` — initial-View бюджет не задет
(и не мог быть задет: арт мебели лежит в ленивом чанке, `initialViewFiles` его
не включает — подтверждено ещё в r1 чтением `lazyFurnitureArtFiles`).
