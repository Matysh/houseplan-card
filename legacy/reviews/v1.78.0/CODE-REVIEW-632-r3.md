## Почему это r3, а не продолжение зелёного r2 — реконструкция по issue и логам

r2 (`docs/reviews/CODE-REVIEW-632-r2.md`, материал `b64bc932`) уже вынес
**зелёный** вердикт: High 0, Medium 0. Зелёный цикла не образует и должен
двигать задачу вперёд (§4). То, что ревью назначено снова, — не сигнал о
находке, а следствие события после вердикта; разобрал по комментариям issue
и логам CI, а не со слов автора:

1. Пока шло ревью r2, `dev` продвинулся на 2 коммита; автор перебазировал
   ветку на `dev@c8f9b5d3` → кандидат `1e866291`.
2. Validate на `1e866291` красный (run `35949058000`, `conclusion: failure`,
   проверено `gh run view`). Разобрал сам, какой именно job/шаг упал:
   ```
   $ gh run view 35949058000 --json headSha,conclusion,status,jobs
   headSha 1e86629189ddf61eacae82fac281b7a13915611a conclusion failure
   Предполёт: документация, провенанс, процесс   failure
   Фронтенд: типы, юниты, мутанты, синхрон бандла   success
   Мутанты по диффу (1..6/6)                         success (все шесть шардов)
   ```
   Упал только предполётный job; **все** мутантные шарды и фронтенд-гейт —
   зелёные на этом кандидате. Внутри упавшего job — конкретно шаг
   `workflow_sync`:
   ```
   $ gh run view 35949058000 --log-failed | grep -i "process.yml\|различаются"
   РАСХОЖДЕНИЕ: process.yml в main и dev различаются.
   ```

   Это проверка «`.github/workflows/process.yml` в `main` совпадает с
   `dev`» — репозиторного уровня инвариант, никак не зависящий от дерева
   ветки #632 (её диф вообще не трогает `.github/workflows/**`, см. список
   файлов выше). Причина расхождения — независимая правка #634 в `main`,
   не отражённая в зеркале; сам автор её так и определил в issue.
3. Автор зеркалировал `main` (`main = 7752329d`) и **переподписал вершину
   без изменения дерева**: `14396ed0` имеет то же дерево, что и кандидат до
   переподписания (дерево `0d959028`, по словам автора) — я это не принимаю
   на слово, а проверяю ниже блобами по каждому файлу.

Итог: r3 — не ревью новой правки, а подтверждение, что дерево, получившее
зелёный вердикт в r2, не изменилось, и что сорвавшийся кандидат упал по
причине, не относящейся к #632. Разбираю дельту, а не задачу целиком
(PROCESS.md §2.10) — она пуста по коду.
