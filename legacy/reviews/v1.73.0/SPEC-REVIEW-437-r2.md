## Скоуп проверки r2

r1 закончился жёлтым вердиктом с одной находкой Medium (M1, в скоупе) и двумя
Low (L1, L2). Это не первый цикл, поэтому объём разбора — по дельте
(PROCESS.md §2.9), а не заново.

```
docs/reviews/SPEC-REVIEW-437-r1.md | 246 +++++++++++++++++++++++++++++++++++++
docs/specs/437-summary-panel.md    | 125 ++++++++++---------
```

Второй файл в diff — публикация r1-документа шагом конвейера (не автор,
содержимое совпадает с найденным на GitHub комментарием, не редактировалось).
Единственный файл, изменённый автором по существу, — `docs/specs/437-summary-panel.md`.

Дельта локальна и не требует полного разбора: правки не меняют ни одного AC,
ни модель хранения, ни контракты поведения — только (а) добавление раздела
French в §10 (i18n) с производными правками AC11, матрицы макетов и §12, и
(б) явное определение `viewAllowed` в §5.3, плюс (в) точечные пробельные
правки чисел по всему документу (не меняющие арифметику). Продуктовый код не
тронут ни в r1, ни в r2.

## Как проверялось

1. Прочитано тело issue #437 (текущая версия) и все 8 комментариев целиком,
   включая раунды r1/r2 и команду владельца «S5-ready, затем остановка,
   реализацию не начинать».
2. Получен полный текст `git diff 4a1aac16..14597ccd -- docs/specs/437-summary-panel.md`
   и построчно сверен с таблицей находок r1 (раздел «Закрытие раунда r1» ниже).
3. Прочитан весь изменённый раздел §10 «i18n и визуальное соответствие» после
   правки, а также затронутые AC11/§12 численные fixtures — целиком, не по
   диффу, поскольку это содержательная правка, а не только пробелы.
4. Проверено определение `viewAllowed` (новая строка §5.3) на согласованность
   с §4.1 (единственное место, где до этого описывался View/kiosk/редакторы) —
   термины совпадают дословно.
5. Факт-чек M1 переисполнен независимо от r1, а не принят на слово:
   - `src/i18n/registry.ts` — French зарегистрирован как полноценная locale с
     ленивой загрузкой (`loadFrench`), тем же паттерном, что немецкая.
   - Подсчитаны ключи всех четырёх словарей: `en.json`, `ru.json`, `de.json`,
     `fr.json` — по 1257 ключей в каждом (python3 `json.load` + `len`).
   - `CONTRIBUTING.md:14–28` подтверждает автоматический parity-тест реестра
     локалей; `test/i18n.test.mjs` присутствует в дереве.
6. Проверена структурная целостность документа после правок: `## `-разделов —
   14 (без изменений), строк `| AC` — ровно по одной на каждый номер AC1…AC26
   без пропусков и дублей (`grep -oP '^\| AC\d+'` + сортировка), `wc -l` = 725.
7. Проверено, что вне изменённых разделов дельта не задела семантику: полный
   `git diff` построчно проверен на предмет отсутствия смысловых правок —
   единственные изменения не в §10/§5.3 — вставка пробела перед/после числа
   (`336`→`336 `, `72`→` 72`, `1`→`версия 1` и т.п.); отдельный `grep -noP`
   по всему файлу на оставшиеся «слово+число без пробела» не нашёл ни одного
   пропущенного случая вне легитимных идентификаторов (`AC1`, `P2`, `i18n`,
   `p95`, номера коммитов/hash).
8. `docs/SCOPE.md` и `docs/specs/README.md` — не тронуты в дельте r1→r2
   (`git diff --stat` подтверждает отсутствие изменений), их корректность

## Чего не проверял и почему

- **`npm run golden:verify`, браузерные smoke (`demo/smoke_*.mjs`), инварианты
  модели (`npm run invariants`), performance-профили** — не прогонялись.
  Diff не меняет продуктовый код, геометрию, `layout`, `marker.space`,
  `open_spans`, рендер или видимое поведение приложения: правка ограничена
  текстом ТЗ (i18n-раздел ещё не реализованной фичи + определение термина +
  пробелы). Эти AC (продуктовая реализация) физически не существуют в коде
  на этом SHA — гонять их не по чему.
- **Три копии бандла на совпадение** в рамках `npm run build` — не
  сверялись, поскольку сборка вообще не является предметом этого diff
  (продуктовый код не менялся ни в r1, ни в r2); `npm run build` прогнан
  только как дешёвый sanity-гейт, а не потому что диф мог сломать сборку.
- **Перевод FR построчно носителем языка** — не проверялся; это вне
  компетенции автоматизированного ревью. Механически подтверждено, что
  таблица заполнена по всем 15 строкам и не содержит явных артефактов
  (пустых ячеек, скопированного текста другого языка).
- **`docs/reviews/SPEC-REVIEW-437-r1.md` как публикуемый артефакт** — не
  ревьюировался повторно по существу: это готовый отчёт предыдущего раунда,
  зафиксированный шагом публикации конвейера, а не предмет ТЗ-ревью r2.
