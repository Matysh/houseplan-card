## Находки

Блокирующих (High/Medium в скоупе) не нашёл.

### Не в скоупе / не критично (не возвращаю автору, фиксирую для памяти)

- `BodyObstaclesMemo.read` ключует тела через `bodies.join('|')` (`physical-geometry.ts:434`) — стрингификация без явных разделителей между точками одного тела, в отличие от явных `','`/`'/'`/`';'`-схем в `floor-geometry-key.ts`. Практической коллизии нет (см. «Как проверялось», п. 7), юнит-тест по значению уже существует. Не требую правки — просто не тот стиль ключа, который принят в остальном модуле; возможный повод для позднейшей косметики, не для возврата.
- Табличного перечисления «AC7 · чем доказано · чем краснеет» в комментарии автора нет (есть только для AC1–AC4). Проверил: инвариант AC7 «нет неограниченных записей / устаревшей геометрии» механически использует тот же `floorPoolEntry`/`lruWrite(…, WALL_UNION_POOL_LIMIT)` и то же ключевание по содержимому, что уже остеклено мутантами AC1 (`opening-wall-index-key-global-epoch`, `sun-key-global-epoch`) и AC2 (`floor-pool-single-slot`, `physical-bodies-pool-bypassed`, `opening-tunnel-evicting-miss-uncounted`) — отдельного механизма AC7 не вводит. Смок AC7 дополнительно гоняет реальный `disconnectedCallback`/remount/`config replacement` и проверяет `pools().every(size <= 8)` и раздельность пулов инстансов — это честная интеграционная проверка состава уже остеклённых единиц, а не новый защищаемый механизм без свидетеля. Фиксирую как наблюдение, не как находку — пустой третий столбец здесь не «дыра», а переиспользование чужого свидетеля, которое я проверил сам.
