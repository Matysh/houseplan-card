## Находки

### Medium (в скоупе, возврат автору) — M1: решение о виртуальных устройствах не отражено в списке release-артефактов, `docs/SCOPE.md` останется противоречащим коду

**Файл:** тело issue #930, §11 «Риски, откат и release-артефакты» (список
«Документы в commit с поведением»); противоречащий документ —
`docs/SCOPE.md`, раздел «Excess-functionality audit (2026-07-22)».

ТЗ фиксирует подтверждённое владельцем 2026-10-17 решение (§13, Q1):
виртуальные устройства становятся полноценными участниками каталога
«Устройства» — входят в «На плане»/«Скрытые», получают фильтр по
пространству, Find, настройки, одиночное и **пакетное** Hide/Show/Delete
(§5.7, §6.7, AC10). Сегодня это не так: `src/device-inbox.ts:197,203`
исключает виртуальные маркеры из каталога целиком (`device.virtual ||
marker.binding === 'virtual' → continue`) — виртуальное устройство сейчас
видно и управляется только напрямую на плане, не через этот диалог.

Это прямое функциональное расширение ровно того пункта, который
`docs/SCOPE.md` фиксирует явно: «**Virtual devices** — placeholders for
not-yet-installed hardware; serves J6. Verdict: **keep, frozen** (no
growth)» (раздел «Excess-functionality audit (2026-07-22)»). Решение
владельца от 2026-10-17 по существу отменяет для #930 более старую позицию
2026-07-22 — это его право, не находка сама по себе. Находка в другом: ТЗ
не называет `docs/SCOPE.md` среди документов, которые правятся в том же
коммите (§11 перечисляет `USER-GUIDE.ru.md`, `USER-GUIDE.md`, `FILTERING.md`,
`ARCHITECTURE.md`, `DEVELOPMENT.md`, `STATUS.md`, changelog — без
`SCOPE.md`). После реализации #930 запись «keep, frozen (no growth)»
останется в репозитории дословно неверной: виртуальные устройства получат
новую пакетную и фильтруемую поверхность, которой на дату аудита не было ни
в каталоге, ни в его операциях.

`docs/SCOPE.md` описывает сам себя как единственный ограничитель, по
которому обсуждаются будущие запросы на рост функциональности
(«features are built, improved and accepted only if they serve a job listed
here... When a new idea appears, first find its row in this file»). Будущий
аналитик или ревьюер, читающий раздел audit буквально, по-прежнему увидит
«frozen, no growth» рядом с уже свершившимся ростом — это создаёт риск либо
необоснованно заблокировать смежную легитимную задачу по виртуальным
устройствам, сославшись на устаревшую запись, либо спутать её с этой уже
принятой.

Это ровно «связанные документы» из собственного пункта «В скоупе» ТЗ (§3:
«...четыре текущие локали, связанные документы/проверки»), то есть
находка в скоупе задачи, не чужая территория.

**Предложение по умолчанию:** добавить `docs/SCOPE.md` в список §11 и при
реализации обновить строку аудита виртуальных устройств, зафиксировав дату и
issue (например: «keep; #930 добавил каталожное/пакетное членство наравне с
HA-маркерами по решению владельца 2026-10-17, дальнейший рост по-прежнему не
предполагается»). Текстовая правка одной строки ТЗ плюс одной строки
`SCOPE.md` при реализации, продуктового решения владельца не требует (оно уже
принято в §13).
