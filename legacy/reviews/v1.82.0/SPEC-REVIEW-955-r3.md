## Что проверено и корректно

- Новый раздел не меняет модель данных, Cancel/Save/dirty-контракт, View и
  не-скоуп: это уточнение способа визуальной проверки (AC1) и геометрии уже
  существующих пунктов 9/AC2, прослеживаемое явной привязкой «К пункту 9 и
  AC2» — не вводит отдельного неименованного AC и не расширяет скоуп задачи.
- Способ доказательства назван и не выходит за разрешённый словарь: сравнение
  скриншотов side-by-side/наложением при одинаковых viewport/DPR/шрифтах HA —
  детализация уже заявленного в AC1 «smoke и golden… парные данные до/после;
  просмотр actual/diff изменённых кадров», не новая категория evidence.
- Явно снят риск ложного автоматического PASS: «карта различий с
  размытием/порогом… не заменяет просмотр» и «не объявлять отсутствие точного
  pixel match автоматическим PASS» — закрывает именно тот тип неоднозначности,
  где числовой порог мог бы подменить ревью; это усиливает приёмку, а не
  ослабляет её.
- Численное требование «4px» для help у двухстрочного названия задаёт
  измеримый критерий там, где исходный п.4 требовал только «выровнен с
  текстом и тумблером» без числа — устраняет потенциальную неоднозначность, а
  не вносит новую.
- Требование к SVG-иконке («внутренний SVG, а не центр внешнего `ha-icon`»)
  называет конкретный технический срез измерения, укладывающийся в уже
  названный метод AC2 «browser smoke с computed style/геометрией».
- «Воспроизводить смещение при разных унаследованных шрифтах/line-height»
  применяет уже сформулированное в AC2 правило «симптомные проверки сначала
  должны воспроизводиться на старом коде» к конкретному дефекту, а не вводит
  новую методику.
- «Включая LED/климат/пылесос/радар и mobile» не расширяет скоуп: типы
  Device уже перечислены в AC3, viewport 320/390px (mobile breakpoints) уже в
  AC1; `TOUCH-SUPPORT.md`/desktop-first не нарушается — проверка на мобильном
  viewport остаётся тестом рендера, не новой touch-моделью.
- В новом разделе нет открытого продуктового вопроса: все формулировки —
  прямые директивные указания владельца на треке `ask`, где, по его
  собственной оценке (комментарий 2026-10-18T11:34:15Z), «дальнейшие вопросы
  не нужны».
- Соблюдено правило локального драфта (`PROCESS.md` §11.8, `AGENTS.md`):
  автор явно фиксирует, что локальная ветка и её evidence не публиковались
  как A/B-коммиты до зелёного спек-ревью.

  файлы/план тестов, не-скоуп, риски/откат) — не требуется по §2.10, делта
  локальна и автор прямо заявил неизменность; содержание унаследовано из r2
  (раздел выше).
- Гейты `npx tsc --noEmit`, `npm test`, `npm run build` — не прогонялись:
  этап spec, продуктового диффа нет, зависимости/Chromium не установлены
  (#696); неприменимы.
- Смоки/golden/инварианты модели/pytest — не прогонялись: нет кода для
  исполнения на этом этапе. Упомянутые автором локальные проверки («304
  native fit/theme checks», «33 парных раздела», «32 Save language/form/
  viewport checks», `gate:small --smokes`) — это evidence реализации на
  локальной непубликуемой ветке, не предмет этого ревью ТЗ и не заменяют
  независимый code review после публикации; сам автор прямо отмечает это в
  комментарии 2026-10-18T15:34:13Z.
- Содержимое мокапов `docs/design/settings-dialogs-944/*.html` построчно по
  новому разделу — не пересматривалось: файлы мокапов не менялись («эталоны
  не переписывать задним числом» выполняется фактом отсутствия изменений
  дерева), содержание доверено r1.
- Точное числовое соответствие нового «4px» существующим значениям в коде:
  `grep` по `src/hp-help.ts`, `src/styles/settings-dialogs.styles.ts`,
  `src/styles/form-kit.styles.ts` не нашёл готового токена отступа help;
  замороженные мокапы содержат `margin-left:6px` у `.field-help-toggle`, но
  это другой случай (одна строка подписи, не второй перенесённой строки) —
  явного конфликта нет, но и прямого эталона для нового числа в
  существующих материалах нет. Не нахожу это находкой: мокапы намеренно не
  переписываются под точечное уточнение, а «4px» — прямое указание владельца
  для нового случая, не домысел автора задачи; точный расчёт остаётся
  предметом реализации и её code review.
