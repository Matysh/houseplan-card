# CODE-REVIEW-508-r2

Issue: #508 — «Сводная панель: в диалоге настроек не работает прокрутка — колесом мыши и touch на мобильных»
Материал: `6ac513caa09a8e583869879412aa3a0c67d04488` (рабочая копия уже на нём). Ветка приведена конвейером к
`dev` до ревью: `e23d742c → 6ac513ca`, поверх легло 1 коммит `dev` (несвязанный — `docs: review document
for #502`).
Заход: r2 · блокирующих циклов израсходовано 0 из 4. Ребейз на ушедший вперёд `dev` формально делает
дерево другим (§7.2) → разбор полный, а не по дельте.

## Почему вообще r2, если r1 был зелёным без находок

Код-ревью r1 (`docs/reviews/CODE-REVIEW-508-r1.md`, материал `768e1281`) уже завершилось вердиктом
«зелёный, находок нет» с исчерпывающим личным прогоном гейтов, мутантов, смоков и подтверждением автора
на живом стенде HA. Сразу после публикации вердикта автор сообщил в issue: «Автоматическое ревью не
отработало» — статусная метка не переставилась, конвейер оставил задачу на месте. Затем конвейер
перебазировал ветку на успевший уйти вперёд `dev` (там landing получил несвязанный коммит с ревью-доком
для issue #502) и передал её на повторное ревью уже под новым SHA. Автор с момента r1 в код и ТЗ не
вносил ничего — это не возврат на правки, а техническое повторение ревью из-за сбоя механики метки плюс
ребейз. Поэтому раздела «находка → возврат → правка» в этом раунде по существу нет: проверка ниже —
подтверждение, что ребейз не изменил и не сломал ничего, а не разбор чьих-то правок.

## Скоуп

Не изменился с r1: один функциональный коммит (`e38beed7`, экс-`768e1281`) — класс A (`src/hp-dialog.ts`,
`src/summary-panel-editor.ts`) + класс B (новый смок `demo/smoke_summary_dialog_scroll.mjs`, контрактный
юнит-тест `test/hp-dialog-contract.test.mjs`, два мутанта в `scripts/mutation-gate.mjs`) + класс C
(`docs/ARCHITECTURE.md`, оба CHANGELOG) + класс D (пересобранный бандл во всех копиях,
`docs/images/screenshots.json` — только фингерпринт). `hp-dialog` получает opt-in булев атрибут
`flex-content` (`?flexcontent` на `ha-dialog`, обе HA-ветки рендера); нативная `<dialog>`-ветка не тронута.
Диалог настроек сводной панели его объявляет — единственный из десяти вызывающих `<hp-dialog>`.

J1 (`docs/SCOPE.md`) — обзорная сводная панель входит в «show the whole home at a glance»; чистый
баг-фикс регресса после #505, скоуп не расширен, продукт не меняет договор.

## Как проверялось (это не дельта — это независимая перепроверка «ничего не изменилось»)

Первый шаг — не поверить заявлению «ребейз ничего не тронул», а доказать его:

```
git diff 768e1281 e38beed7 --stat   # r1-материал vs текущий фикс-коммит
```

Результат: единственная разница — файл `docs/reviews/SPEC-REVIEW-502-r1.md` (несвязанный коммит `dev` для
issue #502). Все файлы продукта — `src/hp-dialog.ts`, `src/summary-panel-editor.ts`,
`test/hp-dialog-contract.test.mjs`, `docs/ARCHITECTURE.md`, оба CHANGELOG, `scripts/mutation-gate.mjs`,
`demo/smoke_summary_dialog_scroll.mjs`, весь пересобранный бандл — побайтово идентичны материалу r1.
`docs/images/screenshots.json` проверен построчно (`grep imageSha256` на диффе): изменились только
`sourceFingerprint`/`sourceSha256`-контекст, ни один `imageSha256` не сдвинулся.

Это и определило объём: код доказанно тот же, что уже получил зелёный вердикт с личными прогонами гейтов,
мутантов и смоков (не только заявлением автора — заявление в r1 тоже было перепроверено исполнением). Все
выводы AC1–AC6 из r1 остаются в силе автоматически, потому что применяются к тому же байт-в-байт коду. Тем
не менее раунд объявлен «полным» (ребейз, §7.2), поэтому ниже — не просто ссылка на r1, а собственный
прогон части гейтов на текущем SHA `6ac513ca`, чтобы исключить эффекты самого ребейза (окружение сборки,
конфликт слияния бандла и т. п.), а не только идентичность текста диффа.
