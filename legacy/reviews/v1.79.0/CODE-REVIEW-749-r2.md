## Почему это r2, а не повторная работа над находками

r1 (`docs/reviews/CODE-REVIEW-749-r1.md`, SHA `9bf35aec…`) вынес **зелёный**
вердикт, High/Medium/Low — 0/0/0. Цикл не образовался (зелёный вердикт его не
открывает, §4). Публикация, однако, не прошла: токен конвейера `HP_PROCESS_TOKEN`
не имеет права `workflow` и GitHub отклонил пуш правки `.github/workflows/_process.yml`
(`remote rejected ... refusing to allow a Personal Access Token to create or
update workflow ... without workflow scope`). Это ровно строка таблицы
AGENTS.md «Handoff и вердикт»: *вердикт был зелёный, слился только конфликт —
ребейз и re-apply*. Задачу вернули в `S6-in-progress` с пометкой «код-ревью
зелёное, переделывать работу не нужно», автор сам сделал
`git fetch && git rebase origin/dev` и запушил свою версию: ребейз
осиротил коммит `9bf35aec`, он стал `a82c482f` на новом основании (`dev`
`14ea2661`), конфликт был только в генерируемом `docs/reviews/INDEX.md`.

Старый SHA `9bf35aec` и записанное в r1 дерево `3075c1fc6dae…` в этом
репозитории не резолвятся (`git cat-file -t` — ошибка) — ожидаемо после
ребейза и явно разрешено разделом «Повторный раунд»: нерезолвящийся SHA — не
находка, когда материал ищется по дереву и блобу. Дерево ищется сравнением
диффов, см. ниже.
