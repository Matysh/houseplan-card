## Находки

### Low — аудит в теле issue ошибочно числит живой селектор мёртвым

`.zoomwrap.slide-left` / `.zoomwrap.slide-right` и keyframes `hp-slide-left` /
`hp-slide-right` перечислены в разделе «Что показал аудит» под фразой «но
часть мертва» с адресом `plan.styles.ts:632–633`. Проверка кодом это не
подтверждает:

- `src/houseplan-card.ts:11077` — `class="zoomwrap ${this._slide ? 'slide-' +
  this._slide : ''}"`, т.е. класс собирается интерполяцией;
- `src/houseplan-card.ts:1085` — `private _slide: '' | 'left' | 'right' = ''`
  — конечное множество из двух значений, не «пусто»;
- keyframes `hp-slide-left`/`hp-slide-right` определены в
  `src/styles/base.styles.ts:275,279`, не в `plan.styles.ts:632–633`.

Это не находка к канону ТЗ: фраза «мертва» живёт в фоновом разделе «Что
показал аудит» (до заголовка `## ТЗ`, вне канона по §2.3), а сам Контракт
поведения п.3 уже требует по каждому из этих же шести кандидатов «если
потребитель реально существует — сохранить и объяснить», и п.4 отдельно
требует учитывать составные селекторы/интерполяции при построении allowlist —
то есть методология АС2 самокорректируется и не даст удалить это правило. Цикл
не открываю, в текущем issue ничего не возвращаю; фиксирую, чтобы исполнитель
не перенёс в таблицу миграции (AC1) ошибочные координаты/вывод «мертво» из
фонового раздела без перепроверки.

Других High/Medium находок нет.
