## Скоуп ревью

Оценивалось ТЗ в разделе `## ТЗ` тела issue #1002: обязательные разделы §7.1,
однозначность и доказуемость AC1–AC7, согласованность с ранее принятым UI Lab
(UI-012–UI-015), с `docs/VACUUM.md`, `docs/USER-GUIDE.ru.md` (раздел 16,
«Роботы-пылесосы») и `docs/CONFIG-COMPATIBILITY.md`, а также техническая
реализуемость заявленных решений на актуальном `dev`.

Предыстория: механическая преформатная проверка один раз вернула черновик
(отсутствовали заголовки «problem»/«non-scope»/«data-migration» и способ
доказательства AC6); автор поправил структуру без изменения содержания.
Этот возврат не расходует модельный цикл (PROCESS.md §4: формат — не вердикт),
поэтому это действительно первый содержательный заход, r1.

## Находки

Нет. Ни High, ни Medium (в скоупе или вне скоупа) не обнаружено.

Отдельно отмечу (не находка, а то, что намеренно не стало находкой после
проверки): дефолтный цвет `#64B5F6` одинаков для всех ещё не настроенных
пылесосов, то есть два «дефолтных» робота на одном плане будут неразличимы по
цвету трассы. Это не упущение спецификации — различение явно описано как
результат ручной настройки («индивидуальным выбором цвета… для каждого
пылесоса» в «Запросе владельца»), а не автоматический дефолт; раздел «Принято
предположительно» корректно не трогает этот продуктовый выбор, потому что он
уже сделан владельцем в теле issue.

## Что проверено и корректно

- Все обязательные разделы §7.1 присутствуют и подписаны: сценарий и
  «что человек увидит до/после» (раздел 1), проблема и не-скоуп (раздел 1,
  подзаголовок), контракт поведения (раздел 2), UX (раздел 3), модель данных и
  миграция (раздел 5), i18n (раздел 6), AC1–AC7 с доказательством (раздел 7),
  план автотестов (раздел 7, «План команд»), риски (раздел 8), откат (раздел 8),
  release-артефакты (раздел 8).
- Каждый AC называет способ доказательства (`unit`/`backend`/`browser smoke`/
  `golden`) и, где AC защитный (AC3 — backend-валидация), прямо перечисляет
  негативные случаи, которые должны покраснеть («строгий отказ bool/string/
  nonfinite/range/unsafe color»), а не просто ссылается на «тест умеет падать».
- Трек `ask` обоснован по критериям §5 (миграция/compatibility-поля,
  UX-контракт draft/ACK, несколько поверхностей) — `show` эту задачу не прошёл
  бы, что отдельно зафиксировано в оценочном комментарии автора.
- Смешение «сохраняется сразу» (source/live/trail_mode/dock-restart) и
  «сохраняется через Save/Cancel диалога» (новый цвет пути) не новая
  неоднозначность: этот же контраст для того же раздела «Пылесос» уже
  задокументирован в `USER-GUIDE.ru.md` («…сохраняются сразу; отмена остальных
  свойств устройства их не откатывает»), то есть ТЗ продолжает существующий,
  а не изобретает новый паттерн.
- Данные/миграция: поля опциональны, independent defaults, без изменения
  версии модели/Trail Store, без массовой миграции — соответствует принятому в
  проекте шаблону совместимости (`CONFIG-COMPATIBILITY.md`).
- Откат, touch-контракт, perf-бюджет (`O(1)` на робота, без новых per-frame
  циклов/таймеров/observer) и release-классификация `major` с обоснованием
  относительно `v1.82.0` названы явно, а не оставлены как «нет».
- Раздел «Принято предположительно» ограничен действительно техническими,
  невидимыми пользователю решениями (имена внутренних ключей, модуль,
  стабильный ordinal); продуктовые решения (стиль, alpha, Save/Cancel,
  запрет приватных CSS-копий) зафиксированы владельцем в теле issue, а не
  отданы на усмотрение автора. Открытых продуктовых вопросов владельцу нет, и
  это утверждение подтвердилось при разборе — скрытых «вопрос вынесен, но не
  замечен» решений не нашлось.

## Чего не проверял

- **Гейты сборки/тестов** (`npx tsc --noEmit`, `npm test`, `npm run build` +
  сверка бандла) — не прогонял: на этапе `spec` нет продуктового изменения кода
  (`material.changedFiles = []`), эти гейты проверяют диф, которого ещё нет.
  Они обязательны на предстоящем этапе `code` для этой задачи.
- **Приватный эталон** `accepted-v1.82.0-vacuum-ui012-ui015-20261021` и его
  SHA-256 manifest — не проверял: архив локальный, вне репозитория и вне
  доступа ревьюера по собственной политике задачи (личные данные/кадры в
  GitHub не публикуются). Сверка кадров — задача code-review (AC6) по
  синтетическим аналогам, когда они появятся.
- **Реальный browser smoke / golden** — не прогонял: кода и демо-сценариев
  (`demo/smoke_vacuum_style_1002.mjs`, `demo/ui-lab/verify-vacuum-1002.mjs`)
  ещё не существует, прогонять нечего.
- **Точные переводы de/fr** — не проверял содержание (его ещё нет), только
  факт, что namespace `settings` поддерживает эти языки технически.
- **Ручная dev/GPU-приёмка** — не требуется и не выполнялась (решение
  владельца 2026-10-16, #929).
