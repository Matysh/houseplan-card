# Независимое ревью линии v1.83.0

Итог: High 0 · Medium 0 · Low 1

Кандидат: `3db71089b498cbed55e9d867a6710edc16d98a2e` (рабочая копия на нём).
База линии: `v1.82.0` / `eb172115f3b90568d22a8b99dc947dd66cf2b409`.
Вход: `release-review-input/brief.md` + `line-membership.json` — 128 issue линии,
329 изменённых продуктовых файлов (всего 2603 файла в диффе линии).

## Что входило в линию

По `docs/CHANGELOG.ru.md` (запись v1.83.0 и предыдущие beta.1–beta.6) и входному
брифу линия несёт: профили внешних экранов и поворот плана на 90°, до трёх
пороговых тревог устройства («Внимание»/«Тревога»), расширенное контекстное меню
устройства в Просмотре (#1089), просмотр одного прошлого маршрута уборки Dreame
(узкое исключение SCOPE для #999/#1117), межкомнатный проход света через
внутренние окна (#1078/#1079), диагностику Zigbee (скрытые устройства, #1077),
полировку диалогов/форм, копирование пространства с отдельным диалогом имени
(включая поздний фикс #1154 про самозакрытие диалога), ускорения сохранения на
больших домах, миграцию старых форм планов (#1015) и другие fix/refactor без
изменения пользовательского поведения.

Это огромная линия (128 issue, 329 продуктовых файлов). Раздел «Чего не
проверял» ниже честно называет, что осталось вне объёма при разумном бюджете
одного независимого ревью.

## Находки

### Low — исполняемый oracle для `ha-dialog`/`verify_space_copy` недоступен в этом ревью

- **Поверхность:** инструментальный доступ ревьюера (tool policy #1065), не продуктовый код.
- **Воспроизведение:** `run_check` с `check_id`, отличным от объявленных в
  манифесте, недоступен; в манифесте `review-execution-policy.json.checks.md`
  для `demo/verify_ha_dialog_discard_recovery.mjs` и `demo/verify_space_copy.mjs`
  зарегистрирован только `read:base:...` (чтение файла), без исполняемого
  `smoke:`/`unit:` эквивалента.
- **Что видит пользователь:** ничего — это ограничение состава проверок,
  поставленных для этого запуска ревью, а не дефект релиза.
- **Персона:** нет (инфраструктура ревью).
- Не блокирует: поведение диалогов перепроверено равнозначными доступными
  смоками (`smoke_space_copy.mjs`, `smoke_discard_dialog_polish.mjs`,
  `smoke_discard_copy.mjs`, все PASS) и разбором `src/hp-dialog.ts`, который
  напрямую адресует класс гонки, для которого существует пиннутая фикстура.

High и Medium находок нет.

## Что проверено и корректно

- Сборка (`npm run bundle:sync`), типы (`npm run typecheck`) на точном SHA
  кандидата — зелёные, биты неизменны (`materialUnchanged: true` во всех
  вызовах `run_check`).
- 16 целевых browser-смоков (вакуум-история ×4, backup archive, marker alerts
  ×2, pdf export, radar live, wall node delete, zigbee topology ×2, device
  contact/copy, discard dialogs ×2, support diagnostics, external screens,
  kiosk, space copy) — все PASS на кандидате после подготовки `test-build`.
- 4 целевых Node-юнита (wall-node-delete, zigbee-topology-action, radar-model,
  retained-page-action) — все PASS.
- Чтением (не только исполнением) разобраны входы/побочные эффекты/отказы для
  пяти самых рискованных серверных поверхностей линии: просмотр истории уборки
  (гонка config/marker во время чтения провайдера — защищена ревизией и
  fingerprint), пороговые тревоги устройства (чистая валидация, не актуатор —
  не нарушает lock invariant), подписка внешних экранов (аутентификация, не
  право записи — соответствует SCOPE про «Authenticated View»), архив/restore
  (zip-slip, размеры, sha256, explicit confirmation — соответствует правилу
  «никогда не удалять файл пользователя по догадке»), удаление узла стены
  (геометрические инварианты комнаты/проёмов на каждом шаге, явный отказ вместо
  тихого success).
- Разобран конкретный «рискованный соседний случай» для #1154 (self-closing
  space-copy dialog): `hp-dialog.ts` корректно различает «мой» `closed`-event
  от события чужого (родительского) диалога по `event.target`/`_closing`,
  предотвращая закрытие свежеоткрытого диалога поздним событием предыдущего —
  соответствует описанию фикса в changelog.
- PDF/SVG-экспорт не содержит параметра экспорта «все пространства» —
  соответствует узкому read-only исключению SCOPE (один активный Space).
- Радар-бэкенд (`radar.py`, `radar_websocket.py`) не входит в список изменённых
  продуктовых файлов линии — проверка корректно не расширялась за пределы
  диффа; затронутый радар-редактор (`radar-section.ts`, `radar-setup.ts`)
  покрыт `smoke_radar_live.mjs` (PASS).

## Чего не проверял и почему

- **Полнота по всем 128 issue.** Линия содержит 329 изменённых продуктовых
  файлов и 2603 файла в полном диффе — независимое ревью по канону (§11.5)
  судит *поверхности*, а не каждую задачу по отдельности; выбраны самые
  рискованные и самые заметные пользователю поверхности (новые SCOPE-исключения,
  приватность/права, геометрия, последний предрелизный фикс). Остальные ~100
  issue линии (мелкая полировка форм, CI/workflow-инфраструктура, переводы,
  internal-рефакторинг) не разбирались по отдельности.
- **`pytest tests_backend`, включая `test_ha_*.py`.** В доступном фиксированном
  реестре проверок (`review-execution-policy.json.checks.md`) нет
  `pytest`-префикса — только `build:`, `read:base:`, `smoke:`, `unit:`. Это не
  находка (манифест — состав, согласованный заранее для этого запуска), но
  честно отмечаю: backend Python покрыт здесь только целевым чтением кода, не
  отдельным тестовым прогоном поверх кандидата.
- **Golden-сцены (визуальный риск).** Поворот плана на 90° (#1070) и профили
  экранов — визуальные изменения в пути отрисовки; в реестре нет исполняемого
  `golden:`-прогона (только `read:base` на PNG-эталоны), так что фактическое
  сравнение пикселей не выполнялось. Разбор ограничился функциональными
  смоками (`smoke_kiosk.mjs`, `smoke_external_screens.mjs`), которые не
  являются визуальным oracle.
- **Фикстура `ha-dialog` напрямую.** См. находку Low выше — `verify_*`-скрипты
  зарегистрированы только на чтение; прямой запуск не был доступен в этом
  исполнителе.
- **Полный `npm test`/`gate:small`.** Не прогонялся целиком — выбраны адресные
  smoke/unit для конкретно разобранных поверхностей, как предписывает политика
  «пригодную проверку не дублировать, прогонять адресно».
- **Радар-бэкенд, LED-лента, импорт Sweet Home 3D/Easy Floorplan, пороговая
  заливка комнаты, J2 «security glance».** Эти поверхности из SCOPE либо не
  входят в список изменённых продуктовых файлов линии, либо изменились
  незначительно (переводы/рефакторинг без видимого поведения) — не разбирались
  отдельно, чтобы не выходить за периметр диффа линии.
