## Что проверено и корректно

- **M1 закрыт по существу, не только по факту существования теста** — три
  прямые мутации (см. таблицу гейтов) доказывают, что guard действительно
  ловит инлайн-литерал в каждом из трёх названных AC1 потребителей
  (`wall-thickness.ts`, `houseplan-card.ts`, `plan-optimizer.ts`), а не только
  в одном из них.
- **Guard читает исходник, а не собранный бандл** — `sourceOf()`
  (`test/near-axis.test.mjs:20`) делает `readFileSync` из `src/*.ts` напрямую,
  минуя `test-build/`; расхождение между исходником и типизированной сборкой
  тест не маскирует.
- **Регекс на вызов, а не только на импорт** — `assert.match(authoring,
  /snapNearAxisEndpoint\(/)` и `assert.match(optimizer,
  /repairNearAxisRoomWalls\(space\)/)` отдельно требуют реального использования
  импортированного символа, а не только присутствия строки импорта (мёртвый
  импорт не прошёл бы эту часть проверки).
- **Трейлеры и класс изменения** — `01512081` (`test: enforce shared near-axis
  threshold source`) несёт `Issue: #290`, `User-Visible: no`; правильно, это
  чисто тестовый файл (`test/**`, класс B), продуктовое поведение не менялось,
  changelog не требуется.
- **Дерево не расходится с гейтами** — до, во время и после всех мутационных
  проверок `git status --short` оставался чист; финальная пересборка `dist`
  побайтово совпадает с обеими закоммиченными копиями.
- **AC2–AC10, H1-регрессия r1, mutation-gate ×6, golden, инварианты, single
  source of numbers, совместимость, performance** — не пересматривались в этом
  раунде: дельта их не задевает (см. «Разбор по дельте»), полностью
  унаследованы из r3 (раздел ниже), который сам разобрал их читая весь
  `origin/dev...HEAD` (а не по дельте) из-за промежуточного ребейза.
