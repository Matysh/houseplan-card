# House Plan UI Lab

Отдельный локальный инструмент для быстрых итераций интерфейса: настоящая сборка
House Plan, настоящие закреплённые компоненты Home Assistant и синтетические данные
вместо подключённого сервера. Это не новый renderer и не замена существующего `demo/`.
Диалоги и редакторы работают через локальный mock; изменение устройств не вызывает
сервисы настоящего HA.

Инструмент добавлен в рамках #964. Согласованные косметические изменения отдельного
частного стенда относятся к #963: они **не встроены** в этот инструмент и не перенесены
в продукт самим добавлением UI Lab. Частный стенд и его замороженный эталон остаются
отдельными артефактами.

## Быстрый запуск

Для проверки продуктовой полировки #976 после сборки и подготовки HA:

```sh
npm run bundle:sync
node demo/ui-lab/verify-polish.mjs --ha-cache "/path/to/ui-lab-ha-cache"
```

Диагностика запускает отдельный loopback-сервер и настоящий закреплённый HA,
не подключаясь к инсталляции. Проверяет покадровое закрытие/фокус, отказы и
повтор Save/отправки помощи, PDF, инструменты, правила и размеры360/390/1280
в двух темах. Синтетические кадры/отчёт — в `artifacts/ui-polish-976/`;
это не приёмка golden и не изменение сохранённого частного стенда на8890.

Нужны Node.js 22 и зависимости репозитория. Команды выполняются из корня checkout;
они одинаковы для Windows PowerShell, WSL и Linux. Docker и доступ к HA не нужны.

```sh
npm ci
npm run bundle:sync
npm run ui-lab:prepare
npm run ui-lab
```

Открыть **http://localhost:8891/**. Порт отличается от сохранённого частного стенда
на `8890`. Остановить сервер можно `Ctrl+C`.

`ui-lab:prepare` — отдельный, явный сетевой шаг: загружает официальный wheel
`home-assistant-frontend` версии `20260930.4`, проверяет закреплённые размер, SHA-256
и детерминированный индекс файлов/модулей, затем готовит только статический runtime.
Требуется примерно 111 MB на загрузку и дополнительное место для распаковки.
Кэш по умолчанию находится вне репозитория: `~/.cache/houseplan-ui-lab/20260930.4`.
На Windows `~` здесь означает профиль пользователя, а не каталог проекта.

Для уже скачанного официального wheel или своего каталога кэша:

```sh
npm run ui-lab:prepare -- --wheel "/path/to/home_assistant_frontend-20260930.4-py3-none-any.whl" --ha-cache "/path/to/ui-lab-ha-cache"
npm run ui-lab -- --ha-cache "/path/to/ui-lab-ha-cache" --port 8891
```

Обычный запуск ничего не скачивает. Отсутствующий или повреждённый runtime приводит
к понятной ошибке, а не подмене настоящих HA-компонентов упрощёнными заглушками.
Существующий непригодный кэш автоматически не удаляется и не перезаписывается:
для повторной подготовки выберите новый каталог.

После обновления исходников продукта выполните `npm run bundle:sync` и перезапустите
сервер. UI Lab проверяет manifest и хэши файлов сборки. Версия, commit,
fingerprint сборки, версия HA frontend и идентификатор набора данных доступны
в панели **UI LAB**. Изменившуюся во время работы сборку сервер не смешивает со старой.
Обновление закреплённого HA runtime требует изменения `ha-lock.json`, проверки
bootstrap и повторного browser smoke; автоматического перехода на latest нет.

## Как работать

Кнопка **UI LAB** или `Ctrl+Shift+L` открывает служебную панель. В ней есть:

- светлая/тёмная тема и языки `ru`, `en`, `de`, `fr`;
- быстрые переходы к настройкам, устройству, комнате, сводной панели и PDF;
- включение/выключение экспериментальных стилей;
- экспорт, импорт и сброс локальной сессии;
- сведения о реально запущенной сборке.

Обычные кнопки и поля остаются продуктовыми. Поддержанные операции сохранения
меняют локальную сессию браузера; поддержанные команды устройствам меняют только
mock-состояние. Неподдержанные серверные операции сообщают об ограничении стенда,
а не имитируют успешный запрос. Полноценная карточка сущности HA не эмулируется.

Стенд не является доказательством backend-совместимости, безопасности команд
устройствам, производительности продукта или визуальной приёмкой release/golden.
Внешние ссылки, загрузки из HA, камеры и иные сетевые интеграции намеренно недоступны.

## Правки стилей без потери открытого диалога

Укажите каталог с четырьмя необязательными файлами:

```text
houseplan-card.css
houseplan-panel.css
hp-dialog.css
ha-dialog.css
```

```sh
npm run ui-lab -- --overrides "demo/ui-lab/overrides"
```

В репозитории эти файлы пустые, с комментариями. Изменения перечитываются примерно
раз в 1,2 секунды и внедряются в соответствующие shadow roots. Открытый диалог,
выделение и несохранённый ввод не должны теряться. Переключатель стилей позволяет
сравнить результат с продуктом. Без `--overrides` дополнительные стили не подключаются.

Для личных экспериментов лучше использовать внешний каталог или игнорируемый
`demo/ui-lab/private/overrides/`. Изменения разметки/поведения требуют отдельной
локальной работы с исходниками и пересборки; CSS-инструмент не обещает заменить
разработку. Не создавайте внутри UI Lab вторую копию продуктовых компонентов.

## Частный набор данных и оформление

По умолчанию используется только синтетический `fixture.json`. Частный снимок
подключается **явно**, без обращения к живому HA:

```sh
npm run ui-lab -- --fixture "/private/lab/fixture.json" --assets "/private/lab/assets" --theme "/private/lab/theme.css" --overrides "/private/lab/overrides"
```

`--fixture` ожидает формат fixture стенда, а не произвольный продуктовый backup:
объекты `config`, `layout`, `states`, `devices`, `entities`, `areas`; дополнительные
`hostConfig`, `floors`, `assets`, `integrations`, `manifests`, `zigbee` допустимы.
Структуру показывает синтетический пример. Сам по себе экспорт плана не содержит
всех HA-реестров и состояний; нового экспортёра из HA этот инструмент не добавляет.

`--assets` обслуживает только локальные content-addressed изображения по маршруту
`/api/houseplan/content/assets/_/<sha256>.(png|jpg|webp|svg)`. Ссылки и записи реестра
assets в fixture должны соответствовать этим локальным файлам. Нет прокси для
докачивания картинок с исходной установки. `--theme` добавляет локальный CSS после
базовой темы; для его изменения обновите страницу. Hot reload относится к четырём
файлам `--overrides`.

**Не коммитьте частный план, HA-реестры, состояния, изображения или сессии.** Для
них предназначены внешние каталоги. Внутри инструмента дополнительно игнорируются
`private`, `.cache`, `exports`, `evidence`. Сервер не публикует абсолютные пути
к частным входным файлам в HTTP-ответах или provenance.

## Локальные сессии

Правки хранятся в `localStorage` отдельно для идентичности исходного набора данных
и fingerprint сборки. Другая fixture или другая сборка не перезаписывает старую
сессию. Перемещение частной fixture в другой путь также создаёт другую идентичность.
Исходный JSON и изображения сервер не изменяет.

Экспорт сохраняет JSON-конверт UI Lab с конфигом, расположением, mock-состояниями
и состояниями виртуального света. Это **не полный backup House Plan**: он не
упаковывает изображения, CSS и HA runtime, не переносит текущий стек Undo/Redo
или несохранённый ввод в открытом диалоге. Держите частный исходный набор отдельно.

Импорт проверяет формат, структуру, лимит 8 MiB, набор данных и сборку, затем
запрашивает подтверждение замены. Чужой, повреждённый или неподдерживаемый файл
не затирает текущую сессию. Импорт между разными сборками намеренно не мигрирует
данные автоматически. Сброс также требует подтверждения и касается только текущей
сессии. Прочие сессии и данные настоящего HA не затрагиваются.

## Изоляция

- Сервер слушает только `127.0.0.1`, проверяет Host и принимает только GET/HEAD.
- Доступны только явные статические маршруты; обход каталогов и выход через
  symlink/junction запрещены. Нет endpoint для серверной записи или HA proxy.
- CSP и ранний browser guard блокируют внешние ресурсы/запросы, реальные
  WebSocket, EventSource, beacon и регистрацию service worker. Bootstrap загружает
  настоящие HA-компоненты, но не запускает HA auth/app/core.
- Публичный инструмент не содержит адреса установки владельца, учётных данных
  или частного плана. Локальный пользователь компьютера всё равно может открыть
  явно подключённую fixture через локальный сервер: это не многопользовательский хостинг.

## Проверки

```sh
node --test test/ui-lab-server.test.mjs test/ui-lab-session.test.mjs
npm run ui-lab:smoke
```

Для собственного кэша smoke принимает `--ha-cache`:

```sh
npm run ui-lab:smoke -- --ha-cache "/path/to/ui-lab-ha-cache"
```

Browser smoke использует свежий профиль, временный порт и синтетические данные:
настоящий HA-диалог, тему/язык, сохранение и локальное переключение, CSS в открытой
форме, экспорт/импорт/сброс, отсутствие неожиданных ошибок и внешних запросов.
Нужен Chromium для установленной версии Playwright (`npx playwright install chromium`).
Node-тесты проверяют локальные маршруты, отрицательные сценарии runtime/fixture,
изоляцию путей и безопасную работу с сессиями. Общие гейты проекта остаются обязательными.
