# Уроки разработки

Короткие выводы из прошлых задач. Это справочный материал по затронутой области, а не обязательный этап входа в задачу.
Правила работы и выбор проверок задаёт только [PROCESS.md](../PROCESS.md); старые отчёты сохраняют результаты своего времени.

| Урок | Источник |
|---|---|
| Одно число, видимое пользователю дважды (превью/факт, подпись/запись), должно иметь один источник. | #233/#234, тест `single-source-numbers` |
| Число тестов и фактическое покрытие берутся из выбранного плана и завершённого отчёта; исторический счётчик не описывает текущий набор. | #472, #1105 |
| Ненулевой exit мутации не означает, что тест поймал дефект: setup failure, invalid mutation и survived различаются. Мутации выполняются отдельно в фоне. | #558, #568, #1105 |
| Необъяснённое отличие скриншота сначала разбирают; эталон принимается явно после просмотра. Исполнитель делает нужные проверки до ревью, ревьюер читает результаты. | #598, #697, #1105 |
| Стенд и реальный Home Assistant имеют разные ветки диалогов; синтетический golden не доказывает работу ha-dialog. | #505, #607, #609 |
| Контролируемое поле без live() может показывать значение, отличное от состояния. Клампить на коммите, а не на каждом символе. | #608 |
| Лог без подтверждённого завершения — неполный результат. Отсутствие FAIL само по себе не является PASS. | #604 |
| Проверка обвязки должна воспроизводить поведение механизма; сравнение текста YAML и регулярных выражений не заменяет такого примера. | #595/#596, #1105 |
| При изменении общего контрола учитывать связанные сценарии его потребителей; выбрать их адресно на S6. | #639, #1105 |
| Повтор доставки события не должен порождать повторный платный вызов модели. У неуспешной попытки должны быть предел и понятный путь продолжения. | #636, #1105 |
