# Передача исполнителю

Визуальный прототип: runtime/app.mjs::installWeather1174 и раздел #1174 в overrides/houseplan-card.css. Включение/источник — draft с применением по Сохранить; Отмена оставляет сохранённое состояние.

Точки интеграции продукта: src/summary-panel-runtime-loaded.ts, src/summary-panel-editor.ts, src/summary-panel.ts, общие reading-kit/form-kit/select компоненты и локализации. Добавить типизированные настройки, сохранение и согласованность штатным механизмом конфигурации. Не переносить подмену приватных методов, манипуляции Lit TemplateResult, CSS polling или лабораторный localStorage.

Виджет использует общую поверхность hpf-reading-block, заголовок hpf-heading-section, строки hpf-reading-pair, разделитель hpf-divider-before, checkbox hpf-check и hp-settings-select. Общие визуальные правила реализовывать в UI Kit; погодному компоненту оставить только специфичную композицию. Hover у содержимого с прямыми верхними углами и сохранёнными нижними.

Wind bearing: демонстрация использует 225° → «юго-западный», 270° → «западный», округление к восьми румбам. Продукт берёт wind_bearing из погодной сущности, корректно нормализует валидные числовые углы, локализует направления. Отсутствие значения не означает север и не заполняется нулём. Дополнительную строку ветра не создавать при отсутствии его данных; направление без скорости обрабатывать согласно фактически доступным атрибутам без фиктивных значений.

Демонстрационные значения захардкожены для согласования внешнего вида: источники weather.lab_home/weather.lab_country не являются реальными HA weather-сущностями. Текущая температура, ощущаемая, ветер, влажность и три дня прогноза — синтетические. Продукт должен поддерживать реальные единицы HA, язык, погодные состояния и наборы атрибутов, дневной forecast через штатную подписку. Отдельные данные прогноза не выдумывать при их отсутствии.

Клик в прототипе отправляет hass-more-info; лаборатория отвечает уведомлением, реальный HA диалог здесь не эмулируется. В продукте открывать штатные подробности выбранной сущности. Не делать внешних запросов к погодным API или своей геолокации.

Подписка существует только пока виджет виден; выключение/скрытие/отсоединение освобождает её. При смене источника убрать старую подписку и устаревшие ответы. Погодные обновления не пересчитывают геометрию плана. Проверки реализации и интеграции выполняются исполнителем, визуальное согласование их не заменяет.

Состояния no-source/unavailable/deleted/partial и сценарий погоды без других блоков включены в replay. Основной вид согласован владельцем на частном локальном стенде; пакетные снимки — та же композиция на публичной синтетике. Сохранять видимость панели по её штатным пользовательским настройкам.
