# Измеримость перехода на UI Kit

Инструменты пакета [#1146](https://github.com/Matysh/houseplan-card/issues/1146)
реализуют решения аудита [#1131](https://github.com/Matysh/houseplan-card/issues/1131).
Состав работ и ТЗ пакетов остаются в GitHub Issues. Этот документ описывает
метод измерения, воспроизведение и границы доказательств.

## Реестр и критерий

[ui-kit-inventory.json](ui-kit-inventory.json) содержит 80 поверхностей и 511
ячеек исходного среза `ecada723a7853a553ede68edb05c988ef7a652a7` после стабильной 1.83.0.
Ячейки Просмотра/киоска обновлены в #1147; остальные пакеты сохраняют исходные
якоря и классификацию до своей миграции.
К — примитив/компонент кита без локальной краски; Л — кит с локальной краской;
П — миграция; Н — сцена или нативная поверхность вне задачи. В JSON это K/L/M/N.
Совпадение внешнего вида с китом само по себе не означает К. Раскладка без
своей краски допустима. Краска включает размеры контролов, отступы внутри них,
шрифт, рамки, состояния, фон, тень, движение и inline-оформление.

Основа — два опубликованных JSON-комментария #1131 на `72c63464a` (80/513).
В provenance перечислены изменения при сверке всех 28 изменённых файлов src:
удалены две ячейки кнопок сводки в киоске; чекбоксы PDF теперь Л; неопределённый
цвет PDF — П (собственный shadow CSS); предупреждение лестницы после #1145 — К.
Контролы основной шапки после #1132 имеют 44 px, но их локальная краска остаётся П.
Старые оценки `historicalLocalCssBlocks` явно привязаны к исходному аудиту.
Ссылки доказательств в ячейках относительны к src/, номера строк обновлены.

У 57 поверхностей есть существующий кадр (сцена использует кадр geometry View),
у остальных 23 — именованный `captureScenario` и команда в `capturePlans`.
Гейт проверяет существование кадров и точек входа сценариев. При миграции
меняются ячейки и доказательства вместе с кодом, без механического перевода П в Н.

## Подсчёт и релизный храповик

```sh
node scripts/ui-kit-metrics.mjs --json=artifacts/ui-kit-census.json
node scripts/ui-kit-metrics.mjs --check
node scripts/ratchets.mjs report
```

Счётчик читает src/**/*.ts, исключая d.ts. TypeScript AST выделяет литералы,
вложенные шаблоны и строки без исполнения кода. Выражения заменяются маркером
с сохранением физических переносов строк. CSS берётся из css-шаблонов,
CSS-похожих фрагментов, модулей стилей и style внутри html/svg. Уникальные
непустые физические строки считаются один раз на файл. CSS-комментарии и
содержимое строк не создают keyframes, transition или правила .btn.

`inlineDecorativeStyles` сохраняет узкий лексический контракт аудита: статические
атрибуты style с декларациями вне списка геометрии и custom properties. Сюда
попадают и сценовые SVG. Это не полный анализ styleMap или динамических стилей;
смысл поверхности определяет реестр. Дополнительные диагностические числа
деклараций/элементов не являются отдельными гейтами.

| Метрика | База v1 | Полоса роста |
|---|---:|---:|
| cssLines | 7820 | 20 |
| keyframes | 19 | 0 |
| transitions (CSS + строковые фрагменты) | 111 | 0 |
| inlineDecorativeStyles | 27 | 0 |
| hpDialogWithoutKit | 29 | 0 |
| btnRulesOutsideKit | 41 | 0 |
| registryOffKit (Л + П) | 372 | 0 |

База — [scripts/ui-kit-baseline.json](../../scripts/ui-kit-baseline.json).
Проверка входит в обязательный локальный gate:small и свежую фазу frontend CI,
а входы зарегистрированы в check-inputs. Отсутствующая база, неизвестная корзина,
потерянный кадр/сценарий или превышение полосы дают красный результат.
Снижение разрешено. На кандидате релиза общая команда
`node scripts/ratchets.mjs tighten` фиксирует факт вместе с остальными потолками.
В обычной задаче базу ради снижения не переписывают.

**Смена метода не является изменением продукта.** Старый скрипт на том же ecada
даёт 7695 строк, новый — 7820: старый терял переносы внутри интерполяций и
склеивал номера физических строк. На старом аудите было 7635 строк. В отчёте
сохранены обе сопоставимые серии. Также 29 вместо старых 27 диалогов без кита:
два условных выражения в decor-image-editor и hp-confirm могли давать ui-dialog
лишь в отдельных ветках; теперь считается безусловный настоящий токен класса.
Это не регрессия CSS и не добавление диалогов. Сравнение последующих пакетов
ведётся одним методом v1, без пересчёта выигрыша по старым приблизительным числам.

## Покрытие CSS и размеры

```sh
npm run build
node scripts/bundle-sync.mjs
node demo/ui-lab/ui-kit-audit.mjs
# При необходимости: --ha-cache /path/to/pinned/cache --output /path/to/output
# Один профиль для диагностики: --theme=light --width=1280
```

Нужен штатный закреплённый runtime UI Lab (см. его README). Скрипт запускает
и закрывает собственный loopback-сервер, запрещает внешний трафик и проверяет
свежесть настоящей сборки. Две темы × 1280/1024/390 px, 27 состояний на профиль:
шапка/tooltip, разделы настроек, сводная и выбор источника, пространство,
предупреждение большого плана, копирование, PDF, помощь, три панели редакторов,
каталог, правила и лотки. Параметры сценариев и результат — в
[ui-kit-audit-1146.json](ui-kit-audit-1146.json).

CDP CSS.startRuleUsageTracking и takeCoverageDelta собирают диапазоны на каждом
шаге; объединение — по SHA-256 текста stylesheet. Полные CSS/стэки/PNG остаются
в artifacts/ui-kit-audit, в Git — компактный отчёт с 162 состояниями, кандидатами
и хэшем полного исходного отчёта. Стиль, который парсер не поддерживает, никогда
не объявляется неиспользованным. Совпадение селектора не доказывает, что каждая
его декларация выигрывает каскад. Отсутствие совпадений не доказывает мёртвость
динамического/непокрытого состояния. Это кандидаты, не разрешение удалить CSS.

Результат для пунктов 6/11 таблицы 4.1 аудита:

- Селекторы кнопок сводной используются. Стэки CDP и вычисленная краска показывают
  совместное участие локальных и более специфичных правил кита. До замены и
  проверки состояний удалять весь диапазон нельзя.
- Старые .decorbar .bdhint/.dfill и .editbar input/.drawwall не встретились в
  матрице; проверить их динамических потребителей перед удалением. Раскладка
  .editbar .wallsgroup используется — весь старый диапазон не является мёртвым.

Во всех шести профилях реальная высота обычной кнопки инструментов — 31.0625 px
(font-size 13 px, normal line-height, padding 6px 10px, border 1px); Undo/Redo —
29.0625 px без рамки; крестик панели — 40 px. Кнопка выхода в основной шапке —
44 px. Компактный вариант пакета #1150 должен сохранить эту компоновку, а не
превращать дробную высоту конкретного Chromium в универсальную константу.
Поля свойств 36 px/radius 5 согласованы отдельно в #931/#1131.

## Редкие поверхности

Команды каждого случая находятся в capturePlans реестра. Для смоков съёмка
явно включается переменными окружения; обычный запуск не снимает новые кадры:

```sh
HP_UI_KIT_CAPTURE_DIR=artifacts/ui-kit-capture node demo/smoke_tap_run.mjs
node demo/capture_ui_kit_transients.mjs
```

В PowerShell переменная задаётся отдельно:
`$env:HP_UI_KIT_CAPTURE_DIR='artifacts/ui-kit-capture'`.
Необязательный HP_UI_KIT_CAPTURE_SURFACES ограничивает запись перечисленными
через запятую id. Каждый checkpoint ждёт видимую настоящую поверхность,
снимает PNG и JSON с размером viewport, вычисленной краской и версией браузера.
После съёмки поверхность ещё должна быть видима. Смоки и их обычные проверки
продолжаются. В исходной проверке все 14 задействованных смоков прошли.

Редкие кадры на offline smoke-оснастке не подменяют проверку с настоящим HA.
У recovery есть один объявленный private-ok fixture: свежий экземпляр настоящего
контроллера вместо уже завершённого кадра, затем штатные HA-события disconnect/
ready. Это сравнение CSS/отрисовки, **не доказательство достижимости или recovery**.
Холодный boot снимается до смены темы; его JSON фиксирует фактическую краску,
а не заявляет отдельную приёмку обеих тем. Общая матрица CSS/размеров выше
использует настоящий пиновый HA и обе темы.

В срезе #1146 обнаружен пробел: нативная загрузка большого PNG на пустом плане
создаёт состояние предупреждения, но ветка онбординга не монтирует его диалог.
Сценарий сохраняет PNG/JSON со статусом missing-before-1147, явно не выдавая его
за кадр предупреждения или успешную приёмку. Исправление и красный/зелёный
регрессионный свидетель входят в ТЗ #1147. После исправления тот же сценарий
должен снимать настоящий guard и проверять возврат в онбординг по отмене.

У группы View/kiosk сохранены 23 поверхности и 100 ячеек: 94 К и прежние 6 Н;
Л/П нет. В остальных пакетах корзины не менялись. Дополнительная проверка

Оформлением владеют общие icon-action/navigation/notice/reading primitives,

UI Lab снимает готовый View после ухода настоящего bootveil. Общая матрица —

снятый после завершения boot, за загрузку. В редкой matrix исправлена оснастка:
хост больше не остаётся 780 px при viewport 390. Проверяются фактическая ширина
и центрирование 56px glyph. Первоначальная тема boot фиксируется по реальной
краске до выбора темы.

Opt-in checkpoints существующих смоков теперь действительно подключают CDP
до навигации и сохраняют stylesheet SHA-256/диапазоны. Перед кадром ожидается
реальное конечное движение во вложенных shadow roots, включая HA; бесконечные
пульсации продолжаются. Новые PNG10000 — валидные browser-encoded файлы,
а не только заголовок с размерами. В текущем сценарии отсутствие guard — ошибка.
Регрессия первого пространства имеет красный свидетель на старом коде и зелёный
на новом: Cancel/Escape/крестик/повтор сохраняют черновик без upload/записей
config/layout и без загрузки полного редактора.

Итоговая проверка включает 24 профильных smoke, HA/native modal lifecycle и
движение, 11 проверок настоящего пинового HA icon picker, 35 selected golden,
162 состояния UI Lab и 30 transient/CDP кадров. После исправления порядка загрузки
32 из 35 canonical-кадров совпадают с ранее просмотренным пакетом; три карточки
device-alert-reasons/device-issues повторно просмотрены целиком и в сравнении
before/after/diff: общий callout, отступ20px и footer без обрезки сохранены.
В каждой из шести UI Lab-пар реально наблюдались show/hide в родном wa-dialog;
их внешний словарь ограничен конкретным файлом и SHA/version официального HA.

Перенесены 16 определений mutation-тестов к фактическим владельцам правил.
Для click/Escape меню нужен mounted browser smoke, а не чистая композиция
headerMenuItems. Проверена только статическая готовность: execution=0,
caught=unknown; мутанты при разработке не запускались.

Разрешённое владельцем увеличение ресурсных лимитов записано отдельно от
семи UI Kit-храповиков: rolling View учитывает стоимость общего кита, общий
raw bundle растёт 3722439→3724923 B. Select-only граф после разделения общего
меню имеет 21463 B gzip; его предел получает обычный запас +10% (21462→23609),
без упаковки кода ради одного байта. Ленивые границы и временные бюджеты
сохраняются; эти изменения лимитов не объявляются ускорением.

Широкий CI c2b90b4 дал красный свидетель зависимости карточки устройства от
порядка загрузки: класс полной формы настроек менял body padding20→0 после
открытия редактора. Read-only body теперь использует обычную `.hpf-form`;
smoke_approved_ui подтверждает20px в обоих порядках. Native modal geometry
ждёт настоящее конечное движение; recovery проверяет inert до140ms выхода
и затем настоящий detach. Shared menu учитывается отдельно от editor-only
листов, с сохранением проверки единственного owning sheet и его cascade slot.
Discard проверяет индивидуальный translate−10→0 и общий вход предупреждений.

Строгие кадры geometry-view light/dark и panel kiosk wide/fixed имеют нулевую
разницу с эталонами. Бейдж масштаба сохраняет прежний native `hidden`: виден после
увеличения и скрыт при fit; общий display не может обойти это состояние.
Остальные видимые изменения описаны отдельными scene intents в release-ledger;
глобальные эталоны и frontend-снимок обычная ветка задачи не меняет.
