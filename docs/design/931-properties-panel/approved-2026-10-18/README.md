# Approved properties panel references — #931

Issue: [Matysh/houseplan-card#931](https://github.com/Matysh/houseplan-card/issues/931).

## Provenance and authority

These static design references were agreed with the owner in the Codex design
discussion on 18 October 2026. They preserve the final `static-panels-v5` visual
design, with the owner's last accepted correction: **all four coordinates of
contour-wall endpoints are read-only in the first version**. The contour hint is
«Положение концов меняется перемещением узлов на плане.»; the previous arrow
suggesting constrained coordinate editing was removed. Thickness remains editable.
The final device hint retains justified alignment across the available width.

The canonical implementation specification is the `## ТЗ` section of the issue
body. This directory is its versioned visual reference, not a second specification
or product implementation. The reference renderer is a static demonstrator with a
synthetic plan and synthetic object values; it contains no Home Assistant access.
The surrounding plan and application shell provide spatial context. The agreement
covers the properties panel, its object selection cues, and the variable dialog;
the fixture is not a request to replace unrelated editor navigation or plan data.

Treat this dated directory as immutable after acceptance. A later approved visual
revision belongs in a new dated/versioned directory. `MANIFEST-SHA256.txt` binds all
files except the manifest itself. Issue links should pin this directory to its
publication commit SHA, rather than a moving branch.

## Reproduction

Sources: `screen.html`, `screen.js`, `scene.svg`, `render.cjs`.
The script uses `require('playwright')`, with no machine-specific dependency path.
Run from the repository with its existing Playwright installation available:

```powershell
$env:NODE_PATH = (Resolve-Path node_modules).Path
node docs/design/931-properties-panel/approved-2026-10-18/render.cjs
```

Captured on Windows with Segoe UI, Playwright 1.62.0 and its installed Chromium.
All assets are local. Reproduction on another OS or font installation can change
font rasterization; it must not silently replace these accepted reference pixels.
The script renders the nine screens/crops, three comparison boards and variable
dialog views, reports panel geometry and overflow, and fails on browser errors.

## Visual acceptance evidence

Implementation review must compare actual product screenshots to these references
with the same viewport, DPR, language, theme, values and selected-object type.
Provide paired full-screen and panel/dialog crops, and a list of any differences
with their resolution. Check panel placement, field/group order, wording,
spacing, type and colour hierarchy, editable/read-only/disabled states, controls,
actions and selection correspondence. A generic passing golden suite alone is not
evidence that the implementation matches these agreed mockups.

Do not reinterpret the synthetic home furniture or placeholder navigation as an
additional product redesign. Behavioural states not drawn here remain governed by
the canonical issue specification and its acceptance criteria.
