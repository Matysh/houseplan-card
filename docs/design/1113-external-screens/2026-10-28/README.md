# #1113 — согласованный визуал внешних экранов

28.10.2026, UI-002, итоговая ревизия 3. Владелец согласовал результат:
«фиксируй все изменения для задачи 1113. запиши их в задачу и приложи необходимые файлы в репозиторий».

## Итоговый интерфейс

- **Общие настройки → Внешние экраны**, перед разделом обслуживания.
- Пустой список: «Внешних экранов пока нет» и единственная кнопка **Создать**.
- Непустой список: строки **Экран N**, краткое описание, редактирование по нажатию на строку, удаление; единственная кнопка **Добавить** под списком. Дополнительного плюса в заголовке нет.
- В строке показывается относительный путь `/houseplan?hpprofile=N`. Кнопка копирования кладёт **полный абсолютный URL установки**, с протоколом, доменом и портом при его наличии. Пример: `https://ha.example.org/houseplan?hpprofile=1`. В прототипе это `new URL(path, location.origin).href`. Не фиксировать localhost в продукте.
- Конструктор **Новый экран / Экран N** — отдельный `hp-dialog` поверх общих настроек. Внутренней дополнительной карточки/рамки со скруглениями вокруг полей нет. Внешняя оболочка диалога сохраняет штатное оформление.
- Общий UI Kit: `hp-dialog`, `hp-settings-select`, `hp-help`, form-kit; штатные ховеры, фокус, выпадающие меню, затемнение, появление и закрытие. Системное уменьшение движения сохраняется.
- Две колонки полей на desktop; отступы тела 20 px, промежутки 20/24 px. Узкий экран — одна колонка.
- Во всех соответствующих списках формулировка **«Как на основном плане»** вместо «Как выбрано на экране».
- Под полями стандартная информационная подсказка `hpf-note`, отступ сверху 24 px: **«Изменения применятся после нажатия „Сохранить“ в общих настройках.»**
- **ОК** переносит профиль в черновик общих настроек; **Отмена** закрывает конструктор без применения. Внешнее **Сохранить** применяет черновик и закрывает общие настройки **с общей анимацией UI Kit**. При ошибке сохранения форма остаётся открытой.

## Поля конструктора

| Поле | Значения |
|---|---|
| Пространства | Все пространства / одно из доступных пространств |
| Поворот | 0°, 90°, 180°, 270° |
| Автолистание | Выключено, 10 с, 30 с, 1, 2, 5, 10 мин |
| Возврат к «Вписать всё» после простоя | Выключено, 30 с, 1, 2, 5, 10 мин |
| Сводная панель | Как на основном плане / Показывать / Скрывать |
| Скрытые устройства | Как на основном плане / Показывать / Не показывать |
| Размер значков | Как на основном плане / 50, 75, 100, 125, 150, 175, 200, 250, 300 % |
| Размер текста | те же значения |
| Кнопки поверх плана | Показывать / Скрывать |

Автолистание недоступно при выборе одного пространства. Возврат после простоя недоступен при включённом автолистании; подсказка объясняет его собственное правило 60 секунд. Номера не переиспользуются; предел — 20 профилей.

## Границы согласования

Это визуальный ориентир и локальный прототип, не продуктовая реализация и не функциональная приёмка. `prototype.mjs` — DOM-адаптер для демонстрации; переносить его буквально в продукт нельзя. Backend, capability/future-version handling, URL resolver, реальный киоск и WebSocket остаются предметом ТЗ #1113. Ошибки, отсутствующие пространства, сохранённые значения вне списков требуют полной реализации по ТЗ, даже если прототип их не воспроизводит.

Замена текста «Как на основном плане» согласована как UI-формулировка. Она сама по себе не меняет техническую семантику `local`, приоритет URL → профиль → локальный выбор → умолчания или правила ключей из ТЗ r1.

Анимация сохранения в прототипе: обычный `_saveSettingsDialog` помечает успешный выход как немедленный через `acceptSavedDialogExit`. Адаптер сохраняет с `keepOpen:true`, затем закрывает через штатный `dialogPresence`; ошибка и явные вызовы keepOpen оставляют форму. В продукте интегрировать это в общий жизненный цикл диалогов, без обхода защиты сессии/прав и без двойного сохранения.

Тесты, сборка и CI в визуальной итерации не запускались. Кадры сняты с синтетическим fixture; личный бекап, план, имена устройств и браузерная сессия не публикуются. Изменения вращения UI-001 относятся к отдельной согласованной правке и в этот пакет не входят.

## Файлы и воспроизведение на другом ПК

- `prototype.mjs` — итоговая ревизия; единственное обезличивание исходника — отдельный ключ локального хранилища.
- `replay.mjs` — запуск на синтетических данных без изменения рабочего checkout.
- `screenshots/01-empty.png`, `02-constructor.png`, `03-list.png`, `04-constructor-note.png` — итоговые состояния (конструктор показан сверху и после прокрутки к подсказке).
- `provenance.json` — согласование, базовый commit и хэши файлов.

Нужны Git, Node.js 22 и отдельный checkout **v1.83.0-beta.3**, commit `09bda8dbee8b50577bfc4affc332b8cda914f5b4`. Пакет можно скачать/checkout отдельно от этой базы.

```sh
git clone https://github.com/Matysh/houseplan-card.git houseplan-ui-base
cd houseplan-ui-base
git checkout --detach 09bda8dbee8b50577bfc4affc332b8cda914f5b4
npm ci
npm run bundle:sync
npm run ui-lab:prepare
node /path/to/this/package/replay.mjs --repo . --port 8892
```

Открыть `http://127.0.0.1:8892/`, Общие настройки → Внешние экраны. При необходимости выбрать русский язык и тёмную тему в панели UI LAB. `--ha-cache PATH` позволяет использовать уже подготовленный runtime. Скрипт берёт чистые app.mjs и синтетический fixture из закреплённого Git commit, создаёт временную копию UI Lab и добавляет только этот прототип. Существующий частный стенд не затрагивается. Остановка — Ctrl+C.

Для просмотра: Создать → ОК → Сохранить; снова открыть раздел и нажать Экран 1. Анимацию внешнего Сохранить смотреть в живом replay — статичный PNG её не подтверждает.
