# Перенос в продукт

- Конструктор в runtime/app.mjs: installProfile1165. Он оборачивает существующий externalScreens controller/dialogPresence, использует hp-settings-select и hp-help. lab_space_views — исключительно локальная схема прототипа, не решение по storage migration.
- Компоновка формы — начало overrides/houseplan-card.css. Полная форма всегда сохраняет согласованную сетку общих настроек; редактируемое пространство занимает всю ширину своего блока.
- Общие cursor/user-select переносить в form-kit.styles.ts, примитивы заголовков и hp-dialog.ts. Не размножать правила по страницам; disabled checkbox — одна общая строка с одинаковым курсором у галочки и текста.
- Footer separator — общий hp-dialog shell, один токен цвета/толщины с header. В прототипе наличие light-DOM footer передаёт CSS-токен внутрь shadow; не полагаться на :host(:has(...)), который не сработал в локальной оболочке.
- Т-образные стыки: settings-dialogs.styles.ts и shell должны заполнять действительную высоту между header/footer. В прототипе flex через hp-dialog.css/ha-dialog.css и общий hpf-settings-form; это адаптер настоящего HA DOM. В продукте выбрать поддерживаемый механизм общей оболочки (в том числе flex-content), не фиксированную прибавку 5px и не приватные HA-селекторы в каждой форме. Сохранить единственный скроллер, компактные окна и мобильное меню разделов.
- Общие изменения применяются к панели и карточке, HA и fallback, всем соответствующим диалогам, а не только конструктору профиля.
- Не переносить hot CSS polling, MutationObserver, monkeypatch private runtime и lab-specific preview flags в продукт. Они нужны только для быстрого согласования без сборки.
- Функциональная реализация: resolver, миграция старых профилей/URL, фактическое центрирование, idle return и сохранение — по issue. Тесты/сборка/CI продукта здесь не запускались.
