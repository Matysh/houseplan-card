## Задача

Перенести в продукт все согласованные UI-правки итерации 29–30.10.2026 на базе **v1.83.0-beta.4**, commit `08b154115ff815062cfc0221f39f7e53545dbe45`. Владелец завершил визуальную итерацию и разрешил публикацию всех изменений отдельной задачей.

**Главный критерий приёмки — соответствие результата согласованным UI-прототипам.** Согласование визуала не означает прохождение функциональных проверок продукта.

## Согласованный контракт

| ID | Требование |
| --- | --- |
| UI-001 | Убрать тонкий верхний блик/обводку, имитирующую объём значков устройств. Остальные тени и статусные контуры сохраняются. |
| UI-002 | Восстановить плавный hover кнопок трёх редакторов в единой финальной стилистике UI-003. |
| UI-003 | Пространства и редакторы привести к стилю правых кнопок: высота 44 px, одинаковые фон и обводка. Название пространства и шестерёнка — прилегающие сегменты. Редакторы — такая же группа. |
| UI-004 | После закрытия редактора клавишей Escape на его кнопке не остаётся белая браузерная рамка. Сохранить клавиатурную доступность и осознанную индикацию фокуса. |
| UI-005 | Удалить дополнительный телефонный режим, скрывающий кнопки после переноса в два ряда. Разрешить дальнейший перенос. Примерно при ширине House Plan 355–423 px: пространства в первом ряду, редакторы и два поворота во втором, прочие действия и управление боковой панелью в третьем. Это ориентир иллюстраций, не новый фиксированный порог. На ещё меньших ширинах допустим дальнейший перенос без исчезновения действий. |
| UI-006 | Диалог печати полностью использует общий UI Kit. Крестик получает штатную анимацию наведения; строки переключателей, select, цвет и footer единообразны. Сохранить исходные обработчики, доступность и reduced-motion. |
| UI-007 | Компактная кнопка редактора устройств: `mdi:chip`. |
| UI-008 | Компактная кнопка редактора подложки: `mdi:palette`. Развёрнутые кнопки сохраняют карандаши и подписи «План», «Устройства», «Подложка». |
| UI-009 | Два поворота и три кнопки масштаба — две отдельные визуальные группы с зазором 10 px и скруглением наружных углов. При скрытом масштабе лишнего зазора нет. |
| UI-010 | Полностью убрать визуальное состояние Power Off с полупрозрачной внутренней MDI-иконкой во всех представлениях. Выключенная иконка имеет обычную непрозрачность; Power On сохраняет оранжевый цвет. Недоступность по-прежнему делает полупрозрачным весь значок. Смысловое состояние, tooltip и специальные правила недоступности не отменяются. |
| UI-011 | Из конструктора внешних экранов убрать опцию «Кнопки поверх плана». В киоске эти кнопки скрыты всегда, в том числе у существующих профилей и при старых URL-параметрах. |
| UI-012 | Цифры Zigbee под устройством рисуются поверх названия комнаты и её показаний. Проверить пересечение текстов, а не только значения z-index. Сохранить цвета LQI и правила недоступности. |

## Связь с предыдущими задачами

- #1120: измерение переполнения сохраняется (редакторы без подписей → скрыть масштаб → dropdown пространств → перенос); UI-005 заменяет дополнительное скрытие кнопок в телефонном режиме. Не возвращать фиксированные пороги из #1119. Порог 1024 px панели свойств редакторов не меняется.
- #1119 / #1026: UI-010 **заменяет** прежнее требование о полупрозрачной иконке Power Off.
- #1113: UI-011 — новое согласованное упрощение конструктора внешних экранов; остальные требования сохраняются.

## Приёмка

- [ ] Все UI-001–UI-012 совпадают с живым replay и приложенными визуальными материалами при одинаковой теме, языке, ширине контейнера и данных.
- [ ] Проверены сужение и расширение панели, раскрытые и компактные редакторы, узкие вертикальные экраны без скрытия оставшихся действий.
- [ ] Печать и выход из редакторов сохраняют штатные действия, hover, фокус, отмену и анимации.
- [ ] Power Off не затемняет только глиф ни на плане, ни в редакторах/превью/карточках пространств; Power On и недоступность сохраняются.
- [ ] Кнопки поверх плана отсутствуют в киоске независимо от прежних настроек; конструктора с этой опцией больше нет.
- [ ] Zigbee читается поверх текста комнаты при фактическом пересечении.
- [ ] Реализация использует продуктовые компоненты и UI Kit, без копирования лабораторного polling/DOM-адаптеров/CSS-mask как архитектуры.
