Скачайте нужный HTML кнопкой Download raw file в GitHub и откройте в браузере. Это самостоятельные документы; подключение к Home Assistant не нужно. Внизу сравнения переключатель «Сейчас / После», внутри — навигация по разделам. У черновиков сверху выбор сценария.

«Сейчас» — реконструкция формы по коду, а не screenshot продукта. Данные синтетические, baseline `104a63f1e218eede610dd621a62346ceb3eab2e6`. Состав и текущие операции дополнительно сверялись с кодом; все проектируемые гарантии определяются текстом issue, а не демонстрационным обработчиком кнопки.

## Согласованность и ограничения

- **Общие v7**: финальная визуальная версия v6 плюс отсечение внешнего оконного луча откосом. В обеих схемах одинаковые окно, толщина стены и направление света. 47 общих записей до/после; намеренно исключены сброс стен/севера и две настройки удаляемого затемнения (#943).
- **Три остальных диалога v2**: предварительные макеты после переноса общей полировки. 6 основных + 6 дочерних сценариев, 329 записей полей/статусов/действий на одинаковых данных. Не считать их содержательную компоновку окончательно согласованной.
- Изменения в примерах локальны. Кнопки не запускают реальное сканирование Zigbee, загрузки HA, импорт или удаление данных. Автоопределение ZHA/Z2M описано в #948, фиксированная демонстрация содержит обе системы.
- Производственное сохранение, отмена, права, ошибки и транзакции реализуются по issue и существующим контрактам. Синтетический прототип не служит доказательством их работы в продукте.

## Редактируемые материалы

- `general-settings-v7.fragment.html` и `settings-drafts-v2.fragment.html` — исходные интерактивные фрагменты с CSS/JS и данными, пригодные для последующей полировки.
- `general-data.json`, `draft-data.json` — те же проверочные данные отдельно.
- `draft-parity-report.json` — проверка полноты 12 черновых сценариев.
- [Решения и открытые вопросы черновиков](draft-decisions.md) — подробная инвентаризация, включая особые границы сохранения пылесоса и радара.

Каноническое описание требований и критерии приёмки находятся в телах GitHub Issues. Этот каталог хранит фиксированные визуальные материалы для сравнения; он не является параллельным бэклогом.
