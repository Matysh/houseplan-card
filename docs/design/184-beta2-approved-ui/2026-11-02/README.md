# Согласованный UI: 1.84 Beta 2, 2026-11-02

Полный контракт UI-001–UI-019: [CONTRACT.md](CONTRACT.md). Это визуальная спецификация для реализации в продукте, а не готовый продуктовый патч. Прямое уточнение владельца: всё переиспользуемое реализовать в общем UI Kit, без отдельных дублирующих стилей; одинаковые узлы используют единый источник размера.

## Воспроизведение на другом компьютере

Нужны Git, Node.js 22+, PowerShell на Windows / unzip на Linux/macOS. Получите ветку пакета `codex/184-beta2-approved-ui` и перейдите в корень checkout. Установка npm-зависимостей и сборка продукта для replay не нужны.

```sh
node demo/ui-lab/prepare-ha.mjs
node docs/design/184-beta2-approved-ui/2026-11-02/replay.mjs --repo . --port 8893
```

Первый шаг загружает закреплённый официальный HA frontend в пользовательский кэш. Если кэш уже есть, повторять подготовку не нужно. Для другого расположения передайте `--ha-cache PATH` обеим командам. Replay скачивает официальный `houseplan.zip` v1.84.0-beta.2 и сверяет SHA256; можно передать имеющийся архив `--release-zip PATH`. Он распаковывается только во временный каталог, исходный checkout и пользовательский стенд не изменяются. Тег содержит прежний tracked frontend, поэтому не заменяйте архив релиза файлами `custom_components/houseplan/frontend` из тега.

Открыть `/HousePlan` — основная панель; `/dashboard` — полноценная карточка Sections с редакторами. Все URL на `http://127.0.0.1:8893`. Синтетический fixture, никаких подключений к настоящему HA. Остановка Ctrl+C. Изменения данных остаются в localStorage отдельного replay; исходное состояние возвращается кнопкой UI LAB → «Вернуть исходный снимок». На частном стенде владельца эту кнопку не использовать.

## Материалы

- `runtime/`, `overrides/`: точный итог локальных визуальных правок. DOM-патчи, observers, polling и подмена private hooks нужны только для прототипа; в продукт переносится контракт через общую архитектуру.
- `fixture.json`: публичные синтетические данные из предыдущего пакета #1132, без частного бэкапа.
- `approval.json`, `journal.json`: согласование всей итерации и финальный перечень изменений; ранние отвергнутые варианты не нормативны.
- `provenance.json`: база, релиз и хэши материалов.
- `screenshots/`: новые иллюстрации на синтетических данных. Для поведения/анимации используйте replay, а не статичный кадр.
- `IMPLEMENTATION.md`: точки переноса в продукт и остающиеся ограничения.

## Адресный визуальный просмотр

1. На широкой панели переключить все редакторы: движение кнопок, боковой панели, сцены и сохранение размера объектов. Уменьшить ширину так, чтобы открытие боковой панели меняло фазу переполнения; повторить. Проверить reduced motion и быстрые повторные переключения.
2. В редакторах «Стены»/«Линия»: поля с «см», 3 символа при вводе/вставке, подсказка Shift, равенство размеров узлов и preview. Добавить узел за прежними границами при разных поворотах; камера остаётся на месте.
3. Навести на замкнутый контур без комнаты; затем создать/сохранить комнату: разные тосты находятся по центру видимого поля, включая боковую панель.
4. Открыть список пространств и источник устройства: выбранный пункт с заливкой, hover рамкой; длинные двухстрочные строки не сжимаются. На узкой панели правая грань hover списка пространств видима.
5. На fixture с открытой по датчику дверью проверить акцент только дуги; полотно обычное. Сравнить закрытый/недоступный датчик и дверь без датчика.
6. В карточке проверить отсутствие заголовка, полосу перед header и углы при двух темах. Настоящая HA-тема задаёт радиус; 20px и высота 632px в примере — настройки harness, не требования к продукту.

Визуальное согласование не означает готовность производительности. Стабильные 60 FPS не подтверждены; после оптимизации обработчик кадра обычно 0,2–0,6 мс, но подготовка переходов в отдельных замерах занимала 0,3–0,9 с и были длинные интервалы между кадрами. При реализации нужны адресные измерения на большом плане. Продуктовые тесты/сборка/CI в ходе публикации не выполнялись.
