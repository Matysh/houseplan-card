## 1. Цель и границы этапа

Получить работающий объёмный вид на реальных планах, не показывая его никому,
кроме тех, кто явно включил флаг.

Входит:

- механизм Labs (§2) — общий, с реестром, сроком жизни флага и тестами;
- чистая математика проекции и обратного преобразования (§4);
- объём стен, перегородок, колонн и реальные разрывы в проёмах (§5);
- проекция позиций маркеров и подписей комнат через ту же функцию (§4.3);
- переключение вида, поведение редакторов и киоска (§7);
- кэш, fallback, диагностика (§8, §9);
- тесты, golden и перф-гейт под флагом (§11).

Не входит: см. §14 и §13 исследования.

## 2. Labs — механизм скрытых фич

Нормативная часть, переиспользуемая всеми будущими «сырыми» фичами.

### 2.1 Реестр

Единственный источник истины — `src/labs.ts`:

```ts
export interface LabsFlag {
  id: string;            // 'iso'
  issue: number;         // 89
  since: string;         // версия карточки, в которой флаг появился
  expires: string;       // версия, начиная с которой флаг МЁРТВ
  summary: string;       // одна строка для консоли, только EN, не i18n
}
export const LABS_FLAGS: readonly LabsFlag[] = [ /* … */ ];
```

Флаг без `issue`/`expires` заводить запрещено: тест паритета (§11) валит сборку.
`summary` намеренно не проходит через i18n — это диагностика, а не UI.

### 2.2 Активация

Один парсер читает **и** query-строку, **и** хэш — карточка уже владеет хэшем
(`space=` deeplink, `houseplan-card.ts:1291`, слушатель `hashchange` на `:1422`),
а query переживает не все переходы Lovelace:

```
?hp-labs=iso              включить один флаг
?hp-labs=iso,foo          включить несколько
#hp-labs=iso              то же самое в хэше
?hp-labs=-iso             выключить один
?hp-labs=off              выключить все
```

Правила:

- значения разделяются запятой, регистр игнорируется, пробелы обрезаются;
- неизвестный идентификатор **молча игнорируется** — никаких ошибок и тостов;
- параметр не удаляется из адресной строки: пользователь должен видеть, почему
  карточка выглядит иначе;
- изменение хэша применяется без перезагрузки (существующий `hashchange`).

### 2.3 Персистентность

Активный набор пишется в `localStorage['houseplan_card_labs_v1']` (соседи:
`houseplan_card_layout_v1`, `houseplan_card_cfg_v1`). Это нужно, чтобы флаг
пережил переход между видами дашборда и перезапуск приложения HA.

Приоритет: **URL → localStorage**. `off` очищает и то, и другое.
Недоступный или сломанный `localStorage` (приватный режим, квота) не является
ошибкой: флаг живёт до конца сессии страницы.

### 2.4 Срок жизни

У каждого флага обязателен `expires`. Как только версия карточки достигает
`expires`, флаг **не включается ни при каких условиях**, даже из URL. Тест
проверяет это на синтетическом флаге. Смысл: лабораторный флаг обязан либо
превратиться в фичу, либо умереть; «временный» флаг, забытый в коде на год, —
это ровно то, ради чего заводится реестр.

### 2.5 Диагностика

- При непустом наборе — **одна** строка в консоль при первом рендере:
  `HOUSEPLAN LABS: iso (#89, expires 1.65.0)`. При пустом — тишина.
- `window.__hpLabs` отдаёт неизменяемую копию активного набора: за это
  цепляются смоки, чтобы не парсить консоль.
- Ничего в UI: ни бейджа, ни тоста, ни строки в «Общих настройках».

### 2.6 Границы механизма

Флаг Labs — **только presentation**. Запрещено гейтить им:

- миграции данных, схему конфигурации и любые записи в сторы;
- новые сетевые вызовы и ws/http-команды;
- поведение бэкенда (бэкенд о флагах не знает вообще).

При выключенном флаге дерево DOM, набор запросов и записи в сторы обязаны быть
идентичны текущим. Это проверяется тестом, а не обещанием (§11).

### 2.7 Чего механизм не делает на этапе 1

YAML-опция карточки (`labs: [iso]`) не вводится: конфигурация уезжает в
скриншоты, в поддержку и в экспорт #50, и флаг «протечёт» раньше времени.
Добавить её можно позже одной строкой в том же парсере.

## 3. Что видно под флагом `iso`

- В режиме просмотра (и в киоске) появляется кнопка `mdi:cube-outline` с
  accessible name «Объёмный вид» / «Volumetric view», рядом с существующими
  элементами шапки; повторное нажатие возвращает плоский вид.
- Строки i18n добавляются в оба словаря сразу (иначе падает тест паритета),
  но существуют только в этой ветке разметки.
- Больше ничего: ни в «Общих настройках», ни в настройках пространства, ни в
  диалогах устройства.

## 4. Проекция

### 4.1 Чистый модуль

`src/iso-projection.ts` — без Lit, без DOM, без `hass`:

```ts
export interface IsoCamera { tiltDeg: number; rotDeg: number; scale: number; }
export function projectPoint(p: readonly [number, number], z: number, cam: IsoCamera): [number, number];
export function unprojectPoint(screen: readonly [number, number], cam: IsoCamera): [number, number];
export function projectPolygon(poly: readonly (readonly [number, number])[], z: number, cam: IsoCamera): [number, number][];
```

Инварианты:

- `unproject(project(p, 0)) ≈ p` с точностью 1e-9 на всём диапазоне холста
  (±5000 по `docs/CANVAS.md`);
- функция детерминирована и не зависит от порядка вызовов;
- камера этапа 1 — **одна константа** (§4.2), но подписи функций уже принимают
  её параметром, чтобы пресеты второго этапа не потребовали переписывания.

### 4.2 Камера

Один зафиксированный ракурс, значения выбираются на spike (D6) и после этого
меняются только вместе с пересъёмкой golden. Свободное вращение и tilt в этап 1
не входят (исследование §5.2).

### 4.3 Одна проекция на всё

SVG-геометрия и HTML-оверлеи (маркеры, подписи комнат, карточки комнат)
проецируются **одной и той же** функцией. Отдельная «примерно такая же»
формула в CSS для оверлеев запрещена: расхождение маркера и плана — главный
риск исследования (§12).

Позиции по-прежнему хранятся нормализованными (`pos.s`, 0..1) и не меняются:
проекция применяется на рендере, к сохранённым данным не прикасается.

## 5. Объём

- Источник — **канонические тела стен** (`wallBodiesGeometry`), те же, что
  используются моделью света. Второй геометрии не заводится.
- Верхняя поверхность — проекция контура тела на `z = h`; боковые грани — только
  для граничных рёбер, видимых при фиксированной камере. Число граней **O(рёбер)**,
  а не O(рёбер × высоту): копирование контура слоями (как в демо) запрещено.
- Проём **реально разрывает** объём: разрыв берётся из той же геометрии, что
  вырезает проёмы для света, а не рисуется поверх.
- Перегородки и колонны экструдируются из своих текущих геометрий; высота у всех
  одна и та же величина, в сантиметрах пользователю не показывается
  (исследование §4).
- Виртуальные границы остаются линиями на полу и высоты не получают.
- `show_borders: false` не меняет семантику: невидимые стены остаются невидимыми,
  но продолжают участвовать в площади и в модели света.

## 6. Слои

Поведение слоёв — таблица §6 исследования, она нормативна. Дополнительно, как
запреты:

- существующее дерево карточки **не оборачивается** в CSS 3D-контекст;
  `perspective`, `rotateX/Z`, `preserve-3d` не появляются ни на `.zoomwrap`, ни
  на её предках;
- day/night `filter: brightness()` и Glow `mix-blend-mode: screen` не трогаются;
- слой света остаётся одним регионом на источник с одним размытием на весь слой
  (`docs/LIGHT.md`); объёмный вид не добавляет второго слоя света — это прямо
  запрещено ассертом `test/golden-matrix.test.mjs`.

## 7. Взаимодействие

- **Pointer.** Все попадания считаются через `unprojectPoint`: клик по комнате,
  hover, перетаскивание маркеров, инструменты. Отдельной hit-геометрии нет.
- **Zoom/pan** работают как сейчас и не пересчитывают модель (§8). Переключение
  вида не меняет сохранённый зум и не двигает фокус плана скачком (совместимо
  с #82).
- **Редакторы всегда плоские.** Вход в любой редактор показывает плоский вид,
  выход восстанавливает предыдущий; переключение не пишет в command stack и не
  создаёт записей в сторе.
- **Киоск** использует последний выбранный вид этого браузера; скрытая панель не
  должна делать возврат в плоский вид невозможным.
- **Непрерывность.** Переключение вида не должно поднимать вуаль warm-remount
  и не должно показывать пустой промежуточный кадр (#73, `docs/WARM-REMOUNT.md`).

## 8. Производительность

- Геометрия объёма пересчитывается только при изменении **контентного
  отпечатка** плана (D5): id + геометрия комнат, стен, проёмов, перегородок,
  колонн, толщины, cell_cm. Ключ вида `${space.id}|${fingerprint}`.
- Pan/zoom меняют только transform/viewBox и ничего не пересчитывают.
- Бюджет: на большом детерминированном фикстуре объёмный вид не хуже плоского
  более чем на **20 %** по `stateUpdateMs`, `modelReadyMs` и `longTask.maxSingleMs`.
  Замер — существующим `demo/performance/compare.mjs`, отдельным профилем.
- Плоский вид при выключенном флаге не должен подорожать вообще: ни одного
  дополнительного прохода по устройствам или геометрии.

## 9. Fallback и диагностика

- Любое исключение в renderer объёмного вида переводит карточку в плоский вид
  на этом кадре, пишет одну строку в dev-лог с причиной и не ломает остальную
  карточку.
- Повторные исключения не спамят лог: одна строка на сессию вида.
- Плоский вид остаётся значением по умолчанию всегда, включая первый запуск с
  включённым флагом.

## 10. Данные и совместимость

- Формат конфигурации не меняется вообще: ни одного нового поля в `spaces`,
  `markers`, `settings`.
- Записей в config/layout сторы объёмный вид не делает (D4).
- Предпочтение вида: `localStorage`, ключ рядом с остальными (`houseplan_card_view_v1`),
  по одному значению на пространство — как уже сделано для зума (`LS_ZOOM`).
- Экспорт/импорт #50 не затрагивается: переносить нечего.

## 11. Тесты

### Юниты

- `iso-projection`: round-trip `unproject(project(p)) ≈ p` на границах холста,
  детерминированность, поведение при вырожденной камере.
- Боковые грани: число граней = числу граничных рёбер; проём даёт разрыв, а не
  нулевую грань; перегородка примыкает к стене без шва.
- `labs`: разбор query и хэша, несколько флагов, `-flag`, `off`, неизвестное
  значение, приоритет URL над storage, недоступный `localStorage`, **мёртвый по
  `expires` флаг не включается ни из URL, ни из storage**.
- Реестр: у каждого флага заполнены `issue`, `since`, `expires`, `summary`.

### Смоки

- **Главный тест этапа: без флага ничего не изменилось.** Снимок
  `card.renderRoot.innerHTML` и списка ws-запросов на одном и том же фикстуре
  до и после ветки Labs совпадает байт в байт.
- С флагом: кнопка появляется, переключает вид, повторное нажатие возвращает
  плоский; вход в редактор показывает плоский вид, выход восстанавливает.
- Pointer: клик по комнате и перетаскивание маркера в объёмном виде попадают
  туда же, куда в плоском (сверка координат через `unproject`).
- Флаг переживает смену вида дашборда (проверка персистентности), `off` его
  снимает.
- Переключение вида не поднимает вуаль warm-remount.

### Golden

- Две сцены под флагом (светлая и тёмная) на фикстуре со смешанной толщиной,
  проёмами, колонной и Glow; ветка активации флага добавляется в
  `demo/golden/harness.mjs`, `GOLDEN_MATRIX_VERSION` поднимается.
- Ни одна существующая сцена не меняется — если меняется, это регресс, а не
  «новые эталоны».

### Мутанты (контракт #85)

Задача не считается выполненной, пока не показано, что тесты краснеют при:

1. включении объёмного вида без флага (D1);
2. отдельной формуле проекции для HTML-оверлеев (§4.3);
3. кэшировании геометрии по `_cfgEpoch` вместо контентного отпечатка (D5);
4. игнорировании `expires` у флага (§2.4);
5. построении боковых граней слоями вместо граничных рёбер (§5).

## 12. Acceptance criteria

1. При выключенном флаге карточка идентична текущей: DOM, запросы, сторы,
   производительность, все существующие golden.
2. Флаг включается из query и из хэша, переживает переход между видами и
   снимается через `off`.
3. Мёртвый по `expires` флаг не включается никаким способом.
4. Под флагом доступен объёмный вид с фиксированным ракурсом; плоский вид
   остаётся значением по умолчанию.
5. Физические стены, перегородки и колонны имеют непрерывные верх и боковые
   грани; виртуальные границы плоские.
6. Двери, окна и ворота дают реальные разрывы объёма без швов и торцов внутри
   проёма.
7. Glow, spill, солнце, заливки и hover сохраняют текущую семантику; второго
   слоя света не появилось.
8. Маркеры, подписи и попадания курсора считаются одной проекцией и не
   расходятся с планом.
9. Редакторы всегда плоские; переключение не пишет в сторы и не создаёт записей
   в истории.
10. Исключение в renderer даёт плоский fallback и диагностируемую причину.
11. Перф-бюджет §8 выполнен на большом фикстуре.
12. Формат конфигурации не изменился.

## 13. Артефакты этапа

нет, и релизные заметки о ней молчат.
