**Адресная проверка достаточности правки (единственный непокрытый вопрос
раунда):** закрывает ли новая формулировка `## Связи` находку F1 (внутреннее
противоречие «0–2» vs «#1146–#1149» в одной и той же issue)?
**Результат:** да. Новая формулировка явно перечисляет все четыре пакета
(`#1146, #1147, #1148 и #1149`) как блокирующих предшественников и добавляет
условие «все четыре должны быть в S8 до начала кода #1150» — это дословно
совпадает с диапазоном, который называет раздел «Проблема, скоуп и
не-скоуп» («Финальный пакет после #1146–#1149»), и с порядком из
авторского аналитического комментария («#1146 → #1147/#1148 → #1149 →
#1150»). Расхождения между разделами issue больше нет; новых чисел,
дублирующих по смыслу уже существующие (§8 — «одно число, один источник»),
правка не вводит — «6 900 строк CSS против 7 635» остаётся тем же
единственным прогнозным числом, что и в r1, перенесённым без изменения.
Негативный/мутантный прогон здесь неприменим (нет исполняемого предмета —
правка текстовая), что соответствует общей политике для случаев без
исполнимого oracle.

Полные build/test гейты (`gate:small`, `npm test`, `tsc`, golden) не
запускались — на этапе spec они не требуются, а материал ревью не содержит
кода; это не изменилось со времени r1.
