# CODE-REVIEW-647-r1

Issue: #647 · Этап: code · Заход: r1 · SHA материала: `f0ba7c5da97418e2b81a257d7b8eda4604e3a41e`

## Скоуп

ТЗ (редакция r2, спор закрыт SPEC-REVIEW-647-r2, зелёный) требует:
убрать текстовый счётчик устройств «N устр.» из шапки основной панели;
вынести × закрытия редактора из активной кнопки режима в отдельный
слот постоянного размера 24×24 px сразу после группы кнопок режимов;
слот пустой и инертен (`aria-hidden`, без фокуса) вне редактора; слот
виден на любой ширине, где видны кнопки режимов, включая 721–1100 px,
где раньше скрывался счётчик; ширина шапки и позиции соседних
контролов не меняются при входе/выходе/переключении редакторов;
кликабельная зона × не меньше 24×24 px; настраиваемая метрика
«Количество устройств» сводной панели (#437) не затрагивается.

Диапазон материала — один коммит `44fed222`/`f0ba7c5d` поверх `dev`
(`27d78801`; `dev` с тех пор получил только неконфликтующий коммит
приёмки golden `632d6a2f`). Правка: `src/houseplan-card.ts` (шапка),
`src/styles/chrome.styles.ts` (слот и ×), `src/styles/dialogs.styles.ts`
(удаление `.count`/медиа-правила), 4 словаря i18n (удаление
`count.devices`), новый смок `demo/smoke_toolbar_stable_width.mjs`,
3 переведённых смока, 6 мутантов, документы (`UX-MODES.md`,
`STYLING-HOOKS.md`, `data-hp-contract.json`), оба changelog, бандл.

## AC · разбор

Таблица «AC · чем доказан · чем краснеет» в теле issue заполнена по
всем защитным AC (AC1–AC6), включая AC7 (регресс, без мутанта — верно
помечено как таковой) и AC8 (существующие мутанты сводной панели).
Пустых третьих столбцов нет.

- **AC1 (К1, нет числа).** Прочитано: `<span class="count">` и i18n-ключ
  `count.devices` удалены из шапки и всех 4 словарей
  (`src/houseplan-card.ts` дифф, `src/i18n/{en,ru,de,fr}.json`).
  `grep` подтвердил отсутствие иных чтений ключа. Смок
  `w*_noHeaderCount` + `ru_noHeaderCount` — зелёные, лично прогнал.
- **AC2 (К2, ширина шапки стабильна) / AC3 (К3, соседи не прыгают).**
  Слот вынесен из кнопки режима как отдельный `<span class="editor-close-slot">`
  с фиксированным `width/height: var(--hp-editor-close-size)` = 24px
  что вне редактора, что внутри — размер не зависит от содержимого.
  Кнопки `.modetab` больше не содержат `×` ни в одном состоянии.
  Смок `w*_widthAndTabsStable`/`w*_idleSlotKeepsSize` — зелёные;
  мутант «слот схлопывается вне редактора» лично воспроизведён,
  краснеет (8 FAILED, совпадает с заявленным).
- **AC4 (К4, × только в редакторе, слот инертен).** `aria-hidden`
  выставлен ровно при `this._mode === 'view'`; в этом состоянии CSS
  `[aria-hidden='true']{pointer-events:none}` и в дереве нет кнопки
  (тернарник `this._mode !== 'view' ? html\`<button>...\` : nothing`)
  — значит слот действительно без фокусируемых потомков, а не просто
  визуально пуст. Проверено чтением; смок `w*_idleSlotInert` зелёный.
- **AC5 (К5, hit-target ≥24×24).** Кнопка `.closex` внутри слота —
  `width/height: 100%`, слот — 24×24 через переменную; отрицательные
  поля старой реализации убраны. Мутант «переменная = 13px» лично
  воспроизведён, краснеет (12 FAILED, совпадает).
- **AC6 (К6, × не прячется на 721–1100 px).** Правило `@media
  (max-width: 1100px){.head .count{display:none}}` удалено вместе со
  счётчиком (`dialogs.styles.ts` дифф), новый `.editor-close-slot` его
  не наследует — отдельный класс, отдельный файл (`chrome.styles.ts`).
  Мутант «добавить то же правило слоту» лично воспроизведён, краснеет
  (9 FAILED на 1000/768 px, 1400 зелёный — ровно то, что просил
  Medium-1 из SPEC-REVIEW-647-r1).
- **AC7 (К7, нет overflow).** Регресс-проверка, мутанта нет (верно
  помечено в таблице). Смок `w768/w390_noHeadOverflow` зелёный, лично
  прогнал; дополнительно `smoke_dialog_footer_width` (соседняя
  раскладка шапки) зелёный.
- **AC8 (сводная панель #437 не изменилась).** Источник «Количество
  устройств» в отдельном модуле сводной панели, диф его не касается.
  `smoke_summary_panel.mjs` — зелёный, лично прогнал.

Документы синхронизированы: `docs/UX-MODES.md` — строка про
panel-host (device count убран из перечня) и абзац про × (слот

**Low-1.** `smoke-select` называет `demo/smoke_decor.mjs` прямым
совпадением по символам `_mode`/`stopPropagation`, но в перечне
прогнанных гейтов хендоффа этого смока нет (назван `smoke_decor`
нигде, хотя `modes`, `houseplan_panel`, `space_settings` — два других

прогнал `node demo/smoke_decor.mjs`, все проверки прошли. Дефекта
нет, это неполнота раскрытия «какие гейты прогнал» из трёх прямых
совпадений smoke-select. Снимаю без возврата автору, с записью здесь.

Других находок нет: High — 0, Medium — 0.

## Что проверено и корректно

- Реализация буквально соответствует «принято предположительно» ТЗ:
  слот стоит на месте бывшего счётчика, отдельный класс без
  наследования правил `.count`, размер — одна переменная.
- Кнопки режимов после правки не зависят от `this._mode` по ширине —
  единственный источник роста шапки убран, а не замаскирован.
- Слот рендерится только внутри ветки `this._canEdit`, как и раньше
  сами кнопки режимов — для домочадца/киоска (не редактор) меняется
  ровно то, что заявлено в сценарии ТЗ: исчезает число, слота не
  появляется, потому что кнопок режимов там и не было.
- 6 мутантов зарегистрированы в `scripts/mutation-registry.mjs` рядом
  с мутантами шапки/режимов, все опираются на реальный
  `guard`-прогон нового смока; 3 из 6 лично воспроизведены с
  результатом, совпадающим с заявленным автором числом упавших
  проверок — доверие к оставшимся трём (AC1, AC3, AC4) основано на
  чтении кода (тривиальные проверки: удалённый узел, убранный
  тернарник, перестановка атрибута) и на `mutation-gate --check`,
  подтвердившем целостность якорей патчей.
- `count.devices` подтверждён мёртвым по всему дереву (`src/`, `demo/`,
  `scripts/`) — можно было безопасно удалить.
- `docs/data-hp-contract.json` синхронизирован с фактической разметкой
  (`data-hp="editor-close"` переехал с `<ha-icon>` на `<button>`).

## Чего не проверял

- **Golden-эталоны и `docs:capture`.** ТЗ прямо называет их
  предрелизным гейтом (§11.4: «Golden, браузерные смоки... запускаются
  перед бетой, после того как код-ревью пройдено»); диф действительно
  меняет визуал (число пропадает из широких кадров, × переезжает из
  кнопки в слот во всех кадрах редактора) — пересъёмку и приёмку
  (`golden:accept -- --reviewed`, `docs:capture`) должен выполнить
  отдельный шаг на Linux CI, не этот раунд ревью.
- Остальные ~38 из 41 «слабой связи» smoke-select (PDF-экспорт, стены,
  декор-объекты, локализация админки и т.д.) — не прогонял: общие
  символы `_mode`/`stopPropagation` не создают правдоподобного пути
  к раскладке шапки в этих сценариях, а полный прогон матрицы —
  предрелизная обязанность, не гейт ревью.
- `pytest tests_backend` — диф не касается `custom_components/**/*.py`.
- `npm run invariants` — диф не касается геометрии модели.
- Windows/WSL и HA-харнесс — не запускал (не требуется этой задачей).
- Мутанты AC1/AC3/AC4 (`toolbar-device-count-returns`,
  `toolbar-close-back-inside-tab`, `toolbar-close-slot-idle-focusable`)
  — не воспроизводил лично их фактическое покраснение; проверил
  чтением кода и статической целостностью якорей (`mutation-gate --check`).
