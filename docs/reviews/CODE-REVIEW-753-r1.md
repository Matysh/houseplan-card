## Скоуп

Issue #753: исключение #562 («инфраструктурный диапазон статуса не требует, если
в диффе нет файлов класса A») по тексту гейта не знало, где находится задача.
Из-за этого issue в `S3-spec`/`S4-spec-review` (трек `ask`) могла пушить ветку
из одних тестов без статусной метки — Rule 8 пропускала её с предупреждением.
Такая ветка становится материалом ревью ТЗ (конвейер берёт свежую
`origin/issue/<NN>-*`), что прямо нарушает §11.8 («до `S5` не пушится ни код,
ни сама ветка») и даёт ревьюеру ТЗ код, который он по §2.4 видеть не должен.

Задача сужает исключение #562: оно действует только для issue БЕЗ меток
`S3-spec`/`S4-spec-review`. Решение принимается по каждому issue в
`checkIssueStatuses`, а не по диапазону, как раньше.

Трек show (#696) — чистая функция одного гейта, решать нечего, поведение уже
записано каноном (§11.8, §2.5). Проверка соразмерна: объём и строгость — не
находки, сверх находок канона track show не расширяет.

Критерий §5 (маршрут вердикта): задача проходит все пункты —
`complexity` (2/10 по оценке автора, чистая правка одной функции),
`surfaces` (один модуль — `scripts/process-gate.mjs`, Rule 8), `migration`
(нет), `ux-contract` (нет — это CI-гейт, не пользовательский интерфейс),
`perf-touch` (нет), `undocumented` (поведение уже в каноне §11.8/§2.5, задача
устраняет расхождение гейта с каноном, а не вводит новое). → `route: fix`.
