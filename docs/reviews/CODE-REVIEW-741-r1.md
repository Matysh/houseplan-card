## Риск по изменённым участкам (#707)

- **perf — `src/iso-scene-render.ts:651` (удалена), участок `iso-scene-render`.**
  Поведение уже зафиксировано: читал тело `resolveIsoOverlayFitEnvelope`
  (`src/iso-scene-render.ts:658-668`) и в версии до диффа, и после — `input.stageSize`
  нигде не читается, функция использует только `baseBounds`, `entries`,
  `ownerId`, `targetView`. Удаление поля из интерфейса и обоих мест передачи —
  изменение только по типам, ни одного пути исполнения не задевает. Документ
  `docs/ISOMETRIC.md` (раздел «Fit», строки ~245-263) фиксирует контракт прямо:
  «Neither zoom nor a stage resize is a layout event… the fit envelope reserves
  no nudge budget» — т.е. stage/aspect и до этой задачи не должны были влиять на
  раскладку. route: `fix` (критерий не нарушен — `perf-touch`: изменения
  производительности нет, т.к. убираемый путь не исполнялся).
- **visual (render) — `src/iso-scene-render.ts:651` (удалена), участок `iso-*` (render).**
  То же: поле не читалось, значит удаление не может изменить картинку. Плюс
  переписанный юнит `#725 AC3/#741` это утверждает явно и проверяемо: `bounds`
  идентичны для пяти разных aspect (0.5, 1, 1000/500, 320/180, собственный aspect
  кадра), различается только `view`; я подтвердил мутационным прогоном (таблица
  выше), что тест ловит регресс, где это переставало бы быть так. Визуальный
  минимум прогоняется `gate:small` (автор) — отдельного `ci:golden` для
  переноса/удаления неиспользуемого поля типа не требуется: рендер-путь не
  меняется ни на один пиксель, доказательство — отсутствие чтения поля в коде
  плюс тест. route: `fix`.
