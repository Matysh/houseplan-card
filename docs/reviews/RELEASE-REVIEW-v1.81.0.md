## Поверхности и как они проверялись

Было запущено шесть параллельных агентов для исполняемой (не читательской)
проверки шести кластеров поверхностей — каждому выданы: список изменённых
файлов кластера, релевantные страницы `docs/SCOPE.md`, задание прогнать
конкретные `demo/smoke_*.mjs` (Playwright, реальный headless-браузер),
прогнать `npm run invariants` там, где затронута геометрия, и вручную
промоделировать посимвольный ввод / настоящий Escape / настоящий клик
крестиком через `demo/serve.mjs`, плюс по одному "самому рискованному
соседнему" сценарию на кластер (например: смена этажа для маршрута
пылесоса — исторический прецедент #611; отмена импорта после выбора файла,
но до подтверждения — проверка "никогда не удалять файл по догадке";
протечка клика через summary-панель на план под ней; вырожденная стена при
перетаскивании узла в угол):

1. Диалоги и жизненный цикл редактора (hp-dialog, draft-close/draft-actions,
   settings/room/marker/space) — включая диагностику на настоящем `ha-dialog`
   (#505, `demo/verify_ha_dialog_discard_recovery.mjs`).
2. Геометрия стен и узлов (wall-node-*, wall-segment-model, wall-thickness*,
   align-grid, room-fit) — включая `npm run invariants`.
3. Устройства и guard-замка (device-*, devices.ts) — включая прямую проверку
   инварианта "тап по плану никогда не активирует замок/сигнализацию"
   (`docs/SCOPE.md`, раздел «The lock invariant»).
4. Маршруты робота-пылесоса и Zigbee-топология (vacuum-*, trails.py,
   zigbee-topology*) — включая смену этажа/карты и наведение на устройство
   для временных соседних связей.
5. Импорт/экспорт, резервные копии, хранилище, восстановление версий
   (import_export.py, store.py, previous_data.py, config_flow.py,
   backup-import-intent.ts, version-recovery*) — включая правило "никогда не
   удалять файл пользователя по догадке" и оптимистичную блокировку.
6. Summary-панель, киоск-карусель, LED-полосы, 2.5D-презентация
   (summary-panel-*, kiosk-*, led-strip-*, optimize-plans-*) — включая
   read-only контракт summary-панели и сохранность канонической геометрии
   при переключении в 2.5D и обратно.

**Эти шесть агентов не успели вернуть результат до принудительного
завершения сессии** (сработал форсированный вызов структурированного
вывода раньше, чем пришли уведомления о завершении фоновых задач). Их
дословные команды и результаты не попали в этот документ — ни один вывод
Playwright-смоков, ни один пример воспроизведения не был мной прочитан и
проверен. Поэтому ни одна из шести поверхностей не может считаться
проверенной исполнением по стандарту §11.5/§2.6: работа была запущена
корректно (реальный браузер, посимвольный ввод, настоящие Escape/клик,
фикстура `ha-dialog`), но не закрыта разбором результатов.

## Находки

Нет — ни одной находки не подтверждено, потому что ни один из шести
прогонов не был мной просмотрен до завершения сессии. Отсутствие находок
здесь означает "не успел проверить", а не "проверил и не нашёл".

## Что проверено и корректно

- `typecheck`, `bundle-policy --verify`, `bundle:sync` — зелёные, на SHA
  кандидата `deee605cb8c88584c14e2e1fe15360e073acd5c6`.
- Непрофильные (не-HA) backend-тесты `tests_backend` зелёные (891/4 skip).

## Чего не проверял и почему

- **Полный `npm test`** — не дождался завершения (сотни test-файлов,
  длительный прогон); не включаю в документ предположительный результат.
- **18 `test_ha_*.py` (397 тестов)** — не собираются в этой песочнице:
  закреплённый `pytest-homeassistant-custom-component` требует Python ≥3.14,
  в среде доступен только 3.12. Honest-флаг `HA harness NOT collected`
  зафиксирован инструментом. Канон предлагает Linux CI или WSL
  (`scripts/wsl-setup.sh --verify`) — недоступны здесь.
- **Все шесть кластеров поверхностей** (диалоги, геометрия стен, устройства/
  guard-замка, пылесос+Zigbee, импорт/экспорт/хранилище, summary/kiosk/LED/
  2.5D) — агенты были запущены корректно с Playwright, реальными кликами/
  клавиатурой и фикстурой `ha-dialog`, но их отчёты не были получены и
  разобраны до принудительного завершения. Это наибольший пробел документа:
  именно эти поверхности и есть предмет независимого ревью по §11.5.
- Полная матрица `smoke-select.mjs --base v1.80.1 --head HEAD` показала
  315 прямых совпадений из 361 смока в таблице — то есть почти весь набор
  смоков формально релевантен линии такого объёма; выбор шести кластеров
  был попыткой покрыть риск-репрезентативный срез (диалоги/геометрия/
  устройства-безопасность/данные-целостность/визуал-наложение), а не
  исчерпывающим прогоном — полная матрица остаётся предрелизной
  обязанностью, а не обязанностью этого ревью.
