### Ручная проверка мутанта (AC1 — защитный AC)

Применил патч мутанта вручную (вернул `process.exit(code)` вместо `process.exitCode = code` в `scripts/mutation-gate.mjs`) и перезапустил `node --test --test-name-pattern="#818 AC1"`:

- **после отката** (`git diff` пуст, файл идентичен коммиту) — зелёный.

Это и есть требуемая строка «AC · чем доказан · чем краснеет»:

| AC | Чем доказан | Чем краснеет |
|---|---|---|
| AC1 (защитный: stdout не теряет хвост под backpressure) | `test/mutation-gate.test.mjs` — `#818 AC1`, реальный CLI, читатель с искусственной задержкой, `queued > 0` как доказательство небанальности | мутант `mutation-gate-cli-exits-before-stdout-drains` в реестре, проверен лично: CAUGHT на патче, PASS после отката |

Дополнительно проверил риск зависания на забытом хендле содержательно, а не только по заявлению автора: весь граф модулей, которые трогает `main()` (`mutation-execution.mjs`, `mutation-selection.mjs`, `mutation-registry-check.mjs`, `mutation-evidence.mjs`, `mutation-attribution.mjs`, `mutation-environment.mjs`), использует только `spawnSync` (синхронные дочерние процессы); `process.stdin`, `readline`, `fs.watch`, таймеры нигде не встречаются (`grep` по всем модулям — пусто). Значит после `main()` действительно нет хендла, который может держать цикл событий, — утверждение автора «открытых хендлов после main нет» подтверждено чтением, а не принято на слово.

- Тестовый хелпер `inventoryCli811` корректно рефакторен в `inventoryRoot811` + обёртку — старые `#811 AC7` тесты не изменили поведения (прогнал — 4/4 PASS, включая прежние ассерты на WARN-строки и ориентир 200).
- Трейлеры коммита верны: `Issue: #818`, `User-Visible: no` — CHANGELOG не требуется и не тронут. Никаких чисел, видимых пользователю, дифф не меняет (инфраструктура CI, не продукт).
- Мутант зарегистрирован с `guard`, указывающим ровно на новый `#818 AC1` тест, и `because` с точной формулировкой регрессии — соответствует формату реестра.
