## Скоуп

Инфраструктурная задача (§1, ускоренный вход, без ТЗ): ночной мутационный
прогон 2026-10-09 (run 37895246049) сообщил 3 сбежавших мутанта и 1
свидетель без вердикта (ошибка подготовки). Issue #837 чинит все четыре:

1. `node-boundary-splice-skips-new-edge-safety` (`fe7c5ac7`) — патч
   `if (false && …)` делал вызов недостижимым и ломал сужение типов TS
   (`TS2345`), test-build не собирался.
2. `node-local-replacements-drop-failed-repairs` (`ecb23286`) — свидетель был
   слеп с рождения: фикстура #834 не чувствительна к подрезке (площадь/
   топология совпадают с/без неё).
3. `resize-pointer-capture-removed` (`33f893d7`) — живая копия хэндла
   кликабельна (`.rszhandle{pointer-events:all}` перекрывает
   `pointer-events="none"` слоя), поэтому старые проверки смока проходили и
   без захвата указателя.
4. `resize-history-boundary-repair-removed` (`33f893d7`) — после ремонтов
   геометрии #834 у реального плана не осталось деградировавшей базы, ветка
   `wall-degraded-extra` не вычисляется ни разу, мутант стал эквивалентным на
   пути смока.

Пятым коммитом (`f7520800`) задача дополнительно чинит красный `dev`,
обнаруженный при прогоне Validate на промежуточном `975bfa2c` (run
37902509308): `reviews-archive`/`reviews-index` ошибочно считали битыми
ссылками цитаты внутри Markdown-кода и не узнавали «Итог: High · Medium ·

## Находки

### High — коммит `f7520800` дублирует уже выделенный под эту же поломку issue #839

`git log` показывает отдельную ветку `origin/issue/839-review-archive-gate`
(коммит `e47a2975`, 2026-10-09 12:23:44+03, на 13 минут позже `f7520800` —
12:10:09+03), выросшую из того же `975bfa2c`. Issue #839
(«Архив ревью v1.80.1: устранить два воспроизводимых падения unit-гейта»,
labels `tests, infra, S7-code-review, track:show`, статус **OPEN**) описывает
ровно ту же пару падений — битые ссылки-цитаты в `reviews-archive` и
нераспознанный вердикт `ship` в `reviews-index` — и в своём теле прямо
фиксирует: «владелец разрешил выполнение в текущем чате 2026-10-09». Автор
#839 независимо реализовал тот же фикс другим способом: новый модуль
`scripts/md-anchors.mjs`, правки `scripts/reviews-index.mjs` (а не только
`reviews-archive.mjs`), плюс запись `docs/release-ledger/v1.80.1/839.json` и
обновления `docs/DEVELOPMENT.md`/`docs/STATUS.md`.

Комментарий #837 называет свою часть «по решению владельца — в этой задаче»,
но ни в теле issue #837, ни в его комментариях нет такой строки от владельца
и нет упоминания #839 — `gh api .../837/timeline` не находит перекрёстной
ссылки на #839 (только на #838 в #839). Технически обе ветки сейчас зелёные
сами по себе (каждая чинит `975bfa2c` независимо), но при слиянии любая из
них вторая встретит конфликт в `scripts/reviews-archive.mjs` и тестовых
файлах либо принесёт в `dev` два разных, несовместимых решения одной и той же
проблемы — и `docs/release-ledger/v1.80.1/839.json` задним числом будет
описывать уже не тот код.

**Воспроизведение:**
```
git log --oneline origin/dev..HEAD                              # 975bfa2c..f7520800, #837
git log --oneline 975bfa2c..origin/issue/839-review-archive-gate # 975bfa2c..e47a2975, #839
git diff 975bfa2c..origin/issue/839-review-archive-gate --stat
gh issue view 839 --repo Matysh/houseplan-card   # владелец, тело, вторая независимая реализация
gh api repos/Matysh/houseplan-card/issues/837/timeline -q '.[]|select(.event=="cross-referenced")'  # пусто для #839
```

Находка в скоупе этого issue (это коммит самого #837), поэтому отдельный
issue не заводится — возврат автору. Варианта два: либо убрать из #837
коммит `f7520800` и оставить фикс исключительно в #839 (который уже несёт
явную формулировку разрешения владельца и бухгалтерию release-ledger), либо
получить явное решение владельца о том, что #839 закрывается как
дублирующий/заменённый этим коммитом, с перекрёстной ссылкой в обоих issue.
Техническое качество самого фикса в #837 (см. ниже) к находке отношения не
имеет — проблема в параллельной, нескоординированной работе над одной и той
же поломкой.

Нет Medium-находок, которые требовали бы отдельного issue (попутных дефектов
вне скоупа, которые нельзя было бы починить в этой ветке, не обнаружено).

## Что проверено и корректно

- Все 4 мутанта из ночного отчёта реально ловятся новыми/исправленными
  свидетелями — подтверждено исполнением `mutation-gate.mjs --id=…`, а не
  чтением реестра.
- Патч `node-boundary-splice-skips-new-edge-safety` сохраняет тот же runtime-
  эффект (условие статически ложно: `added.length < 0`), но больше не рушит
  сужение типов — `tsc` (в составе зелёного Validate) это подтверждает.
- Новый тест `#271/#272` в `test/wall-local-replacements.test.mjs` — не
  тавтология: встроенный отрицательный контроль (`untrimmed` vs `composed`)
  доказывает, что сама фикстура чувствительна к подрезке, в отличие от
  слепой фикстуры #834.
- Оба новых чек-пойнта смока (`capture_preview_stays_under_pointer`,
  `resize_history.*`) снимаются мутацией и проходят на чистом коде —
  проверено прогоном, а не только чтением `demo/smoke_resize_pointer_real_plan.mjs`.
- Подмена `_checkSpacePhysicalGeometry` в смоке ограничена вызовами из
  `_applyGeometryState` (по regex на стеке) и имеет отрицательный контроль
  (`wall-failed-core` остаётся строгим) — подмена доказанно читается, а не
  маскирует всё подряд.
- `markdownCodeRanges`/`proseLinkTargets` (scripts/reviews-archive.mjs:181,
  211) корректно разделяют fenced-блоки и inline-спаны произвольной длины
  обратных кавычек с учётом запрета пересечения пустой строки; `repairLinks`
  и `brokenLinks` используют один и тот же код диапазонов — на реальном
  дереве `brokenLinks()` возвращает 0.
- Трейлеры `Issue: #837` / `User-Visible: no` на всех 4 коммитах; `User-
  Visible: no` оправдан — видимого пользователю поведения карточки диффом не
  меняется (только тесты/инструменты/скрипты), changelog не требуется.
- `mutation-gate.mjs --check` и `process-gate.mjs` зелёные на материале.

## Чего не проверял

- Полный `npm run gate:small`, `pytest tests_backend`, golden, инварианты
  модели, `bundle-policy --verify` — не требуются этим диффом (ни один файл
  `src/**`/Python/геометрии не тронут; `smoke-select` подтверждает «нечего
  выбирать»), это предрелизный объём.
- Не проверял, действительно ли фикс #839 корректен сам по себе (это предмет
  отдельного ревью #839) — только факт параллельного существования и
  несовпадения реализаций.
- Риск автора: переименование `_applyGeometryState` сделает подмену в смоке
  немой (но заметной — упадёт контроль `wall-failed-core`) — принято как
  документированное ограничение, не находка.
- Риск автора: свидетель 3 опирается на то, что фикстура допускает сдвиг шва
  на +785 ед. — не проверял устойчивость к другим фикстурам, вне скоупа.

## Вердикт

High-находка о параллельном, нескоординированном дублировании #839 блокирует
слияние независимо от качества остального диффа (оно подтверждено
исполнением всех заявленных гейтов). Вердикт красный.
