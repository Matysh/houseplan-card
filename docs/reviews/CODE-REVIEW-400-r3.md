## Разбор находки M1 по коду

`src/houseplan-card.ts:825`:

```ts
const HANDLE_PAINT_ORDER = ['edges', 'corners'] as const;
```

и рендер (`:8480-8492`) вместо инлайновых `sides.map(...)` + `corners.map(...)`
в фиксированном порядке теперь итерирует `HANDLE_PAINT_ORDER`, диспетчеризуя на
`role === 'edges'`. Порядок для реального рендера не изменился (`edges` перед
`corners` — corners по-прежнему красятся последними и выигрывают хит), но
теперь это значение переменной, а не расположение блоков в шаблоне — то, что и
требовал вердикт r1.

`scripts/mutation-gate.mjs` (мутант `furniture-edge-handles-steal-the-corner`)
теперь патчит саму константу:

```diff
- find: '      ${/* #400: corners LAST.',
- replace: '      ${/* mutant: corners no longer last.',
+ find: "const HANDLE_PAINT_ORDER = ['edges', 'corners'] as const;",
+ replace: "const HANDLE_PAINT_ORDER = ['corners', 'edges'] as const;",
```

Прежний патч менял текст внутри JS-комментария — компилируемый код не менялся,
поэтому регрессия не воспроизводилась (`поймано 0 из 1`, найдено в r1,
подтверждено ещё раз в r2 независимо). Новый патч меняет порядок ролей на
`['corners', 'edges']`, отчего `edges` красятся последними и перехватывают хит
на мелкой мебели — именно то поведение, которое AC1 запрещает. Живой прогон
подтверждает: `поймано 1 из 1`, а смок-предусловие (`smoke_furniture_polish`)
на немутированном коде зелёное.

`demo/smoke_furniture.mjs` больше не берёт юго-восточную ручку по индексу
`handles[3]` (зависел от порядка отрисовки, что и уронило шард 3 CI на
`d153b20a`), а фильтрует по роли (`!dtrot && !dtedge`) и берёт третий элемент
массива `corners`. В исходнике `corners = [[-1,-1,'nwse'], [1,-1,'nesw'],
[1,1,'nwse'], [-1,1,'nesw']]` (:8466-8468) — индекс 2 действительно
юго-восточный угол (`sx>0, sy>0`). Комментарий смока («SE — второй `nwse`») и
код согласуются.

**M1 закрыта фактически, не только по утверждению автора.**
