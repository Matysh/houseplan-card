## Корректность и находки

Находок High/Medium/Low нет. Старый `grep -q` мог закрыть вход после первого
совпадения; SIGPIPE у пишущего `printf` делает pipeline неуспешным при pipefail.
Guard трактует это как снятие S7 и успешно заканчивает шаг с пустым stage.
Новый `grep -Fx ... > /dev/null` дочитывает поток и сопоставляет полную метку
буквально. Ошибка чтения/отсутствие метки не становятся разрешением запуска.

Тест исполняет извлечённый реальный шаг workflow с fake gh, а не копию логики
guard. Большой снимок вынуждает проявиться прежней ошибке. Исходные восемь
проверок выбора трека сохранены; улучшена только диагностика падения.
Отрицательные случаи требуют отказа при отсутствии S7, похожей метке,
blocked и review-4. Нет retry, отключения pipefail или ослабления oracle.

Ограничение вывода: точное планирование процессов, вызвавшее первоначальный
сбой на двух коротких метках, повторно не получено. Подтверждены механизм
уязвимости и тот же observable failure на расширенном снимке; это не обещание
отсутствия всех возможных причин нестабильности suite.
