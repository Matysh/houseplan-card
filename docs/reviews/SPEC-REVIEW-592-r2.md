## Что проверено в этом раунде (дельта)

1. **Новый абзац «Почему именно этот список эталонов»** — таблица покрытия по
   диалогам (Устройство 7 / Комната 2 / Общие настройки 3 / Пространство 1)
   пересчитана и совпадает с фактическим списком AC2: 3 `device-dialog-*` + 1
   `device-help-popover-*` + 1 `device-ripple-color-*` + 2 `toggle-entity-dialog-*`
   = 7 для устройства; 2 `room-temperature-dialog-*` для комнаты; `general-color-*`
   + 2 `settings-help-zoom-200-*` = 3 для общих настроек; 1
   `space-room-color-popover-desktop-ru` для пространства. Итого 13 эталонов в
   AC2 (12 из r1 + добавленный ripple) — сходится с телом issue.
2. **Три новых смока в AC1**, заявленные как компенсация единственного golden-кадра
   пространства. Проверено чтением каждого файла:
   - `demo/smoke_gear_tabs.mjs` — открывает `_spaceDialog` (строки 23-49),
     проверяет режим `create` (`_spaceDialog.mode === 'create'`) — реально
     задействует диалог пространства;
   - `demo/smoke_esc_dialogs.mjs:67-68` — вызывает
     `c._openSpaceDialog('edit', c._space)` и проверяет закрытие по Esc;
   - `demo/smoke_dialog_footer_width.mjs` — вызывает `_openSpaceDialog('edit', …)`
     дважды (desktop и narrow), измеряет `buttons`, `oneRow`,
     `noHorizontalOverflow`, `insideViewport` (строки 87, 139, 201-217) — реально
     проверяет структуру диалога пространства (число кнопок, отсутствие
     переполнения), а не просто факт открытия.

   Все три файла существуют, все три действительно открывают/используют
   `_spaceDialog`/`_openSpaceDialog`, заявление автора подтверждено чтением
   кода, а не принято на слово. Важная оговорка (не находка, а точность
   формулировки): эти три смока — функциональные/структурные проверки
   (число кнопок, переполнение, режим), не побайтовые сравнения кадра. Автор
   сам явно не относит их к AC2 (побайтовое совпадение), а держит в AC1 —
   формулировка в issue корректна и не выдаёт смок за замену golden-сравнения.
