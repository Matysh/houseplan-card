## Находка r2 и её закрытие

**Medium-1 (r2, в скоупе, возвращена в задачу):** дефект High-1 (двойное
масштабирование `roomPolygons`, из-за которого T-стык партиции к середине
комнатной стены не находился) был идентичен в двух местах —
`_mergeSpacePartitions` (карта) и `optimizePlans` («Оптимизировать планы») —
потому что каждый вызывающий строил геометрию примыканий самостоятельно.
Регрессионное покрытие защищало только путь оптимизатора; путь карты, который
r1 воспроизвёл вторым способом («в браузере через реальные клики»), не имел ни
юнита, ни мутанта.

## Что проверено и корректно

- `spaceMergeGeometry` — единственный источник геометрии примыканий для обоих
  путей; масштаб координат общий с партициями (без лишнего деления),
  исключение активного черновика — опционально и по умолчанию отключено
  (важно для пути оптимизатора, где активного черновика не бывает).
- Новые юниты (`test/wall-merge.test.mjs:214-262`) покрывают три вещи по
  отдельности: масштаб полигонов (включая `x/y/w/h`-комнату и комнату без
  геометрии), исключение черновика (обе ветки), сам T-стык — и делают это на
  уровне модуля, не дублируя мутационное покрытие смоком.
- Трейлеры коммита `fab0c38`: `Issue: #229`, `User-Visible: no` — верно,
  поведение продукта не меняется, правка рефакторит внутреннюю организацию;
  changelog не требуется и не тронут.
- Импорт `roomPoly` из `./logic` в `wall-merge.ts` не создаёт цикла зависимостей.

## Чего не проверял

- Полный набор смоков (127), `npm run golden:verify`, `python -m pytest
  tests_backend`, performance-профили — не задеты дельтой этого раунда (см.
  «Как проверялось»).
- Сценарий «комната через реальные клики» в смоке — автор honestly сообщил,
  что не взлетел (`_offerWallFaces` не даёт цепочке завершиться штатно) и
  оставил покрытие на юнитах общего модуля. Не блокирует: AC2 доказан юнитом
  на уровне `mergeCollinearPartitions`/`spaceMergeGeometry`, что достаточно —
  геометрия примыканий и механика предложения стен (`_offerWallFaces`) —
  разные слои, и дефект r1/r2 жил именно в геометрии. Если понадобится
  клик-путь через реальную комнату — отдельная работа поверх
  `_offerWallFaces`, не предмет этой задачи.
