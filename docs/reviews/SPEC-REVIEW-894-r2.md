## Как проверялось в r2

Повторный раунд — дельта, не задача целиком (§2.10). Проверено исполнением
там, где дельта это позволяет:

- `node scripts/review-preflight.mjs` → `specFormatErrors(body, 'ask', false)`
  выполнен напрямую на текущем теле issue (снятом через
  `gh issue view 894 --json body`): возвращает `[]` (PASS) — формат не
  пострадал от правки.
- Проверка по существу, а не по ключевому слову: новый раздел
  `### Влияние на производительность` называет бюджеты явно («Существующие
  bundle/initial/lazy ceilings, native input и perf budgets не поднимать»)
  — ровно формулировка DoR §2.5 «влияние на производительность и бюджеты
  названо (или явно «нет»)», а не общая фраза без содержания.
- Правдоподобие каждого из четырёх утверждений раздела сверено с текущим
  кодом на `dev` (не риск-выборка, а проверка выполнимости контракта,
  как и в r1):
  - «Lazy editor запрашивается один раз... без eager editor chunk» —
    `src/houseplan-card.ts:578-593` уже лениво импортирует
    `houseplan-editor-runtime` через `import()` за один вызов; контракт не
    требует новой инфраструктуры.
  - «Иконка группы использует общий registry-index/cache и не добавляет
    N×registry scan» — `isLightGroupEntity` (`src/devices.ts:848-854`)
    делает прямой lookup по `hass.entities[eid]`/`hass.devices[device_id]`,
    O(1) на вызов, без сканирования реестра; расширение на `kind ===
    'device'` (AC4) не меняет эту сложность.
  - «Version recovery использует существующий tick/deadline, без нового
    polling/interval» — `src/version-recovery.ts:331,341` уже содержит
    `_tick()`, вызываемый из существующего цикла; контракт не вводит
    второй таймер.
  - «Opening-info re-resolve только при config/context adoption» —
    согласуется с AC1/AC2 контрактом (re-resolve по `stable opening id`
    при authoritative config adoption, не на каждый pointermove); сам
    `_openingInfo` — объект, передаваемый по ссылке (подтверждено в r1 на
    `ef1aeaf6`), новый контракт не меняет модель хранения, только момент
    пересчёта.
  - Все четыре утверждения — выполнимые ограничения существующими
    механизмами, не новое обещание, которое код сегодня не может
    поддержать.
- `docs/reviews/INDEX.md:12` сверен — строка r1 присутствует с ожидаемым
  содержанием (жёлтый, 0 High, 1 Medium), дельта найдена по верной базе.
