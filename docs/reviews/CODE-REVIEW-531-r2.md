## Почему разбор полный, а не по дельте (§2.10, §7.2)

Между r1 и r2 ветку пришлось ребейзить на ушедший вперёд `dev`: после r1
`dev` принял #530 (печать плана), и слияние конфликтовало — конвейер сам
вернул задачу в `S6-in-progress` без траты цикла (комментарий 11:17:57Z),
автор сделал `git rebase origin/dev`, разрешил конфликт и вернул
`S7-code-review` (11:27:06Z). Это ровно случай из PROCESS.md §2.10: «ребейз
на ушедший вперёд `dev` — после ребейза это другой код», для которого
раздел прямо требует полный разбор, а не только находки.

Полный разбор ниже это подтверждает точечно: конфликт ребейза лежал
целиком в производных копиях (бандл-дерево, `docs/images/screenshots.json`,
построчное слияние обоих changelog) — ни один продуктовый файл `#531`
(`src/live-viewport.ts`, тесты, смок, мутанты, `docs/ARCHITECTURE.md`) в
конфликте не участвовал. SHA r1 (`57b80f08`) осиротел ребейзом — по корпусу
ревью (98 из 804) это обычное дело, а не находка (§2.10). Материал r1
недоступен для прямого `git diff` в этой рабочей копии (`git cat-file`
на `57b80f08` не резолвится, дерево `2b20dd807a08` не находится ни в одном
коммите текущего `git log --all`) — сверка сделана иначе: содержимое
`src/live-viewport.ts`, `test/live-viewport.test.mjs`,
`scripts/mutation-gate.mjs`, `docs/ARCHITECTURE.md` на `HEAD` построчно
сравнено с описанием в `docs/reviews/CODE-REVIEW-531-r1.md` (сохранён в
этой же ветке, коммит `af3be59a`) — совпадает без исключений, плюс единственное

## Скоуп

во время жеста панорамы SVG-сцена двигается CSS-трансформом, а `viewBox`

issue.
