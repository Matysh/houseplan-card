## Находки

Находок нет — ни High, ни Medium, ни Low.

Отдельно зафиксирую то, что специально искал и не нашёл, чтобы разбор был
проверяем:

- **Однозначность каждого AC.** Все 12 AC формулируют проверяемый результат
  (не намерение) и называют способ доказательства (`backend + unit`,
  `backend, включая HA harness`, `backend с параметризацией`, `negative-input
  cases` явно для AC7 и т.д.). Трассировка AC ↔ пункты контракта §4 полная:
  каждый пункт §4.1–4.4 и §5 покрыт минимум одним AC, пропусков не найдено.
- **Догадка, выданная за факт.** Не найдена: единственное предположение по
  протоколу (`vacuum_dock_restart_api`) прямо размечено в §15 как технический
  выбор, а не продуктовый факт; диагностический комментарий 12:20:26 explicitly
  не используется в ТЗ как доказанная причина репорта пользователя (§«Данные
  пользователя не блокируют эту фичу»).
- **Продуктовый вопрос, ошибочно вынесенный владельцу.** Не найден; §15
  содержит только технические допущения, которые ревьюер вправе оспорить, но
  ни одно не требует ответа «что видит пользователь» — на этот вопрос ТЗ уже
  отвечает самостоятельно.
- **Реализуемость контракта на существующей архитектуре.** Подтверждена
  чтением `trails.py`/`vacuum_path_collector.py`/`CONFIG-COMPATIBILITY.md`:
  привязка маркер→`vacuum.*`, состояние `docked`, capability-флаг,
  `plan-only`-перенос — всё уже существующие механизмы, а не новые
  недостижимые требования.
- **Согласованность с `docs/VACUUM.md`.** Не нашёл противоречий: контракт §4
  аккуратно надстраивается над существующим 30-минутным grace (`ensure_run`),
  не заменяет его общий алгоритм (явно оговорено в §4.1), сохраняет
  provenance-контракт #872 (§5) и route/source/map-проверку #918 (§4.4).
- **Терминология UI.** Названия переключателя, подписи и соседних элементов
  (§6) совпадают с реальными i18n-ключами, а не придуманы заново.

  краснеет» — требование код-ревью (§2.7) и к этапу spec не применяется.
- `npx tsc --noEmit`, `npm test`, `npm run build`, golden, смоки,
  `npm run invariants` — не прогонял: зависимости на spec-этапе намеренно не
  ставились (#696), диффа кода нет, гейтить нечего.
- Диагностический файл автора вне репозитория
  (`C:/tmp/hp940-analysis/test_issue940_analysis.py`) не перепроверялся
  исполнением — он размечен как «только для аналитики, не приёмка новой
  опции» и сам автор прямо пишет, что AC1–AC12 этим прогоном не закрываются;
  для вердикта ТЗ он не требуется как доказательство.

  накопления — вне скоупа этой задачи по прямому заявлению ТЗ («Данные
  пользователя не блокируют эту фичу»); не проверял и не требовал.
- DE/FR-переводы — ТЗ лишь обязывает их добавить «по действующей
  parity-политике» без указания точных строк; на этапе spec текста переводов
  ещё не существует, проверять нечего (это станет предметом код-ревью через
