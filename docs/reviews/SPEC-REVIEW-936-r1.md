## Скоуп

J4 («от нуля до рабочего плана») и J6 («plan stays true as the home evolves»)
по `docs/SCOPE.md` — задача делает существующий переносимый бэкап (#50, #875)
самодостаточным: один файл для переноса плана вместе с изображениями и уже
сохранённым снимком Zigbee-связей (J7-диагностика, не новое сканирование).
Персонажи и права соответствуют таблице `SCOPE.md`: административная
операция — desktop-first для «Home admin», обычные View/киоск и жесты не
меняются, что текст ТЗ прямо фиксирует («J4/J6 по SCOPE; обычный View и
киоск не меняются»). Не-скоуп явно исключает бэкап HA целиком, новые форматы
картинок, не-графические вложения, новое сканирование/историю Zigbee,
маршруты пылесоса, HA live states и токены/пароли HA — ни один из этих
пунктов не входит в перечень задач `SCOPE.md`, конфликта с «Out of scope»
нет. Раздел «Help/диагностика не меняется» прямо защищает #942 (диагностический
пакет) от расширения — соответствует его собственному скоупу.

## Находки

Находок, блокирующих приёмку (High) или требующих правки текста в этом
раунде (Medium), не обнаружено.

Отдельно рассмотренные и отклонённые кандидаты (чтобы не создавать видимость
поверхностной проверки объёмного текста):

- **Молчаливое исключение GIF.** `_MIME` в `http_api.py` содержит
  `.gif: image/gif`, а скоуп ТЗ перечисляет только «PNG/JPG/JPEG/WebP; SVG».
  Проверка: `FILE_EXTENSIONS` (реальная валидация загрузки) = `{pdf, png,
  jpg, jpeg, webp, txt}` — GIF никогда не был допустимым расширением
  загрузки ни для вложений маркеров, ни для decor (`ASSET_EXTENSIONS`), ни
  для планов (`PLAN_EXTENSIONS`). Запись в `_MIME` — не признак
  существующего пользовательского формата. Не нахожу: ТЗ не теряет
  реально используемый формат.
- **Количественные лимиты (2 GiB / 1600 записей) — не домысел ли это.**
  Это явно помеченный технический выбор автора («Числовые защитные лимиты
  выше выбраны автором; их нельзя молча повышать при реализации»), не
  выданный за факт. Сумма существующих агрегатных квот (`MAX_PLANS_BYTES`
  256 MiB + `MAX_FILES_BYTES` 1 GiB + `MAX_DECOR_ASSETS_BYTES` 256 MiB ≈
  1.5 GiB) укладывается в заявленные 2 GiB с запасом — числа не произвольны,
  решение корректно отнесено к разделу «принято предположительно».
  Не нахожу.
- **«Кому доступен ZIP» (Q2) — не скрыт ли битовый пограничный случай для
  `system-read-only`?** Таблица прав `SCOPE.md` и существующий `auth.py`
  уже исключают эту группу из писателей при любом значении настройки;
  пункт 1 контракта («права администратора проверяются… не только на
  кнопке») покрывает этот случай транзитивно через `may_write`/`is_admin`,
  отдельного продуктового решения не требуется. Не нахожу.
- **Отсутствие отдельного «технического вопроса, вынесенного владельцу».**
  Текст не содержит ни одного технического вопроса, переадресованного
  владельцу под видом продуктового — оба вопроса пачки (Q1, Q2) ровно
  продуктовые («что видит/разрешает пользователь»), что и требует §7.1.
  Блок «принято предположительно» в конце корректно собирает технические
  решения (контейнер v1, HTTP stream vs WS base64, порядок локов) без
  вынесения их владельцу. Не нахожу повода для «технический вопрос —
  замечание».
