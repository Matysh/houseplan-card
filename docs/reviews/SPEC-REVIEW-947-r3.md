## Находки

### Medium (в скоупе) — новый раздел «Документация» сужает объём правки `docs/RADAR.md` до одного подраздела, но в файле есть ещё одно прямое упоминание убираемого тумблера за его пределами

**Раздел ТЗ:** «Документация доступных профилей радара» (весь абзац, в
частности «docs/RADAR.md (Configure a radar)»).

**Суть:** новый текст ТЗ, в отличие от общей формулировки r2-находки, впервые
называет конкретное подмножество `docs/RADAR.md` — раздел «Configure a
radar» — как то, что меняется. Это сильная формулировка: ровно по такой же
логике, которой r2 обосновывал находку («раздел «Файлы и i18n» явно
перечисляет, что трогать… отсутствие в этом списке читается как «не
трогать»»), явное называние одного подраздела файла читается как ограничение
объёма правки этим подразделом — и ничем больше в том же файле.

Но `docs/RADAR.md` содержит ещё одно прямое упоминание убираемого тумблера —
в разделе «Troubleshooting», вне «Configure a radar»:

```
docs/RADAR.md:130-132
- **The section is absent:** only positively recognized hardware or an
  already saved radar gets the main section. Use the manual action for a
  custom real device. Virtual markers cannot own a radar binding.
```

«Use the manual action for a custom real device» — это именно тот ручной
тумблер («Additional actions → This is a presence radar»), который ТЗ
предписывает убрать из UI целиком («Ручной переключатель «Это радар
присутствия» удалён у всех устройств», раздел «Явная граница радара…»). Если
исполнитель правит буквально названный объём («Configure a radar»), эта
строка Troubleshooting останется без изменений: после релиза канонический
документ будет по-прежнему советовать пользователю, у которого «the section
is absent», использовать действие, которого больше нет в интерфейсе — то же
расхождение «canonical doc, который сам себе противоречит», которое r2
формулировал как причину находки, только теперь локализованное в одну
оставшуюся строку того же файла.

Для сравнения: в `docs/USER-GUIDE.ru.md` аналогичного риска нет — `grep -in
"радар|Это радар присутствия|Дополнительных действиях"
docs/USER-GUIDE.ru.md` показывает, что все упоминания (строки 1581, 1583,
1584, 1587, 1603, 1605) лежат внутри одного названного раздела «Радары
присутствия» (`:1581-1605`); узкое название раздела там ничего не оставляет
снаружи. В `docs/RADAR.md` текст проблемной строки физически находится в
другом разделе («Troubleshooting»), который «Документация» не называет.

**Почему это находка ТЗ, а не домысел реализации:** то же обоснование, что и
в r2, — AGENTS.md требует сверять терминологию видимого поведения с
каноническими документами при любом изменении этого поведения, а раздел
«Документация» — единственное место текста, которое перечисляет, что именно
в этих документах меняется. Узость этого перечисления (конкретный подраздел,
а не файл) — текстовое решение автора ТЗ, и именно оно создаёт пробел;
исполнитель, нашедший явно названный объём работ, не обязан по собственной
инициативе искать другие места того же файла.

**Чем краснеет:** не применимо как мутант — находка про полноту описания
объёма работы, не про защитное поведение кода. Подтверждение чтением:
`docs/RADAR.md:130-132` (текст Troubleshooting, вне диапазона «Configure a
radar» `:43-66`) против текста ТЗ «Ручной переключатель «Это радар
присутствия» удалён у всех устройств» и нового раздела «Документация…»,
называющего только «Configure a radar» — прямое текстуальное расхождение
объёма, видимое без исполнения кода.

**Предлагаемое исправление ТЗ:** расширить формулировку раздела
«Документация доступных профилей радара»: «…docs/RADAR.md (разделы
«Configure a radar» и «Troubleshooting» — в последнем убрать «Use the manual
action for a custom real device» как часть описания «The section is
absent») и раздел «Радары присутствия» docs/USER-GUIDE.ru.md…». Это
однострочное расширение объёма в тексте ТЗ, не требующее нового issue
(#202) — та же правка `docs/RADAR.md`, которую #947 уже обязан сделать,
просто без пропуска одной строки файла.
