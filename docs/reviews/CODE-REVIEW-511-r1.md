## Проверка AC по коду

**AC1** — `[green(older), red(newer)]→fail`; `[red(older), green(newer)]→success`; `[cancelled]→wait`; `[cancelled(newer), green(older)]→success`; незавершённый последний → wait; пустой список → wait.

Доказано автотестом `test/release-gate.test.mjs` (тест `#511: the latest non-cancelled run is the verdict…`), покрывающим ровно эти шесть пар плюс порядок-независимость и `latestRelevantRun` напрямую. Читкой кода (`scripts/release-gate.mjs:16-25`) подтверждено соответствие алгоритма формулировке AC: `latestRelevantRun` отбрасывает `conclusion === 'cancelled'`, сортирует по `run_started_at`/`created_at` (убыв.), при равенстве — по `id`; `classifyValidateRuns` возвращает `wait` при отсутствии/незавершённости последнего релевантного прогона, иначе `success`/`fail` по его `conclusion`.

Дисциплина «тест умеет падать» проверена не декларативно, а вручную для обоих заявленных мутантов — временно применил патчи `release-gate-counts-cancelled-runs` и `release-gate-oldest-run-wins` к рабочей копии `scripts/release-gate.mjs`, прогнал `node --test test/release-gate.test.mjs`, вернул файл (`git diff --stat` после отката — пусто):
- мутант «cancelled считаются» → `5 pass / 1 fail`;
- мутант «побеждает самый старый» → `4 pass / 2 fail`.

Оба мутанта ловятся тестом реально, не только по утверждению автора. **AC1 выполнен.**

**AC2** — `release.yml` не меняется, вызовы `release-gate.mjs` для Validate и Full Performance те же.

`git diff --stat origin/dev...HEAD` не содержит `.github/workflows/**` вовсе. Прочитан текущий `.github/workflows/release.yml:43` (`node scripts/release-gate.mjs "$SHA"`) и `:52` (`node scripts/release-gate.mjs "$SHA" --workflow=performance.yml --label=…`) — совпадают с состоянием до задачи, CLI-контракт скрипта (`invokedDirectly`-блок, `scripts/release-gate.mjs:80-95`) не менялся. **AC2 выполнен**, доказано чтением, не исполнением workflow (GitHub Actions здесь не прогонялись — сам гейт CI, его тело неисполнимо локально).

**AC3** — `docs/DEVELOPMENT.md` и `demo/performance/README.md` описывают новую семантику; доказательство — grep фраз в `release-gate.test`.

Тест `#511 AC3: the release documents describe the latest-run semantics` (`test/release-gate.test.mjs`) читает оба файла и проверяет: (а) `docs/DEVELOPMENT.md` содержит новую формулировку и не содержит старую («A missing, failed,\ncancelled or one-hour-timed-out Validate withholds»); (б) `demo/performance/README.md` содержит новую фразу. Прогнан — зелёный. Читкой самих файлов (`docs/DEVELOPMENT.md:356-363`, `demo/performance/README.md:121-127`) подтверждено, что текст не просто проходит regex, а содержательно верен: старая ложная фраза про `cancelled` удалена, новая описывает алгоритм «последний нетронутый cancelled прогон» с явной отсылкой на #511 и на прецедент v1.73.0.

Пограничное чтение AC3, отмеченное в spec-review r2 (правка существующей фразы vs добавление новой), разрешилось в пользу более безопасного варианта — добавления новой поясняющей фразы в оба файла без порчи соседнего контекста; расхождения между двумя чтениями не осталось: результат проверяем и корректен при любом из них. **AC3 выполнен.**

## Прочее замечаемое (не блокирует)
