# SPEC-REVIEW — issue #1000, заход r2

Материал: тело issue #1000, редакция 2 ТЗ (`bodyDigest` f1f163b269a50b831f4b07572641905131ba87b2751a10dbfdac58b0655613a5), дерево репозитория `42ea27f1243e30fcb3f3ec53b4633e81fa8fb8ae`, SHA `7de5bed0a5a4db86d0ca983501a7a524c1284d63`. Трек `ask`, этап `spec`. Учёт: заход r2, блокирующих циклов 1/4 (унаследовано из r1).

## Скоуп

Без изменений относительно r1 (см. `docs/reviews/SPEC-REVIEW-1000-r1.md`, раздел «Скоуп»): задача обслуживает J2 (расширение встроенной семантики тревог на произвольный показатель, которого HA не классифицирует как аварию), J5 (источник для CO₂/влажности/температуры), J6 (настройка живёт в существующем редакторе устройства). Поверхности: «Тревоги устройства» в настройках устройства, общая модель причины `threshold`/`external` в `device-issues`/`device-presentation`, карточка причин/предпросмотр (#972), маркер (Flat и 2.5D), агрегаты комнаты/сводки, бэкенд-валидация, JSON/ZIP-перенос, i18n RU/EN/DE/FR. Не входит: #1001 (сервисы `set_alert`/`clear_alert`), уведомления/автоматизации, произвольные цвета/иконки, AND/OR, комнатные/подписанные условия, редактируемая выдержка, процентный гистерезис.

Предмет этого захода — дельта между редакцией 1 (материал r1, `bodyDigest` 6a68b7b7…) и редакцией 2 (текущий `bodyDigest` f1f163b2…): два находки Medium (F1, F2) и их закрытие. Дельта не локальна по тексту (оба раздела переписаны с новым контрактом — visual anchor A1000-attention-r2 и виджет значения), поэтому ниже — не точечная сверка двух абзацев, а полный повторный разбор контракта поведения, UX-раздела, критериев приёмки и модели данных, с проверкой, что остальные части редакции 1, подтверждённые r1 как корректные, не разошлись с решениями владельца при переписывании.

## Как проверялось

Прочитаны по одному разу: `docs/SCOPE.md`, `AGENTS.md`, `docs/process/REVIEWER.md` (PROCESS.md — канон по ссылкам из конспекта). Прочитан полностью предыдущий отчёт `docs/reviews/SPEC-REVIEW-1000-r1.md` и материал раунда. Кодовый Validate на этапе `spec` не запускался — не требуется (REVIEWER.md, §8 PROCESS.md); продуктового кода в этой задаче нет (`changedFiles: []`).

Построчное сопоставление ТЗ с решениями владельца из текущих комментариев GitHub (не из авторского хендоффа):

- 6402981619 (аналитика S2→S3), 6415792068 (согласованный визуал, **явно** не закрывающий уровни: «В текущем макете нет выбора «внимание/тревога». Требования к двум уровням… этим согласованием не закрываются»), 6416063980/6416736234 (blocked на три продуктовых вопроса), 6417069616 (прямые ответы владельца: #1000 отдельно на общей `threshold/external` модели; добавить выбор уровня, по умолчанию «внимание»; до трёх правил, 3000 ms на включение/снятие, =/≠ для чисел и текста, остальные операторы — только число).

Текст редакции 2 передаёт эти решения без искажения: «отдельно на общей модели» → «Реализация threshold выполняется сейчас независимо от #1001» (Скоуп, п.3); «выбор уровня, default attention» → «level (внимание / тревога)… по умолчанию `attention`»; «до трёх правил, 3000 ms» → «До трёх сохранённых threshold-правил…», «Выдержка ровно 3000 ms для включения и снятия»; «=/≠ для текста, остальное только число» → «>/< /≥/≤ допускают только конечное число… =/≠ допускают конечное число либо непустую строку». Совпадает с уже проверенным в r1 переносом (строка «Что проверено и корректно» r1 не опровергнута новым текстом).

Это снимает находку F1 по её собственному критерию закрытия («либо явно описать конкретный переиспользуемый глиф, либо зафиксировать новый элемент с пометкой предположения»).
- Проверка раздела «Виджет значения»: сверено с исходным предложением «равно состоянию — второй столбец становится выпадающим списком состояний» (историческая секция, п.4) — текст редакции 2 восстанавливает ровно этот механизм для binary/enum (raw on/off, объявленные `attributes.options`, явные `unknown/unavailable`) и явно выделяет единственный случай свободного текста — атрибут/state **без** объявленного перечисления, с «текущим значением рядом» для визуальной защиты от опечатки. Это отвечает на «чем закрыть» из F2 буквально (подсказка с текущим наблюдаемым состоянием рядом с полем).

Автотесты/golden/смоки не запускались — продуктового кода по-прежнему нет, AC описывают будущую реализацию.

## Что проверено и корректно

- Оба Medium из r1 (F1, F2) закрыты в теле issue явными, самодостаточными решениями — не отговоркой и не перекладыванием вопроса на владельца; оба решения помечены как авторские (F1 — явно «принято предположительно», F2 — технический UX-выбор, не меняющий наблюдаемый пользователем контракт сверх уже одобренного constructor/table).
- Новый визуальный контракт A1000-attention-r2 определён достаточно детально для детерминированного Golden: четыре наблюдаемых состояния (только attention / только maintenance / оба / есть alarm), конкретные glyph/цвет/позиция/зазор, поведение Flat и 2.5D единое, поведение при отсутствии attention — пиксельно неизменное.
- Новый раздел о виджете значения не расширяет скоуп и не нарушает решение владельца «=/≠ для текста» — он уточняет **способ ввода** текста, сохраняя то же логическое сравнение (точное, с учётом регистра, 1–255 code points), и явно отделяет случай объявленного перечисления (dropdown) от случая без перечисления (text input с видимой подсказкой).
- Критерии приёмки AC1–AC8 по-прежнему называют способ доказательства без исключений; уточнения в «Виджет значения» и A1000-attention-r2 отражены в соответствующих AC (AC1/AC2 — текстовым уточнением сразу после раздела; AC4 — таблицей состояний A1000-attention-r2).
- Технические опоры новых утверждений существуют в материале: UI-Kit select/dialog/help-компоненты (`src/settings-select-control.ts` и смежные стили) реальны, не выдуманы.
