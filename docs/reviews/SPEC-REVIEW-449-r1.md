## Находки

### Medium (в скоупе — чинится в этом ТЗ, без него — жёлтый вердикт)

**M2. Строка `Touch editor: not exposed`, закрывающая M1, называет
несуществующий четвёртый редактор.**

Строка перечисляет «редакторы Плана, Устройств, **Декора** и **Подложки**»
(`docs/specs/449-double-fit-all.md:9-10`) — четыре разных существительных,
как если бы Декор и Подложка были двумя разными редакторами. Это не так:
`docs/USER-GUIDE.ru.md:201-206` называет ровно три редактора (План, Устройства,
Подложка); `docs/UX-MODES.md:186` прямо называет декор «the decor underlay» —
содержимым редактора Подложки/Background, не отдельным режимом;
`scripts/check-docs.mjs:115` normalizes «Decor editor» → «Background editor»
именно потому, что в проекте это два имени одного и того же редактора (внутри
код называет его `decor`, снаружи — «Подложка» / «Background editor»); и,
наконец, сама эта строка ссылается на §6 «Режимы» и AC7 того же файла, которые
оба перечисляют ровно три редактора: План, Устройства, Background
(`docs/specs/449-double-fit-all.md:180-188,279-285`).

**Воспроизведение:**
```
git show e027b2a0:docs/specs/449-double-fit-all.md | sed -n '9,12p'
git show e027b2a0:docs/specs/449-double-fit-all.md | sed -n '180,188p'
```
Первая команда даёт четыре редактора, вторая — три. Разночтение внутри одного
файла.

**Почему это находка, а не придирка к форме:** ровно это M1 из r1 просило
устранить — необходимость собирать вывод «какие редакторы затронуты» из
нескольких мест. Правка добавила единственную обязательную строку, но эта
строка сама разошлась с §6/AC7, на которые ссылается, — и внесла ложную
сущность («редактор Декора»), которой не существует ни в UI, ни в коде, ни в
каноническом словаре `docs/USER-GUIDE.ru.md`. Оставить как есть значит вернуть
ту же двусмысленность, которую M1 просило закрыть, только в обратную сторону
(лишний редактор вместо необходимого, но неявного вывода).

**Как чинится:** убрать дублирующее существительное, например: «редакторы
Плана, Устройств и Подложки (декора) его не получают» — либо просто «Плана,
Устройств и Подложки», раз термин «декор» уже пояснён как содержимое
Подложки в остальном тексте ТЗ (§2, «Что считается свободным фоном» и другие
места файла, не входящие в дельту, декор нигде не называют отдельным
редактором).

- **Реализацию** — её по-прежнему нет: диапазон `git diff origin/dev...HEAD`
  не содержит класса A/B, только `docs/**`.

  меняет ни одной строки кода.
- **`node scripts/check-docs.mjs`** — не гонял: диапазон не трогает `src/**`,
  и сам скрипт нормализует «Decor editor» только в `PUBLIC_DOCS` (README,
  USER-GUIDE), не в `docs/specs/**`, так что он не поймал бы M2 и не является
  подменой этой проверки.
- **Полный текст ТЗ вне зоны дельты** (сценарий, скоуп/не-скоуп, модель
  данных, риски, план автотестов, откат, release-артефакты) — не перечитывал
  заново; ничто из этого не зависит от добавленных четырёх строк, см.
  «Унаследовано из r1».
- **Q1/Q2/Q3 продуктовую историю** — не переоткрывал: решения владельца
  зафиксированы до r1 и дельта их не касается.
