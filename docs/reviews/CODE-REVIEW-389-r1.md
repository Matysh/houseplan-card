# CODE-REVIEW-389-r1

## Скоуп

Ревью code-этапа issue #389 (Matysh/houseplan-card), заход r1.

## Блокирующая проблема — ревью не выполнено

Ревью не может быть проведено по существу по двум независимым причинам:

1. **Тело issue #389 и комментарии недоступны.** Инструменты GitHub MCP
   (`mcp__github__get_issue`, `mcp__github__get_issue_comments`,
   `mcp__github__search_pull_requests`) вернули ошибку авторизации:
   "Claude requested permissions to use ..., but you haven't granted it
   yet." Разрешение запрошено дважды, не выдано. Без текста issue
   невозможно определить продуктовый сценарий, AC и способ доказательства
   — обязательные пункты по процессу (PROCESS.md §2.7, чтение п.3 в
   инструкции ревьюера).

2. **Материал для code-ревью пуст.** `git log --oneline origin/dev..HEAD`
   и `git diff origin/dev...HEAD` не показывают ни одного коммита или
   изменения: текущая ветка `dev` совпадает с `origin/dev` на SHA
   `32c70ecd`, рабочее дерево чистое. Поиск по локальным и удалённым
   ссылкам (`git branch -a`, `git log --all --grep=389`) не нашёл ветки
   или коммита, связанного с #389 (веток `issue/389-*` или аналогичных
   нет; grep по коммитным сообщениям на "389" ничего не дал, кроме
   несвязанного совпадения с "44" в другом номере).

Итог: нет ни текста задачи, ни диапазона кода, который эта задача должна
была изменить. Оценивать AC, инварианты, гейты или трейлеры не на чем —
любой вердикт кроме констатации блокера был бы фиктивным.

## Что проверено

- `git status`, `git log --oneline origin/dev..HEAD`, `git diff
  origin/dev...HEAD` — диапазон пуст.
- `git branch -a` — ветки для #389 не существует.
- `git log --all --oneline --grep=389 -i` — совпадений с содержательным
  коммитом по #389 нет.
- Попытка `mcp__github__get_issue`, `mcp__github__get_issue_comments`,
  `mcp__github__search_pull_requests` — все три отклонены отсутствием
  разрешения.

## Что не проверялось и почему

Всё содержательное: docs/SCOPE.md-обоснование, AC, дифф кода, статические
гейты (`tsc`, `npm test`, `npm run build`, `check-docs.mjs`), инварианты
модели, смоки, `golden:verify` — не проверялись, поскольку нет ни текста
задачи, ни диапазона кода для проверки. Прогон гейтов без diff был бы
бессмысленным (не над чем гейтовать).

## Рекомендация

Требуется человеческое вмешательство: (1) выдать разрешение на
GitHub MCP инструменты для чтения issue, либо предоставить текст issue
и ссылку на ветку/PR с кодом напрямую; (2) указать, на какой ветке/SHA
лежит код для #389, если он не влит в `dev` и не запушен в
`issue/389-*`.

До получения текста issue и диапазона кода вердикт не может быть
green/yellow в содержательном смысле — фиксируется как процессный блокер
(red), не как оценка качества кода.
