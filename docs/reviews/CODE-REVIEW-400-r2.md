## Находки

### Medium (в скоупе задачи — по-прежнему открыта из r1)

**M1 (перенесена из r1, не закрыта).** Мутационный гейт
`furniture-edge-handles-steal-the-corner` всё ещё не воспроизводит регрессию
AC1: патч правит текст JS-комментария в `src/houseplan-card.ts`, физический
порядок отрисовки `sides`/`corners` не меняется, «поймано 0 из 1» —
воспроизведено исполнением, идентично r1.

Дополнительно к находке r1: комментарий автора от 2026-08-31T05:14:07Z
заявляет закрытие с конкретными деталями (константа `HANDLE_PAINT_ORDER`,
переписанный патч мутанта, замена `handles[3]` на роль в `smoke_furniture.mjs`),
которых нет ни в одном коммите ни одной ветки репозитория — проверено
`git diff`, `git grep` по всей истории и `git fetch` удалённой ветки. Это не
новый дефект по существу (функциональность AC1/AC2 по-прежнему работает и
доказана живым смоком, унаследовано из r1), а расхождение между тем, что
записано в issue, и тем, что лежит в git. Возможные причины — потерянный push,
работа в незакоммיтированной рабочей копии, коммит на изолированной среде,
которая не долетела до `origin`. Это не блокирует зелёный вердикт сверх того,
что уже блокировала находка M1 сама по себе, но без исправления **само
исправление M1 остаётся фактически не начатым**, и владельцу до следующего
раунда стоит убедиться, что описанная в комментарии правка вообще существует
где-то за пределами текста комментария.

**Почему Medium, а не High**: тот же довод, что в r1 — сама функциональная
правка AC1/AC2 верна и доказана живым браузерным смоком, ломается только
постоянная защита от будущего отката (мутационный гейт), а не текущее
поведение продукта.

**Ожидаемо** (не изменилось с r1): патч мутанта должен реально возвращать
`corners` перед `sides` (или иным способом менять фактический порядок
рендера). Проверка приёмки: `node scripts/mutation-gate.mjs
--id=furniture-edge-handles-steal-the-corner` → «поймано 1 из 1», и это должно
быть видно в `git diff` этой ветки, а не только в тексте комментария.
