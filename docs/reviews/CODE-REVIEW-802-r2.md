# Локальное код-ревью #802 — r2, предрелизная совместимость

Вердикт: зелёный · High: 0 · Medium: 0 · маршрут: merge.

Материал: `ee351dcb8445d3f5c939a3c7761bee009634ceed` относительно
неопубликованного кандидата `c175a2ab1afd1a2a16da1a3dc04f5e1a4687149e`.
Полномочия — то же прямое исключение владельца, что в [r1](CODE-REVIEW-802-r1.md).
Это локальное саморевью с дополнительным независимым чтением дельты,
не результат недоступной штатной ревью-модели.

Полный [Validate 37358389278](https://github.com/Matysh/houseplan-card/actions/runs/37358389278)
остановил выпуск: `smoke_room_tooltip_toggle` обнаружил потерю явного
`room: false` у pointer-tooltip устройства. Сам tooltip был виден, но форма
объекта больше не совпадала с прежним `_showTip`. Падение воспроизведено
локально до правки. Неопубликованный кандидат не тегирован.

Исправление продукта — восстановление `room: false`. Чтением всех прежних
эффектов `_showTip` подтверждено: guards, modality и live-sync сохранены;
`lqi/temp/hum` остаются неопределёнными, старые значения не переносятся.
Фокус и tooltip комнаты не меняются. Старый smoke не ослаблен: добавлены
проверки, что tooltip действительно виден и содержит имя устройства.

На повторном локальном прогоне нового smoke встретился единичный CDP-сбой
`Resulting promise was garbage collected` при ожидании RAF-backed test facade.
Повтор на тех же исходниках прошёл, однако fixture исправлена по существующему
прецеденту `smoke_preloader`: Promise явно удерживается на fixture-объекте,
внешний polling ограничен 15 секундами, ошибка передаётся дальше, состояние
очищается. Переключение конфигурации вызывается ровно один раз; retries и
ослабление геометрических утверждений не добавлены.

Проверки:

  `2b841d94e4f34950f604a3e48aa061f4389d7e7e` — PASS, 0 упавших гейтов.
- WSL: `smoke_room_tooltip_toggle` и `smoke_touch_tips` — PASS.
- WSL: новый `smoke_zigbee_tooltip_layout` на итоговом `ee351dcb8` —

- Дельта не меняет пиксели подсказки; полный golden и performance первого
  кандидата были зелёными, но это не освобождает новый кандидат от полного
  exact-SHA Validate перед публикацией.

Остаточных находок по этой дельте нет. Прежний красный кандидат не выпускается;
после слияния требуется обновить fingerprint документации, release bundle и
заново проверить окончательный SHA.
