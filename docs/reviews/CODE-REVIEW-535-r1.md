# CODE-REVIEW-535-r1

Issue: #535 · Заход r1 · блокирующих циклов израсходовано 0/4
Материал ревью: `063de0eef4bfb96802e8ff94fcc0e35177cfde0b` (`origin/dev...HEAD`, один коммит `063de0ee`, база `1ca3b5fa`)

## Скоуп

Правка меняет один плагин сборки, `entryFallbackPlugin` в `scripts/bundle-manifest.mjs`:
панель (`houseplan-panel.js`) теперь импортирует реализацию карточки по
content-hashed адресу (`houseplan-assets/houseplan-card-<hash>.js`) напрямую, а не
через стабильный фасад `houseplan-card.js`, — устраняя единственный адрес в
дистрибутиве, по которому карточка отдаётся без токена версии. `try/catch` и
фолбэк («House Plan обновился — перезагрузите страницу», 4 языка) сохраняются;
при недоступном чанке теперь срабатывает панельный фолбэк, а не карточный внутри
живой панели.

Диапазон изменённых файлов: `scripts/bundle-manifest.mjs`, `scripts/bundle-tree.mjs`
(инвариант манифеста переформулирован под новую топологию), `scripts/mutation-gate.mjs`
(новый мутант + переоформление существующего), четыре тестовых файла
(`bundle-assets`, `bundle-freshness`, `bundle-sync`, `houseplan-zip`), `docs/ARCHITECTURE.md`,
оба `CHANGELOG`, три копии бандла (`dist/`, `custom_components/houseplan/frontend/`,
манифест `houseplan-assets.json`) и отпечаток скриншотов документации (только
отпечаток исходников, кадры не менялись).

По механическому признаку §1 диапазон файлов класса A не задет (только B/C/D) —
классификация полным треком по продуктовому доводу автора (видимое поведение
на устаревшем загрузчике) была спорной точкой ревью ТЗ r1 и признана
обоснованной; я согласен с этим выводом (см. «Ответ на продуктовый вопрос» ниже).

`src/**` не тронут вовсе — подтверждено `git diff origin/dev...HEAD --stat -- src/`
(пусто).

## Находки

### Low — L1: текст `console.error` панели изменён вопреки букве К2 ТЗ

`scripts/bundle-manifest.mjs`, панельная ветвь `entryFallbackPlugin`.

К2 ТЗ дословно: «Текст, четыре языка, класс элемента и `console.error` не
меняются.» Дифф меняет именно `console.error`:

```
- 'console.error("[houseplan] stale houseplan-panel.js: the card entry is unavailable",e)}',
+ 'console.error("[houseplan] stale houseplan-panel.js: the card implementation '
+ 'chunk is unavailable",e)}',
```

Это не покрыто ни одним тестом (ни один `assert` не проверяет содержимое этой
строки) и не названо в разделе «Отклонения от ТЗ — называю сам» хендоффа, хотя
там перечислены четыре других отклонения. По существу изменение оправдано:
после #535 недоступен именно chunk реализации, а не «card entry» — старый текст
стал бы неточным. Строка видна только в консоли разработчика, не пользователю,
и никак не входит в измеряемый функционал AC1–AC6.

**Решение ревьюера:** снимаю без цикла — фактическая точность лога важнее
буквы «дословно» применительно к диагностической строке, которую К2 явно
перечисляет вместе с пользовательским текстом (это, возможно, недосмотр самого
К2, а не сознательный контракт). Отмечаю как принятое отклонение, чтобы
дальнейшие ревью не искали здесь скрытую регрессию.

Других High/Medium/Low не найдено.

## Одно число — один источник

Дифф не добавляет и не меняет ни одной пользователем видимой величины
(строку с толщиной, площадью, размером и т.п.) — только адрес импорта и
служебные тексты (лог, комментарии, changelog). Проверка неприменима к этой
задаче.

## Что проверено и корректно

- **К1** — построчно: `dist/houseplan-panel.js` содержит ровно
  `try{await import("./houseplan-assets/houseplan-card-B09T8YNT.js")}catch(e){…}`,
  ссылок на `./houseplan-card.js` — ноль.
- **К2** — фолбэк (4 языка, класс элемента, стили) не тронут; см. L1 про
  единственное отклонение — сам текст лога, не сам фолбэк.
- **К3** — `dist/houseplan-card.js` не изменился по контракту: тот же
  `try{await import("./houseplan-assets/houseplan-card-B09T8YNT.js")}catch` в
  фасаде, отдельная функция `cardEntry`/`cardPattern` в диффе не тронута.
- **К4** — манифест и рантайм-валидатор согласованы: `initialPanelFiles` не
  содержит фасад, `initialViewFiles` (минус сам фасад) ⊆ `initialPanelFiles`,
  бюджет 2325 Б при потолке 8192 Б.
- **К5** — оба теста `#486` действительно перевёрнуты по смыслу (не
  подогнаны): `assert.doesNotMatch(panel, /houseplan-card\.js/)` появился там,
  где раньше стоял `assert.match` на тот же паттерн; переименование второго
  теста в `#535 …` оправдано сменой контракта, поведенческая часть (customElements,
  фолбэк) не ослаблена.
- **К6** — новый тест на весь дистрибутив плюс ручной `grep -rl
  "houseplan-card.js" dist/` подтверждают: во всём собранном дереве
  единственная ссылка на карточку без версии — она же сам стабильный вход,
  что и требуется контрактом (фасад продолжает существовать для Lovelace).
- **Мутанты** — все три названных автором (`panel-imports-unversioned-card-entry`,
  `panel-entry-bypasses-card-graph`, `panel-entry-fallback-rewrite-skipped`)
  лично перепрогнаны, каждый «поймано 1 из 1»; четвёртый пинned-тест
  (`#486 bundle topology and both stale entries have mutation witnesses`)
  подтверждает, что реестр не потерял старые id.
  Новый мутант `panel-imports-unversioned-card-entry` не входит в pinned-список
  `test/mutation-gate.test.mjs` — это нормально: список пиннует только уже
  существовавшие до #535 id, новый свидетель добавлять туда не требовалось.
- **Отклонения от ТЗ, названные автором** (файл `bundle-tree.mjs`, девять
  задетых фикстур, переоформление мутанта, отсутствие сдвига
  `initialPanelOnlyGzipBytes`) — все проверены по диффу и корректны; ни одно
  не ослабляет проверяемое утверждение (арифметика gzip-сумм в фикстурах
  `bundle-freshness`/`houseplan-zip` сходится: убранный из графа фасад вычтен
  из `initialPanelGzipBytes` ровно на его размер).
- **Документация**: `ARCHITECTURE.md` описывает ровно новую маршрутизацию и
  причину (единственный неверсионированный адрес, отсутствие
  `Cache-Control`, `immutable`-чанки); `CHANGELOG.md`/`CHANGELOG.ru.md`
  синхронны по смыслу, ссылка на #535 в обоих, `User-Visible: yes` в коммите
  соответствует правкам в обоих чейнджлогах в том же коммите. `USER-GUIDE.ru.md`
  не тронут и не должен быть: описывает только фасад карточки (К3, не
  изменился), к панели напрямую не относится.
- **Трейлеры и трассируемость**: один коммит, `Issue: #535`,
  `User-Visible: yes`, ветка `issue/535-panel-card-url` (хендофф) слита без
  дополнительных пушей — ровно то, что заявлено в хендоффе.
- **Сборка воспроизводима**: `node scripts/bundle-sync.mjs` поверх коммита не
  дал ни одного изменения в рабочем дереве — три копии бандла (`dist/`,
  `custom_components/.../frontend/`, стенд `demo/srv/assets/`) детерминированы
  и синхронны.

## Ответ на продуктовый вопрос автора

Автор спрашивает, согласен ли я, что громкое сообщение лучше тихой работы на
старом коде, и не стоит ли отдельной задачей различать «фронтенд новее» и
«бэкенд новее» в самой плашке. Согласен с первым — это и есть суть задачи, она
уже была продуктово одобрена на ревью ТЗ r1. Второе — разумное предложение, но
оно за скоуп #535 (и уже названо автором как таковое в ТЗ и аналитике); отдельным
issue его заводить не обязываю, это на усмотрение владельца/автора при следующей
итерации плашки.

- Поведение в реальном Home Assistant (proxy-кэш, заголовки боевого стенда) —
  вне возможностей код-ревью; измерения из issue (заголовки боевого стенда)
