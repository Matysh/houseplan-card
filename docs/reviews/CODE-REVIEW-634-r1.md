# CODE-REVIEW-634-r1

Issue: #634 — «Стоимость входа агента ≈ 43 k токенов до первого файла кода: ролевые
конспекты PROCESS, индекс TESTING.md, генерируемый STATUS.md».
Этап: code · заход r1 · блокирующих циклов израсходовано 0/4.
Материал: коммит `7dc7597260239f63a25a4f4538dbac3bd67072a5` (один коммит поверх
`fe92ce06`, уже на `dev`-линии). Рабочая копия проверена ровно на этом SHA;
`git fetch`/`checkout` на другой коммит не выполнялись.

## Скоуп

Класс задачи — B/C (инфраструктура/документация): `.github/workflows/process.yml`,
`AGENTS.md`, `PROCESS.md`, `docs/DEVELOPMENT.md`, `docs/STATUS.md` +
`docs/STATUS-FEATURES.md` (новый), `docs/TESTING.md` + `docs/testing-notes/*`
(8 новых файлов), `docs/process/AUTHOR.md` + `REVIEWER.md` (новые),
`docs/TESTING-DEMO.md`, `scripts/entry-cost.mjs`, `scripts/status-snapshot.mjs`,
`scripts/md-anchors.mjs`, `scripts/inventory.mjs`, `scripts/check-inputs.mjs`,
`scripts/mutation-registry.mjs`, четыре новых тестовых файла. Ни одного файла
класса A — подтверждено чтением `git show --stat`. Задача не обязана служить
строке `docs/SCOPE.md` (это процесс/инструменты, не продуктовая фича); ей
корректно присвоены метки `process` и `tech-debt`, без `S*` до первого
`S7-code-review` — по правилу для инфраструктурных задач.

Предмет: три AC из тела issue —
AC1 (вход автора по маршруту ≤ 12 000 слов, замер скриптом),
AC2 (каждый пункт ролевого конспекта ссылается на существующий раздел канона),
AC3 (`TESTING.md` ≤ 800 строк, приложения по индексу) —
плюс заявленные в хендоффе побочные правки: генерируемый Snapshot в
`docs/STATUS.md`, сокращённый промпт ревьюера в `process.yml`, порядок чтения по
роли в `AGENTS.md`.

## Что проверено и корректно

- Класс изменений — B/C, файлов класса A нет; правило «инфраструктурная задача —
  сразу в ветку, без ТЗ» соблюдено, метка `S7-code-review` корректна.
- `PROCESS.md`: **ни одно правило по существу не изменено** — диф ограничен
  абзацем о конспектах в шапке и уточнением про промпт ревьюера в §10.4;
  сверено построчно.
- Ролевые конспекты (`docs/process/AUTHOR.md`, `REVIEWER.md`) — каждый пункт
  верхнего уровня ссылается на существующий якорь `PROCESS.md`, ключевые
  формулировки дословны и лежат в названном разделе (проверено тестом и
  выборочно вручную по нескольким пунктам — трейлеры, лимит циклов, шесть
  классов риска, «одно число — один источник», запрещённое).
- `scripts/md-anchors.mjs` строит якоря по алгоритму GitHub без схлопывания
  дефисов (сознательно отличается от `check-docs.mjs`, комментарий это
  объясняет) — по построенным тестам расхождений не найдено.
- `scripts/entry-cost.mjs`/`test/entry-cost.test.mjs` держат маршрут автора и
  `AGENTS.md` («Reading order by role») в синхроне машинной сверкой списков
  файлов и их порядка, а не на слово автора.
- `scripts/status-snapshot.mjs`: версии берутся из `parseVersionSources`
  (`release-contract.mjs`, не тронут), счётчики — из вынесенной в отдельную
  экспортируемую функцию `testInventory` (`scripts/inventory.mjs`, CLI-вывод при
  прямом запуске не изменился), рассинхрон версий не сглаживается, а
  показывается текстом «NOT synchronized: …». `--check` намеренно не в CI —
  причина документирована в самом скрипте и подтверждена наблюдением (счётчик
  тестов уже разошёлся на 20 всего за несколько влившихся задач).
- `docs/TESTING.md` → `docs/testing-notes/*`: перенос дословный (независимая
  построчная сверка, расхождение только в заголовке и разделителе),
  `test/golden-matrix.test.mjs` обновлён читать индекс с приложениями и
  реально проходит (id `#242`/`#250` резолвятся из `geometry.md`).
- `docs/STATUS.md` → `docs/STATUS-FEATURES.md`: раздел «feature surface»
  перенесён дословно (независимая построчная сверка), таблица «Standing state
  and decisions» сохранила все прежние строки, кроме `Version` (ушла в
  генерируемый Snapshot).
- `scripts/inventory.mjs`: рефакторинг в чистую экспортируемую функцию не
  изменил CLI-поведение (monolith-блок и структура вывода на месте), снятие с
  `NOT_AN_INPUT` подтверждено зелёным `check-inputs.mjs --coverage`.
- Промпт ревьюера в `process.yml` сокращён с делегированием правил в канон и
  конспект; все примеры-прецеденты (#150, #102, #403, #234, #233, #237, #244,
  #252–259) остались в `PROCESS.md` §2.10/§8, а не исчезли вместе с текстом
  промпта — сверено чтением обеих версий. Битая ссылка «§2.9» → «§2.10»
  действительно исправлена.
- Трейлеры коммита корректны: `Issue: #634`, `User-Visible: no` — оправдано
  (нет пользовательского поведения), changelog не требуется и не тронут.
- Метамомент: этот самый прогон ревью выполняется по **старому** промпту
  `process.yml` (ссылка на «§2.9», а не «§2.10» в системном приглашении этой
  сессии) — ровно то расхождение, которое хендофф объявляет ожидаемым
  («`process.yml` исполняется из `main`», нужно зеркало после слияния). Это
  независимое наблюдение подтверждает точность авторского отчёта, а не
  находка против задачи.

  прогонялись вручную по одному — проверены только регистрацией id без
  коллизий и структурным сходством с двумя вручную подтверждёнными; будь один
  из них некорректен по существу (например, `find` не находит целевую строку),
  это не изменило бы вердикт этого раунда, но стоило бы отметить при полном
  прогоне `node scripts/mutation-gate.mjs --check` (не выполнялся — дорогой
  гейт, не гейт ревью при отсутствии диффа в исполняемом продуктовом коде).
- Живой прогон конвейера новым промптом — по документированной причине

  предмета ревью.
