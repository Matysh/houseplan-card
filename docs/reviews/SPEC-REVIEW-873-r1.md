# SPEC-REVIEW-873-r1

**Issue:** #873 — «Редактор устройств: магнит равных интервалов и подсветка одинаковых расстояний в ряду»
**Этап:** spec (PROCESS.md §2.4) · **Трек:** ask · **Заход:** r1 · блокирующих циклов 0/4
**Материал:** тело issue #873, раздел `## ТЗ`, редакция 2 от 14.10.2026 (сверена автором с `origin/dev ee6717a8`); рабочая копия ревьюера на `ca1e58cc` (docs-only коммиты поверх `ee6717a8`, продуктовый код не менялся — см. «Как проверялось»).

## Скоуп

Новый магнит равных интервалов + визуальная подсказка двух промежутков при
перетаскивании значка в редакторе устройств (десктоп). По `docs/SCOPE.md` —
J4/J6 (аккуратное GUI-размещение, поддержание плана). View/киоск не
затрагиваются (контракт п.12 / AC8). Вне скоупа явно: наклонные ряды,
вставка внутрь ряда, групповое распределение, сущность «ряд», переключатель
магнитов, магнит к стене/«прилипание» (#866 — отдельная задача, явно не
блокер и не предпосылка).

## Находки

Не найдено ни одной находки High или Medium. ТЗ однозначно по каждому из
восьми критериев приёмки, способ доказательства назван для каждого (unit
модуль + `node --test`, smoke на реальных PointerEvent, явный столбец «чем
краснеет на dev / мутант» без единого пустого значения), контракт поведения
закрывает все пункты из раздела «что обязательно разобрать» запроса
владельца (определение ряда, третий/четвёртый участник, перенос внутри
ряда, центры/края, конфликты с сеткой/направляющими/магнитом к стене,
управление, порог захвата, визуал, жизненный цикл, производительность,
touch, доказательство) явной строкой контракта или UX-раздела. Открытых
продуктовых вопросов нет, и это подтверждается историей issue, а не только
заявлением в теле: оба вопроса (измерение между центрами; только Г/В ряды)
закрыты владельцем предметно 12.10.2026, независимость от #866 — отдельным
решением владельца того же дня. Технических споров автор/ревьюер не
возникло: раздел «Следствия канона, принятые в редакции 2» воспроизводит
действующий канон (`CANVAS.md` §9.3–9.4) без искажения, оспаривать нечего.
