## #763 — Киоск: диалог масштаба грузит весь рантайм редактора

Коммит: `083d4d6e3324b9f74e3cb61aa0aea2f1a707923a` (один, патч-набор
`b19fada391be7d2c4a3e648feb5d2551e78f74c1` — совпадает с `ship-issues.json`,
проверено `git show <sha> | git patch-id --stable`).

### Что проверил

- **Чтение диффа** (`git show <sha>`). Правка в `src/houseplan-card.ts` —
  ровно одна удалённая и одна добавленная (комментарий) строка внутри
  многострочного выражения `editorRuntimeRequested` (строки 10697–10707):
  убран `this._kioskDialog` из списка диалогов, требующих редакторский
  рантайм. Жест открытия (`3 s hold`, строка 6755), сама отрисовка диалога
  (`_renderKioskDialog`, строка 10603) и запись масштаба (`_saveKioskScale` →
  `this._summary?.saveScale`, строка 10600) не тронуты — соответствует
  заявлению «the loader and the gesture are untouched».
- **Проверка правильной переменной.** В исходнике рядом две похожие
  конструкции — `onboardingRuntimeRequested` (10695) и
  `editorRuntimeRequested` (10697); по diff context могло показаться, что
  правка задевает `onboardingRuntimeRequested` (следующая строка после
  изменения — `if (onboardingRuntimeRequested …)`). Прочитал файл целиком
  (`Read` строк 10690–10714 на кандидате) — убрано именно из
  `editorRuntimeRequested`, как и написано в теле коммита. Ложная тревога
  снята.
- **Проверка отсутствия скрытых зависимостей от editor runtime.**
  `_renderKioskDialog` использует только `hp-dialog` (core), `this._t` (core
  i18n) и `_saveKioskScale` → `this._summary?.saveScale` —
  `summary-panel-runtime`, отдельный от editor runtime модуль
  (`SummaryRuntimeSlot`, строка 2226), который подключается при монтировании
  любой карточки независимо от этой правки. Подтверждает тезис ТЗ и коммита,
  что диалог не нуждается в editor runtime вовсе.
- **Побочный контур не спутан.** `_kioskDialog` остался в
  `_editorSecondaryDialogBlocked` (строка 8693–8702, не изменено этим
  коммитом) — это блокировка одновременного открытия вторичных диалогов
  редактора, а не условие загрузки рантайма; трогать его не требовалось.
- **Единственность точки мутанта.** Строка-цель нового мутанта
  `kiosk-scale-dialog-loads-editor-runtime`
  (`|| this._vacFit || this._vacCalConfirm);`) встречается в
  `src/houseplan-card.ts` ровно один раз — патч однозначен.
- **Рамки `track:ship`.** `git show --unified=0 -- 'src/**'` — 1
  удалённая/1 добавленная строка в одном файле, без новых файлов, ключей
  i18n, полей конфига и Python. В рамках (лимит 30 строк). Класс риска по
  `scripts/change-risk.mjs` (прогнан вручную на `git diff --unified=0
  <sha>^..<sha>`) — пустой: `classes: []`, `raising: []`. Правка не выходит
  из трека ship ни механически, ни по смыслу: это однострочная правка
  условия ленивой загрузки, без нового UX-контракта, геометрии, конфига или
  измеримого перф-бюджета — сама суть ТЗ в том, чтобы убрать лишнюю загрузку,
  а не добавить новую поверхность.
- **`npm test`** — зелёный на кандидате: 3871 passed, 1 skipped, 0 failed
  (3872 всего).
- **`node scripts/smoke-select.mjs --base <sha>^ --head <sha>`** — прямое
  совпадение по символам диффа (`_kioskDialog`, `_vacFit`, `_vacCalConfirm`):
  `smoke_kiosk.mjs`, `smoke_lazy_editor_chunk.mjs`, `smoke_version_recovery.mjs`,
  `smoke_vacuum*.mjs`, `smoke_danger_confirm_branches.mjs`,
  `smoke_editor_gestures.mjs`; зарегистрированная связь —
  `smoke_kiosk_scale_no_editor.mjs` (новый, назван строкой ТЗ напрямую).
- **Реестр мутантов.** Новая запись `kiosk-scale-dialog-loads-editor-runtime`
  добавлена в `scripts/mutation-registry.mjs` и учтена в
  `docs/testing-notes/mutation-browser-guards.md` (счётчик 243→244, раздел
  «Custom-element and HA browser lifecycle» 104→105 — согласовано).
  `node scripts/mutation-gate.mjs --check` проходит (структурная проверка
  реестра; сам мутант, как и положено на этом треке, не гонялся — §11.7,
  «мутанты в разработке не гоняются ни на каком треке»).
- **Changelog и трейлеры.** `User-Visible: yes` и `Issue: #763` на коммите;
  `docs/CHANGELOG.md` и `docs/CHANGELOG.ru.md` получили согласованные записи
  в одном коммите — требование §3 п.10 выполнено.
- **Прочитал содержимое нового смоука** `demo/smoke_kiosk_scale_no_editor.mjs`
  целиком: холодная страница, реальный 3.4 с touch-hold через CDP
  `synthesizeTapGesture` (не клик по новому backdrop), движение слайдеров
  клавиатурой, Reset/Close, повторное открытие с сохранённым масштабом,
  контроль — обычный вход в редактор вне киоска по-прежнему запрашивает
  чанк, и негативная проба — чанк отклонён сетью, диалог всё равно работает
  и уведомление «не удалось загрузить редактор» не показывается. Сценарий
  покрывает именно формулировку ТЗ: «доказать smoke-тестом холодного киоска,
  что диалог работает без запроса editor-чанка, а обычный вход в редактор
  вне киоска по-прежнему загружает его».
- **Правка `smoke_lazy_editor_chunk.mjs`.** Случай (a) («Kiosk: a 3 s hold…»)
  раньше фиксировал старый (ошибочный) цикл — 2 запроса чанка и 1 уведомление
  при недоступной сети; теперь утверждает 0 запросов и 0 уведомлений, с
  явной ссылкой на #763 и на новый подробный смоук. Согласовано с фиксом, не
  противоречит.

### Находки

Нет. Код делает ровно то, что написано в строке ТЗ, не трогает соседнее
поведение (жест, значения масштабов, Reset, Close) и не выходит из
механических и смысловых рамок трека `ship`.

### Чего не проверял

- **Браузерные смоуки не исполнены.** Песочница ревью не резолвит домен
  `demo.local`, которым пользуется `demo/serve.mjs` (`getaddrinfo EAI_AGAIN
  demo.local`); тот же таймаут с идентичной ошибкой воспроизводится и на
  заведомо не тронутом этим коммитом `demo/smoke_kiosk.mjs` — это ограничение
  окружения ревью, а не дефект задачи или регрессия со стороны правки.
  Корректность доказана чтением (`_renderKioskDialog`, `_saveKioskScale`,
  условие `editorRuntimeRequested`) и структурными проверками
  (`smoke-select`, `mutation-gate --check`, `npm test`), а не исполнением
  нового смоука и мутанта в браузере.
- **Полный набор смоков/golden/perf** — не прогонялся: вне объёма пакетного
  ревью ship (§8, §11.7 — полные наборы являются предрелизным гейтом) и не
  затронут этой правкой (нет меток `ci:full`/`ci:golden`, класс `visual` не
  определён).
- **`typecheck` / `npm run build` / `bundle-policy --verify`** отдельно не
  гонял как самостоятельный гейт после ревью (сборка выполнялась только для
  попытки локального смоука и была откачена `git checkout -- . && git clean
  -fd` вместе с сопутствующим изменением `dist/`); зелёный Validate на SHA
  кандидата, упомянутый во входе ревью, принимается как источник этих
  дешёвых гейтов (§8).
