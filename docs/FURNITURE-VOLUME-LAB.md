## Источник модели

Исходные рисунки обычного плана в `assets/furniture/houseplan-0.4.1/svg/plan`
не изменяются. Рядом в `svg/volume` находятся сопровождающие SVG с теми же ID:
все 60 моделей каталога. Принятые `sofa`, `coffee_table`, `bed_double` остаются
в схеме 1, остальные 57 используют схему 2. Сохранённый план по-прежнему содержит
symbol, координаты, размеры, угол и отражения. В него не записывается объёмная сетка.

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 180 90"
     data-hp-volume-schema="1" data-hp-model="sofa" data-hp-back="top">
  <rect data-hp-part="seat-left" x="25.2" y="22.5"
        width="64.8" height="57.6" rx="5.4" data-hp-radius-ratio="0.06"
        data-hp-z-min-cm="29" data-hp-z-max-cm="44" />
</svg>
```

Это иллюстрация формата; фактические размеры берутся из SVG модели.

| Поле | Договор схемы 1 |
| --- | --- |
| `viewBox` | `0 0 width_cm depth_cm` из каталога; координаты в сантиметрах |
| `data-hp-model` | Точный ID существующего предмета |
| `data-hp-part` | Уникальный стабильный ID детали внутри модели |
| `x/y/width/height` | Замкнутый прямоугольный footprint детали, внутри общего footprint |
| `rx` | Радиус скругления в исходном SVG |
| `data-hp-radius-ratio` | Радиус относительно меньшего габарита всего предмета; `rx = ratio × min(viewBox W,H)` |
| `data-hp-z-min-cm` | Нижняя отметка детали от пола, не меньше нуля |
| `data-hp-z-max-cm` | Верхняя отметка, строго выше нижней |
| `data-hp-back` | `top`: задняя сторона у верхнего края исходного рисунка |

Схема 1 поддерживает только самозакрывающиеся `rect`. Произвольные path,
отверстия, группы, скрипты, внешние ссылки и дополнительные атрибуты
не поддерживаются и останавливают генерацию. Максимум 96 деталей на модель.
Это совместимый формат для трёх уже принятых рецептов.

## Схема 2: остальные 57 моделей

Те же единицы, ID и диапазоны высот; корневой `data-hp-volume-schema="2"`.
Разметка описывает отдельные физические детали, а не одинаковую экструзию
всего рисунка. Исходный Flat используется для сверки контура и ориентации.

| Поле / примитив | Значение |
| --- | --- |
| `rect` | Скруглённый замкнутый профиль; радиус ограничивается меньшей стороной профиля |
| `ellipse` | `cx/cy/rx/ry`; круги и овалы, без прямоугольной подмены |
| `polygon points` | Простой замкнутый контур, 3–48 вершин; допускается вогнутый |
| `data-hp-hole-points` | Один простой внутренний контур polygon, строго внутри внешнего |
| `data-hp-plane` | `xy` по умолчанию; `xz` или `yz` для rect/ellipse с вертикальным профилем |
| `data-hp-inset-cm` | Толщина обода rect/ellipse; образует сквозное отверстие с внутренними стенками |
| `data-hp-base-scale` | Масштаб нижнего контура XY вокруг центра, 0.05–1 |
| `data-hp-top-scale` | Масштаб верхнего контура XY, 0.05–1 |
| `data-hp-top-offset` | Смещение верхнего контура относительно ширины/глубины детали; он остаётся в её границах |

Для XY профиль лежит в плане и вытягивается между Z-min/Z-max. Для XZ
профиль занимает X и Z, а глубина Y задаёт толщину; для YZ аналогично.
Polygon с вертикальной осью пока отклоняется валидатором. Скрипты, внешние
ссылки, произвольные path/transform и неизвестные атрибуты запрещены.
Самопересечения, выход отверстия наружу и неположительная толщина — ошибка
сборки. Отверстие не заливается: кольца имеют противоположный обход.

Правила семейств:

- Сиденья ниже спинок и подлокотников; ножки, основание, подушки отдельны.
  У барного стула круглый профиль сиденья и изогнутая спинка по Flat SVG.
  Спинка офисного кресла — цельная вертикальная деталь XZ, не верхняя планка.
- Кофейные столы ниже обеденных. Четыре ножки соответствуют исходному
  рисунку; круглые, капсульные и скруглённые столешницы различаются.
- Шкафы состоят из стенок, полок и фасадов. Открытые полки остаются пустыми;
  навесные секции имеют ненулевую высоту установки, показанную в галерее.
- Сантехника имеет дно, чашу, обод и внутренние стенки; закруглённый передний
  край не подменяет прямую заднюю сторону. Угловая ванна имеет секторный контур.
- У техники экраны, люки, ручки и корпуса отдельны. Люки вытянуты по XZ,
  вытяжка сужается вверх. У плиты и навесных приборов записана отметка установки.
- Лестница состоит из 13 ступеней разной высоты; ковёр остаётся тонким.
  Растение и тренажёр — условные объёмные модели, согласованные по назначению.

Высоты являются визуальными значениями прототипа, не данными производителя.
Пиктограммы назначения на Flat (вешалка, снежинка, посуда) не превращаются
в физические выступы. Материал всех моделей остаётся общим матовым стеклом.

Смежные видимые полосы боковой поверхности объединяются; повторные вершины
капсул удаляются, чтобы боковина не обрывалась. Тень новых моделей строится
по общей проекции деталей, включая вогнутость, без прямоугольника вокруг.
Для трёх принятых моделей геометрия, материал и тень сохранены точно.

При изменении W/H масштабируется footprint и радиус; высоты сохраняются.
Поворот и оба отражения применяются к общей исходной системе координат.
Существующий масштаб высоты сцены, порядок граней, стеклянный материал,
цвет, прозрачность и тень сохранены. Никаких отдельных высот для галереи нет.

## Сборка и загрузка

1. Править SVG в `svg/volume`.
2. `npm run furniture:volume:generate` генерирует реестр и каталог галереи.
3. `npm run furniture:volume:check` проверяет соответствие без записи.
4. `npm run bundle:sync` собирает продуктовый бандл и локальные demo assets.
5. `npm run ui-lab:gallery:build` собирает самостоятельную страницу галереи.

Обычная сборка отклоняет устаревший сгенерированный реестр. Невалидный SVG
не превращается в молча пропущенную деталь. Runtime не парсит SVG: один
лениво загружаемый модуль используется через `furniture-volume-runtime.ts`.
Fingerprint должен совпасть с основной сборкой. При ошибке загрузки или
несовпадении остаётся штатный плоский рисунок; данные плана не меняются.
Повтор загрузки — после перезагрузки страницы.

Общий путь: SVG → генератор → `furniture-volume.generated.ts` →
`iso-lab-furniture.ts` → `iso-lab-furniture-render.ts`.
Галерея и сцена импортируют эти же модули. Сборка галереи отдельная:
контракт двух продуктовых entry и штатный bundle manifest сохранены.

- 96 точных сравнений сеток до/после миграции: 3 модели × 4 ракурса ×
  4 сочетания отражений × 2 пропорции, с поворотом предмета 23°.
- 1920 комбинаций для всех 60 моделей: 4 камеры × 4 сочетания отражений ×
  2 пропорции; конечные координаты, видимые грани и неизменность входного decor.
- 49 целевых тестов: дополнительно полости, вертикальные профили, сужение,
  семейства высот, непрерывные боковины и исправления обеих спинок.
- Проверки схемы, отрицательных высот, несовпадающих ID, повторных частей,
  выхода за footprint, активного XML, загрузки/ошибок реестра и fingerprint.
- Существующие проверки transform-контракта, плоского арта и его runtime.
- Визуальные результаты и логи находятся в соседнем `ui-lab-furniture/evidence`.

Все 60 предметов просмотрены в галерее. Пересечения соседних предметов,
сложный порядок прозрачных граней в общей сцене, `width_cm`, редактирование,
