# UI-059 — окна, двери и ворота #1024, согласовано 12.11.2026

Решение владельца: «Отлично, теперь всё ок. Фиксируй текущую версию окон и дверей со всеми правками в журнале и актуализируй ТЗ в #1024.»

Это итог всей итерации на штатном плане UI Lab, включая последние 3 см и изменение угла направляющих. Промежуточные рисунки не являются эталоном. Согласованы интерфейс и визуальное поведение, продуктовая реализация и её проверки ещё предстоят.

## Настройки окна

- Окно содержит 1–4 равные створки, две по умолчанию. При обновлении сохраняются число, геометрия, положение, ориентация и прежние связи существующих окон.
- В свойствах окна — список створок, по строке на каждую, плюс/минус. Плюс неактивен при четырёх, минус при одной; ограничение объясняется штатной подсказкой UI Kit, без системного title.
- Строка открывает настройки одной створки внутри того же диалога. «Готово» возвращает в список с изменениями черновика; «Отмена», Escape и крестик отменяют изменения этой створки. Сохранение всего окна — только общей кнопкой.
- При удалении настроенной створки — подтверждение потери её настроек. Ширина оставшихся долей пересчитывается поровну, их идентичность и связи сохраняются.
- Направление «Открывание» находится на уровне окна, одинаково для всех существующих и новых створок. Внутри створок его нет.
- При комнате только с одной стороны варианты «Внутрь» / «Наружу»; при комнатах с двух сторон — «В комнату „…“». При неопределимой стороне — нейтральные «К стороне A/B», без выдуманной комнаты.
- В настройках створки — небольшое превью всего окна в той же ориентации, что на плане; текущая створка выделена акцентом HA. Превью использует фактический рисунок и мгновенно отражает черновик.

## Источники состояния и свет

- У каждой створки свой контакт открытия, инверсия, ручное «Открыто / Закрыто» и «Петли»: слева / справа / открывается вверх.
- Без назначенного датчика положение выбирается вручную. С датчиком ручное поле неактивно и показывает текущее разрешённое состояние. Недоступный назначенный датчик не включает скрытый ручной fallback.
- Опция «Есть шторы, жалюзи или ставни» — единая сущность на створку. При включении появляются привязка устройства, инверсия и положение штор; приоритет устройства над ручным положением ровно такой же.
- Оконное стекло пропускает свет и закрытым, и открытым. Только закрытые шторы/жалюзи/ставни перекрывают свою долю светового прохода. Сами шторы/ставни физически не рисуются.
- Для каждой створки с этой опцией — отдельная индикация: mdi:weather-sunny / mdi:weather-sunny-off. Неизвестное состояние не выдаётся за подтверждённо закрытое. Значки всегда со стороны, противоположной открыванию створок.
- На всех полях створки стандартные подсказки UI Kit. Возле отключённого положения объяснение: какой источник задаёт состояние, каково оно сейчас и почему поле неактивно; «Не назначено» возвращает ручной выбор. Никаких команд реальным устройствам.
- Отдельного типа «глухая секция» нет: достаточно ручного закрытого положения.

## Двери и ворота

- Сохраняется ранее согласованный выбор распашного/откатного механизма: одно полотно двери; два синхронных распашных либо одно откатное полотно ворот, общий контакт/замок.
- Добавлено ручное положение «Открыто / Закрыто» без датчика. Значение по умолчанию — открыто, как прежде. С выбранным датчиком поле отключено, положение берётся из него.
- Сохранение/повторное открытие сохраняет ручной выбор. Проходу лишнее поле не добавляется; команды HA и правила замков не меняются.

## Ручки, скругления, стекло и слои

- Дверная ручка — короткий поперечный штрих у свободного края, с обеих сторон, цвета полотна. У окон ручки только со стороны комнаты; если комнаты с обеих сторон — обе ручки. Определяется физическая сторона, независимо от открывания и отражения.
- Финальная геометрия ручки в единицах существующего visualScale: полная длина 7.7, толщина 2.1, скруглённые концы. Отступ от свободного края боковой створки: min(15% ширины, 6×scale)×1.5. У открывающейся вверх — по центру ширины. Размеры условного символа не записываются как физические параметры дома.
- Слегка скруглены углы всех символов дверей, окон и ворот, включая откатные. Радиус прямоугольных элементов 0.6×scale, соединения/концы штрихов round. Рамки выбора и зоны захвата не меняются.
- Тело каждого оконного проёма имеет голубую заливку #42bfff с непрозрачностью 20% и два лёгких диагональных белых блика (26% и 32%). Это декор стекла, а не новая световая маска.
- Открытые створки — того же цвета, что символ окна. Все створки/ручки рисуются поверх всех дуг/направляющих, в том числе соседних створок; соседняя боковая створка перекрывает диагональную направляющую верхней.
- Порядок слоёв: стекло/блики → голубые внутренние трапеции → дуги/направляющие → тонкие линии закрытого положения → створки/ручки → значки света.

## Открывается вверх — окончательный рисунок

- Условный вид сверху: свободное полотно параллельно проёму, выдвинуто на 20 см при полном открытии. В закрытом состоянии сохраняется полная ширина.
- При полном открытии сужение **по 3 см с каждой стороны**, всего 6 см. Не по 5 см. На очень короткой створке ограничивается так, чтобы ширина оставалась положительной.
- Только две наклонные боковые направляющие. Вертикальных направляющих нет. Внутренняя трапеция залита тем же голубым с непрозрачностью 20%.
- Угол наклонных направляющих на **10° ближе к 90°**, чем в исходном варианте «угловые треугольники» (два согласованных шага по 5°). Концы полностью спрятаны под свободным полотном и под линией закрытого положения, не выступают за края.
- Тонкая линия на месте закрытой створки остаётся: полная исходная ширина, толщина как у дуги, цвет самого символа. Она рисуется после направляющих и прикрывает их концы.
- Между створками **нет добавленных зазоров 5 см**: этот эксперимент отменён, равные доли примыкают друг к другу.
- Точные формулы и защитные ограничения сохранены в accepted source. Их перенос должен давать тот же рисунок, а не интерпретировать угол заново.

## Общий контракт цвета направляющих

- Положение задано датчиком → дуга/наклонные направляющие акцентного цвета темы Home Assistant.
- Положение задано вручную → они того же цвета, что сам символ двери/окна.
- Источник положения створки — её контакт, не контакт штор. Неизвестное состояние назначенного датчика не превращает его в ручной источник.
- Правило общее для плана, превью, размещения/перетаскивания, Flat/2.5D/static и поддерживаемых экспортов. Тонкая линия закрытого положения остаётся цветом символа. Тела ворот не перекрашиваются по этому правилу и не получают выдуманных дуг.

## Общие UI-исправления

- Раскрытые списки следуют за полем при прокрутке диалога, включая стандартный select и MDI; собственная прокрутка списка сохраняется. Если поле полностью вышло из видимой области, список закрывается; подписки очищаются.
- Плюс на пределе использует штатную help-подсказку. Поля, подсказки, кнопки, ховеры и состояния — существующий UI Kit.
- В автономном Lab восстановлено затемнение за диалогами: 45% чёрного только при отсутствии переменной темы HA. В продукте использовать общую поверхность диалога и уважать заданный темой scrim.
- Починка загрузки большой локальной сессии — служебная часть Lab, не требование продуктового поведения #1024.

## Приёмка переноса

Обязателен визуальный паритет с UI-059 на одинаковых синтетических данных, теме HA, viewport, масштабе и ориентации: список/настройки каждой створки, состояния disabled/help, общий выбор стороны, превью, 1–4 створки, боковые и верхние открытые/закрытые положения, ручки, цвета/блики/слои/значки; двери и ворота с ручным и контактным положением.

Проверить две стороны комнат, повороты/отражения, смешанные соседние створки, неизвестные источники, световые доли, Save/Cancel/Escape/Undo/Redo/reload, старую конфигурацию, адаптивность и темы. Данные UI Lab не являются продуктовой моделью; нельзя переносить localStorage, global hooks, DOM-патчи или polling вместо штатных механизмов.
