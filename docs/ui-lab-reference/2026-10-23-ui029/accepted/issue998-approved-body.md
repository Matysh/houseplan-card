## Запрос владельца

Привести выпадающие списки к одному оформлению из UI Kit по согласованному образцу «Способ отображения». Исходная задача касается настроек устройства, MDI picker и переполнения «Источника состояния значка». По дополнению владельца от 23.10.2026 **проверить все диалоги House Plan** и исправить остальные выпадающие списки, оформление которых отличается от этого образца.

## Проблема

1. MDI picker выбора иконки внешне отличается от соседних выпадающих списков, в том числе после предыдущих исправлений.
2. Индикаторы раскрытия различаются: сплошной треугольник у «Способа отображения» и уголок/шеврон у других полей.
3. Раскрытый «Источник состояния значка» может выходить за ширину диалога и создавать горизонтальную прокрутку.
4. При полировке локального MDI picker выявлены дополнительные расхождения: двойная рамка при фокусе, другое оформление поиска, отсутствие зазора между полем и списком, избыточная подсказка поиска.

## Согласование внешнего вида

23.10.2026 владелец явно принял последнюю версию локального UI Lab: «Отлично, теперь всё ок. Фиксируй эту версию в журнале и в #998».

Локальная запись — **UI-029**, цикл после **v1.83.0-beta.1**. Принят именно внешний вид прототипа; перенос в продукт и проверка всех диалогов ещё предстоят.

## ТЗ

### Согласованный внешний вид

- Закрытые поля: единые высота **44 px**, радиус **8 px**, фон, отступы, типографика, cursor, hover/focus и disabled по UI Kit. Образец — «Способ отображения». Для MDI picker учитывать суммарный размер его вложенных элементов, а не добавлять ещё одну рамку снаружи.
- Индикатор раскрытия — **сплошной треугольник**, как в образце, с плавным поворотом при раскрытии/закрытии.
- Раскрытый список: единые рамка, радиус **10 px**, фон, тень, отступы и состояния пунктов. Между полем и списком MDI picker — **7 px**, как у эталонного списка; сохранять зазор и при раскрытии вверх. Размеры ограничивать доступным экраном, длинные названия/идентификаторы не должны создавать горизонтальную прокрутку.
- Поле поиска внутри MDI picker: обычное поле UI Kit высотой **44 px**, радиус **8 px**, одна рамка, корректные внутренние отступы между лупой, текстом и очисткой. Подсказка — **«Поиск»**, без «Добавить пользовательский элемент». Это изменение подписи, а не удаление существующих возможностей пикера.
- **Двойной рамки у MDI picker быть не должно**, в том числе после клика, при открытом списке, фокусе на поиске и возврате фокуса. Фокус должен оставаться различимым без второго конкурирующего контура.
- Для «Источника состояния значка» сохранить поиск, корректные переносы длинных названий/ID и вписывание списка в ширину диалога.
- Использовать общие компоненты/токены UI Kit и динамические цвета темы Home Assistant. Не размножать отдельные стили для каждого диалога.

### Отдельное обязательное указание исполнителю: MDI picker

**Перепроверить именно MDI picker вручную и визуально рядом с обычным выпадающим списком. Он неоднократно оставался отличающимся после общей унификации. Одной проверки CSS или обычного select недостаточно.**

Проверить настоящий компонент Home Assistant, а не запасное текстовое поле: закрытое поле; hover; фокус мышью и клавиатурой; открытый список; пустой поиск с подписью «Поиск»; введённый запрос; очистку; выбор иконки; повторное открытие; Escape и возврат фокуса. Отдельно проверить отсутствие двойной рамки, оформление поиска, зазор 7 px и треугольник. Повторить в светлой/тёмной теме и на узком экране.

Сравнить реализацию со **согласованной версией UI Lab** при одинаковых данных, теме, размере окна, масштабе и состоянии элементов. Визуальное совпадение — обязательная часть приёмки.

### Обход остальных диалогов

Проверить все диалоги, содержащие выпадающие списки: общие настройки, пространство, комнату, устройство (включая специальные типы), диалоги редакторов, печати и прочие фактически найденные места. Не ограничиваться заранее перечисленными четырьмя настройками.

Составить краткий перечень проверенных диалогов/полей и состояний. Все найденные отличия привести к тому же оформлению UI Kit — закрытое поле, раскрытый список, поиск при его наличии, индикатор, отступ, hover/focus/disabled, открытие/закрытие. Сохранять назначение специальных пикеров, поиск и существующее поведение выбора. Если общий компонент исправлен в одном месте, перепроверить другие места его использования.

### Критерии приёмки

1. Все найденные выпадающие списки диалогов соответствуют согласованному UI Kit; приложен перечень проверенных мест. При одинаковых условиях реализация визуально совпадает с принятой версией UI Lab.
2. MDI picker прошёл отдельную визуальную проверку перечисленных состояний: одна рамка, стандартное поле поиска с подписью «Поиск», зазор 7 px, единый треугольник и оформление списка. «Источник состояния значка» не вызывает горизонтальную прокрутку, в том числе с длинными значениями и на узком экране.
3. Сохранены поиск, выбор и сохранение значений, клавиатурная навигация и корректный Escape вложенного списка без закрытия всего диалога. Нет регрессий связанных исправлений #988/#991/#995; темы HA, мобильный экран и disabled отображаются корректно.

## Границы

Область расширена владельцем до выпадающих списков **всех диалогов**, где найдены отличия. Это унификация оформления и устранение переполнения, без изменения модели данных, бизнес-логики, состава опций или возможностей специальных пикеров. Остальные элементы и поверхности приложения не редизайнить в рамках этой задачи.
