## API and lifecycle evidence

`test_modern_registry_surface_never_uses_deprecated_mapping_or_entry_set`
supplies a strict collection of real entry wrappers with `async_get` lookup.
It refuses mapping access and ordinary `config_entries` access. The old product
fails on `devices.items`; the candidate supplies both exact Z2M and ZHA readings.
This is a white-box/API-contract double on HA 2026.8.3, **not execution of the
upstream HA 2026.10 deprecation shim**. Legacy mapping and old/composite entry
sets have independent pure inputs. Official API sources are linked in the issue.

Registry revocation is also tested while another real subscription promise is
held: native device disable/remove and entity removal retire the old row before
the promise settles; a late packet cannot republish it. The first draft failed
this extra case, so it gained synchronous affected-row retirement and a dirty
binding publication fence. A valid update received during an unrelated held
refresh is cached and appears after the fresh proof, rather than being lost;
that extra case also failed in an intermediate draft before the input was
retained. The original pre-fix product was not rerun for this
additional scenario; it is not misreported as the historical baseline failure.

Native config-entry title change observes a new cached ZHA reading without a
timer tick; native entry disable retires HA-disabled devices. Only the fake
radio's reload is mocked, not House Plan behavior. ZHA loss/reload, replacement
gateway, changed membership, explicit unknown and a zero on the new radio retain
an independent MQTT reading and its timestamp. Existing old/current gateway,
source ambiguity, retained subscribe, topic change, payload/ACL and teardown
checks remain part of the executed 43-test subset.

Risk coverage: async generation/held subscribe/unload; data/ACL/ambiguous source;
bounded volume and steady operation counts; host/API old/current shapes. Geometry
and raster changes are not applicable. Config/layout/Store/wire format, UI,
