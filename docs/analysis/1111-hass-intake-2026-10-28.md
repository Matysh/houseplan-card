# HA tick intake and activity demand (#1111)

The card retains the active registry projection across HA frames, comparing state
object references and applying the unchanged disabled/parent rules only to changed
rows. Registry signature/authority, connection, user, reconnect and a return from
hidden/departed intake trigger one full rebuild. Earlier frame dictionaries stay
immutable. Ecovacs source overlays remain separate from the cached raw projection.
Ripple requests the existing cached light resolver only when a visible ripple
consumer belongs to the current space; removal still retires its history/timers.

## Evidence and limits

The initial ordinary tests exercised the actual card getter and intake method on
unchanged code: five changed rows caused 1673 registry decisions and an empty
ripple roster still read the light projection. These were assertion failures,
not an import/setup failure. Candidate targeted tests: 27 passed, including the
incremental/full corpus, disabled and missing parents, YAML/sun, addition/deletion,
undefined state values, previous-frame immutability and owner/visibility changes.
The extra off-floor activity browser case preserves the existing color assertions.

`node demo/benchmark_hass_tick.mjs --runtime=<compiled-runtime> --output=<report>`
compares the unchanged compiled 61cc75bb source and the candidate in separate Node
processes using one shared host fixture and the production intake/getter/activity
methods. The unchanged roster/transport/vacuum ports are inert in this isolated
CPU benchmark. It measures no browser paint, pointer latency or network time;
those consumers have their named existing smokes. The source hashes and all
samples are in [before](1111-hass-tick-before.json) and [after](1111-hass-tick-after.json).
The #1093 input fixture contains 214 registry devices, 2890 entities, 1673 states
and 200 represented markers. Each group has 20 samples.

Registry-change lookups include both the 2890-row registry and 1673 states.
The resolver already cached its completed light calculation before this change;
requests/fingerprint work and actual cache misses are reported separately. No
claim is made that every original request recomputed the graph. A new state map
still requires a cheap key/reference scan and copy-on-change; this is not a claim
of O(k) total map traversal. The normative AC are processed-state and rebuild
counters; these timing observations introduce no threshold, and registry p95 is
reported even where it increased. No existing timing limit changed.

No protocol, persisted configuration, rights, device classification or new GUI
control changes. E2E verdict: not needed; the accepted task retains existing HA
journeys and names the consumer smokes. Revert the task commits to roll back.
