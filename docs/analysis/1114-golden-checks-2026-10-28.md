# Explicit unchanged Golden checks (#1114)

The old API could select unknown render scopes only by declaring a pending
`change`/`new` delta. That route permits an intended difference; it cannot prove
the strict unchanged frames required by #1097/#1098. Their actual plan refusals
were retained (including #1098 CI40685040818 classification RED).

The optional `visual.goldenChecks` contains unique existing scene IDs and concrete
reasons, without an expectation field. It is disjoint from `visual.golden` and
any selected pending delta. Only the bounded task plan adapts it to the internal
`unchanged` result contract. The worker requires passed status, equal canonical
PNG SHA256 and complete zero differingPixels/diffRatio, keeping the prior
metadata/error/child-result checks. Existing tolerant and explicit change/new
paths are unchanged. Checks do not enter pending acceptance expectations.

Stale check epochs and new checks combined with task full requests fail explicitly.
The normalized selected-task intent is already part of the receipt key: previous
tolerant/change/new coverage with identical IDs cannot satisfy the new contract.
A new strict record round-trips through the ordinary verifier. The legacy task
wire (push+coverageScope=task) carries it; full/unscoped push cannot. The infrastructure
patch's own CI plan uses no new expectation until protected dev readers are updated.
No job, event, default/full capture or global baseline is changed.
