# Вход для исполнителя

Единый порядок работы — [корневой PROCESS.md](../../PROCESS.md).
Этот файл помогает найти нужный раздел, не добавляя условий приёмки.

Команды процесса находятся в `process-next/`; старые инструкции в `legacy/`
не задают дополнительных этапов. Состояние подключения:
[отчёт переключения](../../process-next/evidence/cutover-status.md).

Начни с issue: ожидаемый результат, установленный трек и текущий статус.
Прочитай [SCOPE](../SCOPE.md) и относящиеся к задаче продуктовые контракты.
Метки, треки и четыре условия первоначального выбора ship описаны в PROCESS;
установленный трек агент не меняет.

Для ask полное ТЗ остаётся в теле issue под `## ТЗ`.
[Шаблон ТЗ](SPEC-TEMPLATE.md) соответствует существующей авторской проверке
формы. Автор заполняет и проверяет его до S4; модель затем оценивает смысл,
полноту, реализуемость и альтернативы. Для ship/show этот шаблон автоматически
не добавляется.

Реализация идёт в отдельной ветке/worktree. Перед завершением задачи используется
очередь из раздела «Очередь и завершение» PROCESS: актуализация, выбранные
проверки S6, ревью по треку и merge. Исполнитель коммитит правки, публикует
рабочую ветку в origin и запускает `finish` с
`process-next/config.json` и запросом своей задачи; команда без `--execute`
показывает только план. Пример команды и подготовка токена — в DEVELOPMENT.

Состав проверок выбирается по затронутому слою и области задачи из единого
каталога. [TESTING](../TESTING.md) объясняет назначение наборов.
Чистая документация не запускает тесты, сборку, lint, проверку ссылок или hooks.
Для документации show/ask остаётся содержательное ревью текста.

Перед передачей используй короткий
[контекст исполнителя](../../process-next/templates/review-context.md):
что изменилось, почему выбран подход, где риски, что фактически проверено.
Не переписывай независимые правила ревьюера и не выдавай ожидания за результат.

Замечания исправляются на S6 с нужной адресной проверкой. Уже применимые
успешные результаты сохраняются. Возврат на исправление не разрешает расширять
исходную задачу или автоматически менять её трек.

Техническая подготовка среды — [DEVELOPMENT](../DEVELOPMENT.md).
Кандидаты выпуска, перенос исправлений и закрытие задач — разделы PROCESS
о выпуске; старые release-скрипты не являются дополнительным маршрутом.
